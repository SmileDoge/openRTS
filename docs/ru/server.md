# Сервер openRTS

`openrts-server` — собственный игровой сервер openRTS (шаг 6 плана, этап 3).
Это его первый режим, **Legacy включён**: сервер говорит на протоколе RTS,
поэтому оригинальный `rts1.exe` и клиенты openRTS заходят на него так же,
как на `rts_server.exe`. Как ведёт себя сервер RTS:
`reverse/multiplayer.md`, `reverse/multiplayer-protocol.md`. Клиентская
сторона того же протокола — `net.md`.

Пока нет:
- протокола openRTS (Legacy выключен) и общих для всех настроек;
- поездов, которые сервер ведёт сам (TRAFFIC, шаг 7);
- пультов `rts_server_DSP.exe`: они получили бы ответ на вход как игрок, а
  не ожидаемые `0x4501`.. (ещё не разобраны).

## Запуск

Обновить openRTS на компьютере сервера без игры: `openrts-updater.exe`
рядом с ним (окно, видеокарта не нужна) или `openrts-updater.exe --yes`
из скрипта; затем запустить сервер заново и поставить расстановку
`autosave-previous` (INSTALL.md, «Без игры»).

```
openrts-server --route Kuban_RTS --root D:\Games\MDDRTS --port 800 --season summer --weather clear --time 10:00
```

| Флаг | |
|---|---|
| `--route <папка>` | маршрут, папка в `ROUTES` (регистр не важен) |
| `--root <папка>` | установка RTS (по умолчанию текущая папка) |
| `--port <n>` | по умолчанию 800, как у `rts_server.exe` |
| `--season`, `--weather` | `spring`..`winter` или 0..3; `clear`, `snow`, `rain` или 0..2, `storm` или 3: гроза openRTS (игрокам RTS — дождь, docs/weather.md) |
| `--time HH:MM` | время суток на старте (12:00) |
| `--no-admit` | не пускать новых игроков |
| `--max-players <n>` | места: новый игрок сверх стольких подключённых получает отказ (`0x4702`, как при `--no-admit`); вернувшийся под своим ником и пульты диспетчера не в счёт; 0 (по умолчанию) — без ограничения |
| `--autosave <минуты>` | все поезда на путях сохраняются расстановкой `autosave` так часто и при остановке (по умолчанию 2, 0 — никогда); при запуске прошлая сохраняется как `autosave-previous` (Расстановки) |
| `--discord-join`, `--public-address <хост:порт>` | в профилях Discord игроков openRTS появляется «Присоединиться» с этим адресом (не задан — тот, по которому зашёл каждый игрок); net.md, «Вход через Discord» |
| `--dispatcher-password <текст>` | с ним входит пульт диспетчера с другого компьютера (без него — только с этого; «Пульт диспетчера (в игре)» ниже) |
| `--data <папка>` | где сервер хранит свои файлы (сохранённую базу маршрута); по умолчанию папка пользовательских данных openRTS (`%LOCALAPPDATA%\openRTS`, или рядом с программой при `portable.txt`), никогда не установка RTS |
| `--command "<строка>"` | строка консоли, выполняемая при старте (можно несколько) |
| `--run <с>` | остановиться через столько секунд (для тестов); запуск в консоли |
| `--no-window` | запуск в консоли, без окна (нужен `--route`) |
| `--capture <файл.ppm>`, `--capture-at <с>` | снимок окна через `с` секунд после старта сервера (по умолчанию 3), затем окно закрывается (проверка) |

Маршрут загружается примерно за секунду (Kuban: 1653 узла путей, 1951
головка сигналов, 0,9 с), после чего сервер ждёт подключений. Игроки
заходят через «Сетевую игру» стартового меню или
`openrts_viewer --mp-connect хост[:порт]`, либо через `rts1.exe`.
Аргументы и строки консоли в Windows читаются как UTF-16, так что русские
имена путей и сообщения работают.

Его запускает и стартовое меню («Сетевая игра», «Свой сервер»: «Открыть
окно запуска сервера») с папкой RTS, со своим окном (порт задаётся там) и
своим журналом (`openrts-server.log` рядом с настройками); «Подключиться к
своему серверу» затем входит на 127.0.0.1 на порт, с которым окно сервера
запускалось последним (`server_window.ini`), с ником и ролью из меню.

## Окно

Без `--no-window` (или `--run`) сервер открывает своё окно, как
`rts_server.exe`. Игра идёт в своём потоке, каждые 20 мс, как и без окна;
окно читает и меняет её под блокировкой, а рисует вне её (2026-11-21: до
того игра делала шаг раз за кадр, и на компьютере без видеокарты, где
окно рисуется программно, мир игрокам приходил с перерывами в секунды).
На таком компьютере `--no-window` ещё легче.

- **Окно запуска:** папка RTS (с кнопкой «Обновить», чтобы заново
  перечислить её маршруты), маршрут, сезон, погода, время, порт (0 —
  любой свободный), пускать ли новых игроков, места («Мест в игре»,
  сначала 16, 0 — без ограничения), пароль диспетчера (с ним
  пульт диспетчера может войти с другого компьютера), «Вход через
  Discord» с адресом для игроков (net.md, «Вход через Discord»), папка
  сервера.
  Аргументы заполняют его. Без `--route` оно такое, каким было при
  последнем запуске (`server_window.ini` в папке сервера, пароль тоже), но
  папка, порт и пароль из командной строки остаются.
- **Затем пульт на карте маршрута** (та же карта, что у Track control во
  вьюере, `trackmap/`): пути, стрелки, сигналы с литерами, платформы,
  тупики, станции, поезда цветом их вида (игрока, трафик, стоящий) с
  номерами, владельцами, скоростью и стрелкой перед головой — куда
  повёрнут поезд, маршрут каждого поезда и отрезки
  станционных маршрутов (ждёт — серый, задан — зелёный, поезд на нём —
  тёмно-зелёный). Колесо — масштаб, протяжка правой кнопкой двигает
  карту, первый поставленный поезд переводит карту к себе. Правый щелчок
  открывает, что можно сделать в этом месте:
  - поезд: отдать игроку или забрать, отменить маршрут, удалить;
  - стрелка: направление, запереть от игроков или отпереть;
  - сигнал (сверху — отчёт его единицы): задать показание, открыть,
    автоблокировка, закрыть, вернуть как по умолчанию;
  - путь: «Поставить поезд» (сначала состав, выбранный во вкладке
    «Поезда», затем любой по части названия), маршрут выбранному поезду
    досюда (от головы или от хвоста, если место позади).
- **Постановка поезда** сначала видна: состав стоит на карте контуром,
  первый вагон оранжевый с крупной стрелкой туда, куда он повёрнут,
  красный, где не помещается или наезжает на поезд; полоса над картой
  пишет, что именно и какой он длины. Его можно тащить вдоль пути,
  щелчок по другому пути переносит его туда, ← / → сдвигают на 1 м (с
  Shift — на 10 м); «Поставить (Enter)» ставит (на другой поезд сервер
  всё равно не поставит), «Развернуть (Пробел)» разворачивает, «Отмена
  (Esc)» отменяет.
- **Вкладки:**
  - «Поезда»: поезда (номер, id, вид, машинист, вагоны, скорость; щелчок
    выбирает поезд и показывает его), действия с выбранным (исчезнувший
    поезд перестаёт быть выбранным), новый поезд: состав (поиск по части
    названия, русскими или латинскими буквами; щелчок по выбранному или
    «Снять выбор» снимает выбор) показывается в начале маршрута и
    ставится оттуда.
  - «Станционные маршруты», как «Собрать маршрут» у `rts_server.exe`:
    поезд (выбирается здесь, во вкладке «Поезда» или на карте), его
    очередь с состоянием и отменой каждого отрезка и маршруты, которые он
    может взять дальше — от конца последнего отрезка, иначе от головы
    (синяя метка со стрелкой на карте); «Направление» меняет сторону (там
    он сменит направление или поедет хвостом вперёд). Главные пути первыми
    зелёным, на неправильный путь последними лиловым, «[П]» и длина
    станционного пути, на который он ведёт, сколько до его начала.
    Выбранный рисуется на карте (толсто, со стрелкой на конце и именем;
    путь до него тонко), и карта показывает его целиком; маршрут под мышью
    — оранжевым. «Задать» (или двойной щелчок) ставит его в очередь с
    «держать следующий» и приоритетом, и список идёт дальше от его конца:
    до следующей станции и дальше. «Все маршруты станции» — любые маршруты
    станции; внизу — очередь всех поездов.
  - «Сигналы»: все сигналы типа — ручной / открыт / автоблокировка, тип
    «как поездной», вернуть умолчания, задать как умолчания, сохранить
    базу маршрута (в папку сервера).
  - «Игроки»: ник, состояние, поезда, адрес; сообщение игроку или всем,
    отключить игрока.
  - «Журнал»: журнал сервера и строка для команд консоли (`help`), те же,
    что в консоли.
- **Полоса сверху:** маршрут и порт, время сервера и его установка, пауза,
  пускать ли новых игроков, сколько играет (из скольких мест), откуда может войти диспетчер
  («только с этого компьютера» или «откуда угодно, по паролю»), остановка
  сервера. Под ней —
  что сделано последним, 5 с (ошибка — 10 с).

Журнал идёт и в консоль за окном. В окне пока нет: пуска и остановки
поезда самого по себе (сервер не ведёт поезда до шага 7, TRAFFIC).

## Консоль диспетчера

| Команда | |
|---|---|
| `status` | маршрут, время, пауза, игроки, поезда |
| `users` | игроки: id, на связи или нет, в игре или в меню, поезда, последнее место |
| `trains` | поезда: id, номер, вид, владелец, вагоны, где стоит, скорость |
| `paths [текст]`, `consists [текст]` | из чего можно собрать поезд |
| `add "<состав>" <путь> [номер]` | поезд, стоящий в начале пути (STATIC); отказ, если там стоит другой («occupied by train N») |
| `place "<состав>" <узел> <смещение> <forward\|back> [номер]` | поезд (STATIC), голова первого вагона которого стоит в точке пути, по узлу или против него |
| `assign <поезд> <ник>` | поезд ведёт игрок (`0x4601`; остальные получают `0x4605` PLAYER) |
| `unassign <поезд>` | поезд забран: стоит как STATIC |
| `remove <поезд>` | удалён (`0x4602` 1); владельцу сначала сообщают |
| `weather [clear\|snow\|rain\|storm\|dynamic [зерно]]` | погода во время игры, игрокам openRTS и пультам (`0x45FA`, docs/weather.md); также верхняя полоса окна («Динамическая погода», «Другая» — другое зерно) |
| `number <поезд> <номер>` | номер поезда (`0x4605` всем, как его шлёт `rts_server.exe`, когда пульт его меняет: по нему RTS нумерует вагоны); не номер другого поезда |
| `move <поезд> <узел> <смещение> <0\|1>`, `chocks <поезд> none\|head\|tail\|both` | стоящий поезд ставится заново: в другом месте или с башмаками по концам (Расстановки) |
| `name <поезд> [текст]`, `notes <поезд> [текст]` | название (карта пульта показывает его после номера) и заметки, здесь одной строкой (форма поезда в пульте — несколькими); `0x461A` всем и в снимке мира; без текста — стирается |
| `say <ник\|*> <текст>` | сообщение (`0x4611`) |
| `pause`, `resume` | `0x4616`; на паузе ничего не отправляется, как в RTS |
| `time [ЧЧ:ММ[:СС]]` | показать или задать (`0x460D` всем) |
| `route <поезд> <сигнал> [сигнал...]` | маршрут поезда, как сборка на пульте: от головы поезда (или от хвоста, если он едет хвостом вперёд) до сигнала с таким именем в базе маршрута («литера»), через остальные по очереди, кратчайшим путём; из нескольких сигналов с одним именем берётся ближайший по пути. Все стрелки на нём переводятся, и противошёрстные, и пошёрстные, и удерживаются: игроки не могут их перевести, пока хвост поезда их не проедет (плюс 30 м). Его ручные сигналы по ходу поезда открываются («Сигналы» ниже). Можно указать и номер элемента TDB |
| `route <поезд> cancel` | стрелки маршрута освобождены (остаются как есть), открытые им сигналы закрыты |
| `heads` | каждая головка сигнала, как её получают игроки: элемент TDB, показание, draw state, режим (для сравнения с `openrts-net-dump --heads`) |
| `signals [текст]` | имена сигналов и сколько сигналов под каждым |
| `stations [текст]` | станции маршрутов станций из базы маршрута и сколько маршрутов у каждой |
| `routes <станция> [текст]` | маршруты станции: ID, имя, откуда, куда, флаги, проложен ли путь |
| `next <поезд> [back]` | маршруты станций, которые поезд может взять дальше, как «Собрать маршрут»: от конца последнего отрезка, иначе от головы (back — в другую сторону); ID, станция, имя, «[П]» и длина пути, главный путь, на неправильный путь, сколько до него; с подсказкой `back` или `rear`, когда они нужны |
| `segment <поезд> <ID маршрута> [back] [hold] [rear] [priority N]` | отрезок маршрута поезда — маршрут станции по ID (back — от его конца; hold — следующий отрезок поезда ждёт; rear — поезд идёт по нему хвостом вперёд): проверяется и встаёт в очередь, выставляется в свой черёд («Маршруты станций» ниже) |
| `segment cancel <id>` | отменён: маршрут поезда возвращается к концу предыдущего отрезка |
| `segments` | очередь: id, поезд, маршрут станции, состояние, переведено стрелок |
| `junction <узел> [ветка] [lock\|unlock]` | перевести (отказ, пока занята или удерживается маршрутом) или запереть от игроков |
| `signal <элемент\|имя>` | единица сигнала: режим, показание, задал ли его диспетчер, умолчания, типы головок; по имени — если оно только у одного сигнала |
| `signal <элемент\|имя> <показание>` | держать на этом показании (ручной, задан диспетчером: маршрут его не трогает), как «Установить показание» пульта |
| `signal <элемент\|имя> open\|auto\|close\|default` | открыть (скрипт работает, пока поезд его не проследует), автоблокировка, закрыть (ручной на STOP_AND_PROCEED, как снятие «Открыт» / «Автоблокировка» на пульте), вернуть умолчания |
| `signal type <тип> <manual\|open\|auto>` | все сигналы с головкой этого типа sigcfg, как переключение по типу на пульте |
| `signal defaults` | все сигналы обратно к умолчаниям из базы маршрута |
| `signal set-defaults` | умолчаниями каждого сигнала становятся его нынешние режим и показание («Задать как умолчания» пульта) |
| `signal type <тип> normal on\|off` | тип отображается как поездной (его головки идут в показание своего сигнала; «Отображать как поездной» пульта) |
| `signal save` | умолчания и типы «как поездной» — в копию базы маршрута у сервера (`<data>/server/<маршрут>/<файл>.rtsdb`, прежняя остаётся как `.bak`): «Сохранить всё» пульта для сигналов; дальше сервер читает сначала эту копию |
| `couple <поезд> <поезд>` | второй присоединяется к первому там, где они стоят торец к торцу (ближайшие концы в пределах 50 м), как `rts_server.exe` сцепляет поезд LOOSE, въехавший в другой: `0x460F` всем, владельцу первого тоже |
| `cut <поезд> <вагон>` | расцепить перед вагоном `вагон` (с 0): вагоны с него — отдельный поезд, вид и владелец как у поезда; `0x460E` всем, владельцу тоже |
| `helper <ник> <поезд\|off>` | игрок — помощник машиниста в кабине поезда, или больше нет (игроки openRTS: «Помощники» ниже) |
| `kick <ник>`, `admit on\|off`, `quit` | |

## Пульт диспетчера (в игре)

Удалённый диспетчер (с 2026-11-21; с 2026-11-09 был спрятан, пока не готов
сервер, решение пользователя): «Сетевая игра» в стартовом меню, «Войти
как: Диспетчер (пульт)», с паролем диспетчера сервера.

Пульт — это сам openRTS (выбор пользователя, 2026-11-09):
`openrts_viewer --mp-connect хост --mp-nick <ник> --mp-console
[--mp-password <текст>]` (стартовое меню передаёт пароль в
`OPENRTS_MP_PASSWORD`, не в командной строке и не в журнале).
- **Кого пускают** (`ServerOptions::consoles`, включено;
  `dispatcher_password`): с компьютера сервера (127.0.0.1) — любой ник без
  пароля; с другого — только с паролем диспетчера, заданным на сервере (в
  окне запуска или `--dispatcher-password`): неверный или пустой получает
  `0x4707` (собственный код openRTS), сервер без пароля — `0x4702`. До
  2026-11-21 ник из `--dispatcher` пускал пульт откуда угодно без пароля;
  теперь такие ники только сужают круг (если заданы, ник тоже должен быть
  среди них). Пароль идёт открытым текстом, как и весь протокол.
- Он входит с `0x4500` (собственное openRTS: пароль — длина `u16` и
  единицы UTF-16 с нулём — после нуля ника; такой вход может быть до 256
  байт, у игрока — 64) и сразу получает мир, поезд не нужен.
- Его карта — трек-контроль, открытый на старте. Стрелка, переведённая на
  нём, и показание сигнала («Показание …» в меню сигнала или «по скрипту»)
  уходят на сервер командой. «Поставить состав сюда» (его можно двигать и
  разворачивать, как в одиночной игре) ничего не ставит на путь самого
  пульта: состав уходит на сервер, и тот ставит его ничьим (STATIC), чтобы
  отдать игроку. В меню поезда — «Перейти к поезду», «Отменить маршрут» и
  «Удалить поезд» (на сервере); машинист — в окне пульта. Поезд, выбранный
  на карте, выбирается и в окне.
- **Маршрут поезду с карты, как его задаёт пульт RTS (Legacy):** выберите
  поезд, правый клик по пути, «Маршрут выбранному поезду досюда». Пульт
  находит путь от головы поезда (или от хвоста, если место позади) по своей
  копии сети, отправляет каждую стрелку, которую надо перевести, как
  `0x460A`, затем длину маршрута как `0x4619` (поезд, метры, флаг 1, если от
  хвоста) — как пульт RTS (живая запись 2026-11-05). Сервер откладывает эту
  длину от головы по стрелкам, как они стоят, держит их и рассылает
  оставшееся расстояние (`0x4619`) всем, игрокам тоже, раз в 0,5 с, пока
  оно меняется; `-1` — когда поезд его прошёл или пульт его отменил
  (`0x4619` -1). Карта рисует маршрут зелёным от головы поезда. Второй
  способ RTS — станционные маршруты из базы маршрута — раздел окна
  «Станционные маршруты» ниже.
- **Ручной маршрут как в RTS** (2026-11-21): у выбранного поезда видна его
  линия от головы (и бледнее — от хвоста) по стрелкам, как они стоят;
  диспетчер переводит их, пока линия не пойдёт куда нужно, и щёлкает по
  ней правой кнопкой: «Конец маршрута здесь» отправляет только длину
  (`0x4619`), как пульт RTS. «Маршрут для выбранного поезда сюда»
  (кратчайший, с точками проезда) остаётся.
- **Стрелки как в RTS** (2026-11-21): стрелка стоит, куда её поставили.
  Поезд игрока, взрезав стрелку (пошёрстно, с другой ветки) или оставив её
  позади (обратно в `MainRoute` или под резерв следующего поезда), ставит
  её у своего владельца, тот шлёт `0x460A`; сервер принимает как есть
  (кроме заблокированной диспетчером, как `rts_server.exe` `0x40C52C`) и
  сообщает остальным. Стрелки своих поездов (без игрока) сервер ставит сам.
  Ручная стрелка пешком — запрос (`0x4642`), отказ при блокировке,
  резерве или занятости.
- Окно «Пульт ДСП»:
  - время, пауза, установка времени;
  - поезда (номер, вид, машинист, скорость, маршрут): выбор поезда
    центрирует на нём карту; отдать игроку, забрать, удалить, задать или
    отменить маршрут до сигнала (литеры);
  - «Станционные маршруты», как в окне сервера: выбранный поезд, его
    очередь с состоянием каждого отрезка и отменой, маршруты, которые он
    может взять дальше (запрашиваются у сервера раз в 3 с и при изменении
    очереди: от конца последнего отрезка, иначе от головы; «Направление»
    поворачивает поиск), главные пути первыми зелёным, на неправильный
    путь — последними сиреневым, «[П]» и длина пути, расстояние; «держать
    следующий», приоритет, «Задать» или двойной щелчок ставит его в очередь
    (строка `segment`); очередь всех поездов. Выбранный маршрут на карте
    пока не рисуется;
  - «Сигналы»: все сигналы типа (типы маршрута читаются здесь) — ручные /
    открытые / автоблокировка, отображать как поездной или нет, вернуть
    умолчания, задать как умолчания, сохранить базу маршрута (на сервере,
    в его папку): строки `signal`;
  - выбранный поезд: номер («Задать номер»), название и заметки (несколько
    строк; «Сохранить название и заметки»), как форма поезда в пульте RTS:
    `0x461A` серверу, он рассылает их всем; карта показывает на поезде
    «№ название», а у выбранного — заметки. Пока форму правят, набранное
    остаётся; правка другого диспетчера приходит туда, где не правят
    (2026-11-21, тестеры);
  - новый поезд: состав (с фильтром) и путь, поставить на путь — с
    номером (пусто — первый свободный), названием, видом (STATIC, PLAYER,
    LOOSE, TRAFFIC) и состоянием (Холодный, Включен, На ходу), по
    умолчанию STATIC и Холодный (2026-11-21, организатор); так же в
    «Поставить состав здесь» на карте, в «Новом поезде» окна сервера и на
    его карте. `0x45F3` несёт название, вид и состояние после вагонов (у
    пульта старой версии их нет: STATIC, холодный). Поезд TRAFFIC стоит:
    сервер пока никого не водит;
  - меню поезда на карте (пульта и окна сервера): «Номер и название»,
    правится прямо там;
  - Трек-контроль у пульта: камера не следит за поставленными поездами
    (без своего поезда она шла за первым, и каждый поставленный поезд
    уводил к себе диспетчера), без вида из вагона (F3); «К себе» —
    карта на камеру, Ctrl+T — телепорт к курсору (пункт меню «Телепорт
    сюда» остаётся);
  - игроки (диспетчер, не на связи, в меню, в игре; их поезда): сообщения
    одному или всем, отключить игрока, пускать новых или нет;
  - журнал: отправленные команды и ответы сервера; ввод любой команды
    сервера.
- Пакеты — собственные openRTS (их нет ни в одной программе RTS):
  - `0x45F0` пульт → сервер: строка команды, как на сервере (все, кроме
    `quit`);
  - `0x45F1` ответ — то, что напечатал сервер;
  - `0x45F3` пульт → сервер: состав, который надо поставить на путь, — его
    вагонами (у каждого папка и файл, локомотив или вагон, развёрнут,
    холодный, ручной тормоз), с его MaxVelocity, номером (не обязательно) и
    местом: начало пути или голова первого вагона на узле, смещении и
    направлении. Состав — собственный файл диспетчера; серверу нужны только
    файлы вагонов, из них он и собирает свой поезд. .con откуда угодно с
    компьютера диспетчера тоже («Обзор...» на карте): читается там, по его
    пути (2026-11-21: до того для таких — «consist not found», искались
    только папки игры, среди них грузовые составы тестеров). Пульт RTS делает то же
    своими пакетами (живая запись 2026-11-05): `0x4607` с записями вагонов,
    id сервера в ответ `0x4507`, затем `0x4603` / `0x4606`, чтобы поставить
    его; эту последовательность сервер тоже будет принимать, когда к нему
    пустят `rts_server_DSP.exe`;
  - `0x45F2` сервер → пульты, раз в секунду: время, пауза, пускаются ли
    новые игроки, пользователи (id, ник, на связи, в игре, пульт, место
    камеры, их поезда) и поезда (id, номер, вид, подвид, состояние,
    владелец, стрелки маршрута, скорость, стоит ли, вагоны, первый вагон);
    с 2026-11-21 затем отрезки станционных маршрутов (id, поезд, ID
    маршрута, станция и название, от конца / держит следующий / хвостом
    вперёд, приоритет, состояние, сколько стрелок из скольких переведено) —
    читатель без них останавливается перед ними;
  - `0x45F8` пульт → сервер: что поезд может взять дальше (`u32` поезд,
    `u8` 1 — в другую сторону); `0x45F9` ответ (`net::ConsoleNext`): поезд,
    направление, стоит ли он на пути сервера, хвостом вперёд, отрезок,
    после которого (id, название), затем маршруты (ID, от конца, главный
    путь, на неправильный путь, платформа, длина пути, расстояние, станция,
    название) в порядке `GameServer::next_routes`.
- Ручная стрелка, которую игрок переводит пешком (`track.md`), уходит на
  сервер как `0x4642`, как у `rts1.exe`; ответ сервера — то, что стоит.
  Других способов перевести стрелку в сетевой игре у игрока нет, как в
  RTS.
- Стрелку, которую переводит поезд игрока (взрез, возврат в MainRoute за
  хвостом, `0x460A`), ни клиент, ни сервер не переводят под чужим
  поездом и перед ним на столько, сколько он проходит за 4 с (5 м для
  стоящего, не больше 150 м): сервер возвращает отправителю её
  положение. Позиция называет хвост поезда, остальное каждый компьютер
  откладывает по своим стрелкам: стрелка, возвращённая под чужим
  поездом, уводила его на другой путь везде, кроме компьютера хозяина.
- Все стрелки рассылаются заново, по 40 каждые 0,25 с по кругу (3000 —
  меньше чем за 20 с): пропустивший перевод клиент получает его через
  несколько секунд. Клиент заново раскладывает чужой поезд от головы,
  если его хвост лежит не там, куда ведут стрелки (кроме сошедшего).

## Расстановки

Все поезда на путях сервера сохраняются под именем и ставятся обратно
(2026-11-21, организатор): вагоны (файл, развёрнут, холодный, ручной
тормоз, башмаки), голова первого вагона (узел TDB, смещение, куда
смотрит), номер, название, заметки, тип (STATIC, PLAYER, TRAFFIC, LOOSE;
поезд PLAYER возвращается ничьим) и состояние. Файл тот же, что пишут
одиночная игра и пульт диспетчера (docs/ru/placements.md, «Файл»), в
`<data>/server/<маршрут>/placements/<имя>.placement` на сервере и в
`placements/<маршрут>/` в папке данных openRTS диспетчера (среди них и
расстановки одиночной игры этого маршрута: присланную игроком кладут туда
или на сервер как есть). Расстановка включает другие (строки `include`):
они ставятся вместе с ней.

- Сервер: `placement save <имя>`, `placement load <имя> [add]` (поезда на
  путях сначала убираются, если не `add`; составы включённых расстановок
  вместе с ними), `placement list`, `placement get [имя]` (её включения и
  все составы, включённые помечены `from`; без имени — поезда сейчас),
  `placement include|exclude <имя> <другая>`, `placement delete <имя>`,
  `placement clear` (убрать все поезда), `placement upload <имя> <часть>
  <частей> <текст>` (файл пульта по частям: пакет команды пульта вмещает
  0x3C00 байт; записывается целиком, когда придёт последняя). Вкладка окна
  «Поезда», «Расстановки»: сохранить все поезда, поставить (с удалением
  текущих), добавить, удалить; «Открыть: вложения, поезда» показывает её
  включения (убрать, добавить другую) и составы вместе с включёнными
  (номер, название, тип и состояние, вагоны и башмаки, из какой
  расстановки), отмеченные ставятся или сохраняются другой расстановкой
  (расстановка одного поезда из станционной).
- Пульт диспетчера, «Расстановки»: сохранить все поезда на сервере или у
  себя; список расстановок сервера — показать или сохранить у себя (как
  свою: составы включённых в ней, без включений); свои — показать (с
  составами включений), сохранить на сервере (выгружается, поезда на его
  путях остаются как есть) или удалить; у показанной — её включения
  (убрать, добавить другую: на сервере через `placement include|exclude`)
  и составы (номер, название, тип и состояние, вагоны и башмаки, из какой
  расстановки; заметки по наведению), отмеченные ставятся на путь
  (`console_place` каждый: номер, название, заметки, тип, состояние,
  башмаки, место), при галочке сначала убираются все поезда, или
  сохраняются другой расстановкой у себя или на сервере.

**Перестановка стоящего поезда** (2026-11-21): `move <поезд> <узел>
<смещение> <0|1>` (голова там, при 1 лицом вдоль узла) и `chocks <поезд>
none|head|tail|both`; меню поезда в окне сервера и Управление путями у
диспетчера («Переставить (на карте)»: предпросмотр его вагонов тянут и
разворачивают, затем ставят; «Башмаки»). Сервер убирает его и ставит
заново с тем же номером, названием, заметками, типом, состоянием и
вагонами (новый id: клиенты RTS видят, как поезд ушёл и пришёл); если не
помещается — отказ (поезд ставится обратно на прежнее место), поезд
игрока не переставляется. Башмаки держат его и на сервере (10 кН каждый,
как PlaceDrag RTS).

**Поезда машинистов сохраняются** (2026-11-21): расстановка помнит, чей
поезд (`owner <ник>`), и его собственное состояние (`state`: то, что
openRTS владельца шлёт раз в 30 с пакетом `0x45FB` `openrts_train_state` —
воздух, аппараты и флаги вагонов и сохранённые состояния DLL, сжатые, по
частям). Поставленный обратно поезд с владельцем ждёт его: зайдя под
этим ником, машинист сразу получает поезд (без диспетчера), а его openRTS
возвращает в поезд состояние (DLL — как только они запустятся). Так же и
при перезаходе, пока сервер работает.

**Автосохранение**: все поезда на путях сохраняются расстановкой
`autosave` каждые 2 минуты (`--autosave <минуты>`, 0 — никогда) и при
остановке сервера; если поездов нет, остаётся прежняя. При запуске
прошлая сохраняется как `autosave-previous`: после падения или перезапуска
«Поставить» её (или `--command "placement load autosave-previous"`), и
поезда встанут как стояли. Файл пишется целиком, затем заменяет старый:
падение во время записи оставляет прошлый.

Проверено: `openrts.content.server_kuban` сохраняет поезд Кубани с
номером и названием, очищает пути, ставит его обратно (номер, название,
заметки, тип, состояние, вагоны, место в пределах 0,5 м) и читает файл
как пульт; переставляет его с башмаками с обеих сторон (в записях — 0x100
и 0x200) и на 60 м дальше (номер, заметки и башмаки сохранены), не
ставит за пределы пути (поезд остаётся); расстановка, включающая его (но
не себя), ставит его, `placement get` помечает его `from`; выгрузка 41
состава в нескольких частях записана как отправлена; автосохранение и
сохранение прошлого запуска. `openrts.server` читает прежний файл
одиночной игры, пишет и читает новые поля, разбирает включения (цикл,
отсутствующую) и восстанавливает текст из строк выгрузки.

## Что он делает

**Вход** (`rts_server.exe` `0x4436C8`):
- первый пакет определяет вид: `0x4600` — игрок, `0x4500` — пульт (пока
  отказ `0x4702`), что-то другое — `0x4704`;
- протокол 101, иначе `0x4705`; ник от 1 до 15 знаков;
- тот же ник ещё раз перехватывает пользователя: старое соединение
  закрывается, его поезда остаются за ним (как переподключение у сервера
  RTS);
- ответ: `0x4600`, 101, «Маршрут: <RouteID>\r\nСезон: <сезон>», сезон и
  погода, RouteID строчными буквами и четыре счётчика, которые `rts1.exe`
  сверяет со своим маршрутом (узлы TDB, элементы пути, подстанции,
  электросекции: `reverse/multiplayer.md`, «Login»). Kuban даёт 1653, 4074,
  3, 3 — как `rts_server.exe`;
- затем `0x4601` на каждый поезд пользователя: меню ждёт хотя бы одного.

**Стартовые данные** (`0x4608`): только пользователю с поездом или уже
игравшему, иначе `0x4703` (один код, как в RTS). Снимок идёт в порядке
живого сервера (`net::write_snapshot`):
- корень, время;
- все стрелки (индекс = узел TDB − 1, ветка, блокировка);
- все головки сигналов (их элемент TDB, показание, состояние отрисовки,
  режим 1 или 0, когда диспетчер её держит, скорость);
- поезда: `0x4607`, `0x4603`, имя, `0x4606`, груз, сход, `0x4601` для своих;
- места других игроков (`0x462D`, имена по 32 байта), пауза;
- `0x4608`.

Электроснабжение не отправляется: клиенты считают его по своему маршруту.

**В игре** — по правилам `rts_server.exe`:
- `0x4603` поезда PLAYER от любого отправителя (RTS не проверяет
  владельца) запоминается и пересылается всем остальным; `0x4606` тоже,
  вместе с местом поезда;
- `0x4617`, `0x4639`, `0x463A`, `0x463C`, `0x463D` (огни, звуки, вид)
  уходят игрокам в пределах 3 км от поезда. Место игрока — это место его
  камеры (`0x462D`), а не поезда. openRTS: 15 с после того, как игрок
  попросил у владельца вид поезда (`0x4623` режим 2, пересылается
  владельцу), ответ доходит до него, где бы ни была его камера: клиент
  спрашивает, когда загружает поезд, а камера в этот момент может быть ещё
  за километры (там, где она начинала), и ответ терялся;
- `0x461B`, `0x461D`, `0x463F`, `0x4640` пересылаются; `0x461C`, `0x4636`
  пересылаются и запоминаются; `0x4641` делает поезд STATIC поездом LOOSE;
- `0x462D` запоминается и пересылается с id пользователя спереди и именем
  сзади, на 84 байта (как в живом захвате);
- отбрасывается, как от игроков RTS: `0x4602`, `0x4605`..`0x4607`,
  `0x4613`, `0x461A`, электроснабжение, `0x4649` (диспетчеров пока нет).
- Флуд (больше 5 000 пакетов или 2 500 звуковых за 5 с): `0x4706`, и
  пользователь отключается.
- Когда игрок уходит, его движущиеся поезда объявляются стоящими.

**Маршруты.** Станционные маршруты из базы маршрута («Сборка маршрута
поезда» на пульте, `0x450B`) пока не читаются: `route` ведёт до сигналов по
именам — именно их и соединяет станционный маршрут. И он, и ручной маршрут
пульта рассылают оставшееся расстояние (`0x4619`), как rts_server.exe; у
клиентов RTS нет для него обработки, пульты openRTS его рисуют.

**Стрелки и сигналы** решает сервер:
- `0x460A` / `0x4642` / `0x4609` игрока выполняется на сети сервера и
  рассылается всем. Запертая стрелка или стрелка под поездом — отказ, и
  отправитель получает её настоящее положение обратно.
- Сигналы работают так, как их ведёт `rts_server.exe` («Сигналы» ниже),
  каждые 0,05 с, со всеми поездами на сети сервера. Изменившаяся головка
  уходит как `0x460C`.

**Сигналы** (`simulation::SignalSystem::set_dispatched`; как это делает
RTS: `reverse/dispatcher.md`, «Режимы сигналов на сервере»):
- Единицы сигналов сервера — это объекты сигналов `rts_server.exe`:
  сигнальные элементы TDB в одной точке векторного узла, обращённые в
  одну сторону, в порядке его таблицы (в этом же порядке записаны
  `SignalUnit` базы маршрута).
- У каждой есть режим: **ручной** (головки держат то, что им задали, и
  скрипт не выполняют), **открыт** (выполняют, пока голова поезда не
  дойдёт до сигнала, потом снова ручной — чаще всего STOP),
  **автоблокировка** (выполняют всегда). Выполняющаяся головка видит
  `enabled` = режим и единицы впереди так, как стоят стрелки (заново при
  переводе любой), поэтому проходной показывает по показанию следующего.
  Цепочки поездов и свободно работающие головки, как в игре, не
  используются.
- При загрузке каждая единица ручная и один раз выполняется с `enabled` 0,
  затем база маршрута (`<RouteID>.rtsdb`) задаёт ей умолчания: `UnitFlags`
  бит 2 — открыт, иначе бит 4 — автоблокировка, иначе ручной, и единица
  выполняется один раз. Ручная не удерживается на `DefaultAspect`
  (`rts_server.exe` держит его на сигнале, выбранном на пульте, при
  загрузке такого нет): она показывает то, что дают её скрипты с
  `enabled` 0, — на Кубани в основном STOP_AND_PROCEED, красный, как в
  первом снимке живой записи; удержанные на STOP, её головки `-also` были
  бы тёмными («No»). Кубань (сборка 2026-11): 1405 единиц, 503 на
  автоблокировке, 902 ручных; без поездов её проходные показывают CLEAR_2
  389, APPROACH_1 40, APPROACH_3 14, RESTRICTING 44, STOP_AND_PROCEED 16.
  Значит, входные, выходные и маневровые горят красным, пока диспетчер их
  не откроет или не задаст маршрут; проходные перегона работают сами.
  «Вернуть умолчания» делает то же. `SignalUnit` находит свою единицу так
  же, как в `rts_server.exe` (сначала по своему номеру, затем по месту
  первой головки, которое у сигнала, обращённого в другую сторону в общей
  точке, сдвинуто на 20 м: `reverse/dispatcher.md`), так что используется
  каждая, и режимы — как в файле.
- Маршрут (`route`, `0x4619` пульта) открывает свои ручные сигналы по ходу
  поезда, кроме тех, чьё показание задал диспетчер; его конец или отмена
  закрывает те, что ещё открыты.
- Поле `+96` в `0x460C` — это `enabled` головки, поэтому в нём режим
  единицы (0 ручной, 1 открыт, 2 автоблокировка), как шлёт сервер RTS.
- **Пульты** (Legacy, `0x4500`; принимаются при включённом
  `ServerOptions::consoles`, как в сессии с 2026-11-21): после мира пульт получает `0x4618` каждой
  единицы (номер единицы, показание, режим, флаг диспетчера), затем —
  каждой единицы, у которой изменились показание, режим или флаг.
  `0x4618` от пульта задаёт единицу: режим 1 или 2 — этот режим, режим 0 —
  ручной на переданном показании (заданном диспетчером, если флаг стоит);
  на единицу, которой у сервера нет, приходит ошибка.
- **Типы «как поездной»** (`SignalTypeShownAsNormal` в базе маршрута,
  `signal type <тип> normal on|off`): их головки идут в показание своей
  единицы наравне с головками её низшей функции, при прогонах шага.
- **Умолчания**: `signal set-defaults` берёт режим и показание каждой
  единицы как её умолчания; `signal save` записывает их в копию базы
  маршрута у сервера: файл так, как его пишет «Сохранить всё» RTS (каждая
  единица по порядку с Position, NumSigItems, Name, UnitFlags с битами 2 и
  4 по умолчанию и остальными как были, DefaultAspect; типы — после
  заголовка), остальное (точки, маршруты, пути) как было. У единицы одно
  имя, как пишет RTS: на Кубани 901 имя стало 896 (несколько единиц,
  которым старая база давала два имени). Файл установки не трогается;
  если скопировать туда сохранённый, `rts_server.exe` получит те же
  умолчания.
- Маршруты станций — ниже.

**Маршруты станций** (`server::StationRoutes`, `GameServer::add_segment`;
как это делает RTS: `reverse/dispatcher.md`, «Маршруты станций и
отрезки»):
- При загрузке точки маршрутов из базы ставятся на путь (в пределах 3 м),
  а путь каждого маршрута станции прокладывается от начальной точки к
  конечной через перечисленные стрелки по порядку и в их положениях, и
  обратно; маршрут на станционный путь идёт до его дальней точки (у
  выходного светофора впереди, «точка окончания маршрута» из руководства).
  Кубань: 182 точки (все на пути), 828 маршрутов, 828 путей, все
  проложены в обе стороны.
- Что поезд может взять дальше (`StationRoutes::available`,
  `GameServer::next_from`): от конца его последнего отрезка (иначе от
  головы и от точки, у которой он стоит, в пределах 300 м назад) в
  выбранную сторону через стрелки в любом положении до первой точки
  маршрутов на каждом ответвлении; маршруты, начинающиеся там в эту
  сторону. Выход, от которого в эту сторону ничего нет, и точка, от которой
  ничего не начинается, проходятся, так что после маршрута на перегон идут
  маршруты следующей станции (Кубань от пути 4 Краснодара-1: Краснодар-2,
  Витаминкомбинат, Титаровка). Маршруты в одну сторону — только от начала.
- Маршрут поезда — цепочка отрезков, каждый — маршрут станции (от начала
  или от конца). Отрезок проверяется сразу (поезд; нет ждущего маршрута
  встречного поезда на дальнем конце перегона, на который выводит его
  конец; есть путь дальше от конца предыдущего отрезка поезда) и встаёт в
  очередь по приоритету.
- Каждый шаг выставляет те, чья очередь (предыдущий отрезок поезда
  выставлен и не держит следующий): конец на перегон ждёт маршрута
  встречного там или поезда, идущего навстречу по нему; точка начала ждёт
  другого ведомого поезда между; затем стрелки должны быть свободны (ни
  одна не замкнута и не держится для маршрута другого поезда, при
  проверках — нет другого поезда на пути между ними). Они переводятся,
  маршрут поезда прокладывается от головы до конца отрезка (удерживается,
  его ручные сигналы открываются, `0x4619`): состояние 1. Маршрут с
  флагом 8 можно выставить частично (состояние 2). Поезд на нём — 3;
  проехал — 4, и на следующем шаге отрезок уходит. Стрелку отрезка
  перевели иначе, пока маршрут поезда её держит, — отрезок снова ждёт.
- Отмена: маршрут поезда уходит (прокладывается заново до конца
  предыдущего отрезка, если тот выставлен).
- Пульты получают `0x450B`, когда отрезок встаёт в очередь, и в своём
  мире, `0x450E` при каждом изменении его состояния, `0x450D`, когда он
  уходит; на `0x450B` пульта (проверяется по станции и тайлу начальной
  точки) и `0x450D` отвечает `0x450C`.

**Поезда на сервере.** У каждого поезда есть копия на сети сервера
(`simulation::Train`): вагоны из файлов состава, поставленные туда, куда
указывает последний `0x4603`, и продвигаемые дальше с этой скоростью до
5 с, как экстраполирует `rts1.exe`. Они занимают путь для сигналов и
стрелок и делают сцепку и расцепку точными:
- `0x460F` (A взял B): владелец B, если это другой игрок, сначала получает
  `0x4601` «не твой»; затем остальные получают `0x460F`, владелец B —
  `0x4610` (B → A), все — `0x4603` объединённого поезда, как в живом
  захвате. Повторная сцепка с уже исчезнувшим поездом ничего не делает;
- `0x460E` (расцепка): отцеп получает наименьший свободный id и сохраняет
  вид, владельца, номер и состояние; отправитель получает `0x4610` (свой
  временный id → серверный), остальные — `0x460E` с новым id и `0x4603`
  отцепа.
- Стоящие поезда остывают, как на сервере RTS: `0x4605` «Включен» через
  480 с после остановки, «Холодный» через 1 200 с.

**Время** идёт с обычной скоростью; `0x460D` отправляется каждые 300 с
(как у `rts_server.exe`) и когда диспетчер его меняет.

## Помощники

- **Игроки openRTS** после входа шлют `0x45F4`, сервер отвечает. Такой
  игрок может получить мир без поезда (`rts1.exe` без поезда, как и раньше,
  ждёт в меню, `0x4703`): только если сам попросил (в меню «Войти без
  поезда», `--mp-no-train`); иначе, как в RTS, ждёт поезд от диспетчера
  (с 2026-11-21).
- **Запрос** (`0x45F5`): игрок просится помощником в поезд. Сервер
  спрашивает владельца (игрока openRTS в игре) и сообщает помощнику «ждём
  ответа»; владелец принимает или отказывает. Нельзя, если: нет такого
  поезда, его никто не ведёт, игрок ведёт его сам или одна из сторон не
  openRTS.
- **Диспетчер** назначает помощника командой `helper <ник> <поезд>`, как
  диспетчер в RTS, без вопроса машинисту; `helper <ник> off` снимает.
  `users` показывает, кто где помогает и кто играет в openRTS.
- **Потоки:** `0x45F6` владельца (его кабина) идёт его помощникам в этом
  поезде, `0x45F7` помощника (его рука) — владельцу поезда. Больше их
  никто не получает.
- **Помощь кончается**, когда уходит помощник или машинист, когда поезд
  отдают другому, забирают или удаляют, или когда так говорит одна из
  сторон; обоим сообщается.
- Сторона клиента — в `docs/ru/net.md`, «Игроки и помощники».
