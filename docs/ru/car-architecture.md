# Архитектура вагона и состава (проект)

Состояние: проект в обсуждении (2026-11-06). Ничего из этого не сделано.
- Он нужен для шага дорожной карты «Вагоны как сущности» (`roadmap.md`);
  сменные системы поезда оттуда строятся на нём.
- **Предложение** отмечает то, что предлагает этот документ; вопросы
  пользователю — в конце.
- Существующий контент и DLL RTS работают без изменений (см. «Цели»).

## Зачем: где сейчас живёт состояние вагона

| Где | Что там о вагоне | Заметки |
|---|---|---|
| `simulation::CarState` (`Train::cars()`) | физика, воздух (магистраль, резервуары, цилиндр), ручной тормоз, сцепки, рукава, кабели, краны, башмаки, раскачка кузова | по индексу: индекс меняется при каждой сцепке и расцепке |
| `TrainView::Car` (`viewer/src/train_view.cpp`, около 5500 строк вместе с остальным) | определение и ключ, модель и её загрузка, пантографы (нужные и нарисованные), наружные двери, огни, груз, звуки вагона, кабины и доп. библиотек, вид и звук для сети (`remote_*`, `net_*`) | состояние симуляции вперемешку с отрисовкой и объектами звука |
| `TrainView::Unit` | поезд, его роль, категория, ИИ-машинист, флаги хоста DLL, «чужой» | |
| `CabView` | положения переключателей кабины, двери, окна, столкновения, экраны | до 2026-11-06 жила, только пока в ней машинист (двери закрывались за ним); теперь хранится по ключу вагона в `board_cabs_`, это заплатка |
| хост DLL (`dllhost`, `CarMirror`) | состояние DLL, переключатели, `Init` один раз на вагон | по ключу вагона; паркуется, когда вагон уходит из хоста |
| `NetSession` | записи поездов сервера, ключи вагонов, свои и чужие поезда | ключ через сцепки переносится вручную |
| `Engineer` | где он: режим, ноги, индекс вагона | снова вагон по индексу |

Что из этого вышло, только за 2026-11-06:
- **Двери.** Смена кабины закрывала двери покинутой кабины.
- **Посадка.** Была написана дважды: своя кабина машиниста и другие
  кабины.
- **Непрочитанные кабины.** У кабины, ещё не прочитанной, все двери были
  открыты.
- **Ключи вагонов.** Их приходилось вручную проносить через сетевые
  сцепки, иначе терялась DLL вагона.

## Цели

- **Одно место на вагон.** Его состояние живёт в одном месте под одним
  постоянным id.
- **Логика отдельно от данных.** Логика — в сменных модулях: RTS, плагина,
  Lua («Сменные системы поезда» в дорожной карте).
- **Без окна.** Симуляция работает без окна: сервер openRTS выполняет тот
  же код.
- **Мультиплеер.** Вагон считает его владелец, остальные получают его
  состояние.
- **Legacy: как в RTS.** Шаг 0,05 с, ABI DLL RTS (`ts.h`), то, что видит
  `rts1.exe` на том же сервере.
- **Контент как есть.** `.eng` / `.wag` / `.sd` / `.con` читаются как
  сейчас. Автору нужно что-то делать, только чтобы использовать то, что
  сверх RTS.

Не цели:
- общий движок ECS (вагонов сотни, а не миллионы);
- новый формат контента;
- новый ABI DLL.

## Предлагаемая модель

### Вагон (предложение)

- **`CarId`:**
  - постоянный и уникальный в игре: сегодняшний ключ вагона;
  - создаётся один раз вместе с вагоном;
  - сохраняется через сцепки, расцепки, отданный и возвращённый поезд,
    расстановки;
  - номер вагона RTS (`train << 18 | record << 10 | UiD`) остаётся полем
    для сети.
- **Определение:** то, что говорит контент (`.eng` / `.wag`, его `.sd`,
  запись состава). Читается один раз, не меняется.
- **Компоненты:** простые данные; каждый есть, если он есть у вагона.

  | Компонент | Хранит |
  |---|---|
  | кузов | развёрнут ли, связь с физикой поезда (положение, скорость) |
  | сцепки | оба конца: состояние сцепки, рукава, концевые краны, кабели (СМЕ, высоковольтная шина), башмаки |
  | тормоза | магистраль, резервуары, цилиндр, состояние воздухораспределителя, ручной тормоз |
  | токоприёмники | пантографы нужные и поднятые |
  | двери | каждая дверь вагона, наружная и внутренняя (`ExteriorDoors` и `InteriorDoors` из `.sd`), у каждой одно состояние: модель вагона и модель кабины рисуют одну и ту же дверь |
  | огни | состояние и затухание каждого огня |
  | интерьер | пространства и двери между ними (ниже) |
  | кабина | переключатели пульта, табло, окна, кресла, лампы |
  | груз | грузы и их модели |
  | звук | триггеры и переменные как данные (объекты звука остаются во вьювере) |

- **Модули:** логика, подключённая к вагону в определённом порядке.
  - Модуль читает входы и компоненты и пишет компоненты:
    `step(car, train, dt)` плюс события (переключатель, клавиша, сцепка).
  - Модуль DLL RTS — адаптер хоста DLL. Собственное состояние DLL остаётся
    в процессе хоста; то, что она показывает (переключатели, выходы),
    зеркалится в компоненты.
  - Нативные плагины, позже Lua (план из дорожной карты).
  - Модули по умолчанию: логика MSTS, клавиатурный машинист, огни, двери,
    пантографы без DLL.
  - Системные модули: тормоза, тяга, как «Сменные системы поезда» в
    дорожной карте.
- **Класс — это набор:** какие компоненты и модули по умолчанию получает
  вагон, выбирается по его данным. Не дерево наследования C++; плагин
  меняет модули без наследования.

### Поезд (предложение)

- Упорядоченный список `CarId`, у каждого — его разворот.
- Что принадлежит всему поезду:
  - решатель сцепок и массивы физики, на которых он работает;
  - течение воздуха по тормозной магистрали между вагонами;
  - поездные провода: СМЕ, высоковольтная шина, цепи управления.
- **Сцепки и расцепки** сливают и делят списки. Компоненты вагона не
  трогаются, так что ничего не переносится вручную.
- **Роли** остаются у поезда: ведомый, ИИ, стоящий, чужой.

### Слои (предложение)

| Слой | Хранит |
|---|---|
| `simulation` | хранилище вагонов (`CarId` → вагон), поезда (списки id), шаг; без отрисовки и объектов звука |
| `trainplugin` | адаптеры модулей: хост DLL, нативные плагины, Lua |
| `viewer` | вид каждого вагона: его модель, модель кабины, звуки, выбор мышью; строится из компонентов и не хранит ничего, что нужно симуляции |
| `net` | передача компонентов; при Legacy на них ложатся пакеты RTS |

Сервер openRTS берёт `simulation` и `trainplugin` без `viewer`.

### Шаг (предложение)

При Legacy каждые 0,05 с, каждый раз в одном порядке (детерминизм для
мультиплеера и тестов паритета):
1. Входы: клавиши, мышь на кабине, сеть.
2. Модули вагонов (среди них `Run` у DLL), в порядке поезда.
3. То, что принадлежит поезду: поездные провода, магистраль, сцепки.
4. Физика.
5. Выходы: изменения по вагонам уходят в вид, звук и сеть.

### Владение и сеть (предложение)

- У каждого вагона есть владелец: клиент, который ведёт его поезд, иначе
  сервер (ИИ, стоящие поезда).
- Модули вагона выполняет только владелец. Сегодняшние замороженные DLL
  отданного поезда (вид 2) становятся общим правилом.
- У компонентов есть отметки изменений; отправляется изменившееся. При
  Legacy на компоненты ложатся пакеты RTS:
  - вид и огни: `0x4617`;
  - пантографы: `0x463C`;
  - звук: `0x4639` / `0x463D`, всё состояние — `0x463A`;
  - двери и тормоза: как описано в `net.md`.

### Интерьер и машинист (предложение)

- **Пространства** — области `Connects` из `.sd`: CAB, TAMBUR_*, SALON,
  TUALET, EXTERIOR, WAGON_FRONT / WAGON_BACK. У ЭД9М весь интерьер вагона
  — одна модель кабины с несколькими пространствами.
- **Двери** соединяют два пространства. Сцепка соединяет WAGON_BACK одного
  вагона с WAGON_FRONT следующего.
- **Машинист — находящийся** в (`CarId`, пространство, положение); позже
  пассажиры — тоже находящиеся.
- **Одно правило для каждой двери**, как в RTS (`reverse/train-dll.md`
  §13): Enter — дверь, Ctrl+Enter — пройти. Посадка, выход и переход в
  соседний вагон становятся одним проходом.
- **Кабина управления** — пространство кабины с пультом, в которое он
  вошёл. Вход в неё — смена модуля (`ChangeLoco`), как `0x436734` у RTS.

### Стандартные классы (предложение)

Выбираются по данным; плагин может заменить модуль или добавить свой.

| Класс | По чему выбирается | Компоненты | Модули по умолчанию |
|---|---|---|---|
| локомотив | `.eng` с двигателем, не в составе электрички | кабина или кабины, токоприёмники, тормоза, сцепки, огни, двери | его DLL, иначе клавиатурный машинист и логика MSTS |
| вагон электрички: головной, моторный, прицепной | тип RTS вагона, `EngExtended`, состав | по виду; у головного — кабина | DLL секции в каждом вагоне, где она есть |
| пассажирский вагон | `.wag` пассажирского вида | двери, интерьер (купе), огни, отопление, тормоза | по умолчанию |
| грузовой вагон | `.wag` грузового вида | тормоза, ручной тормоз, груз, двери и люки | по умолчанию |
| тендер и остальные | их вид | что нужно | по умолчанию |

## Как туда прийти

По одному шагу; на каждом сегодняшнее поведение сохраняется, проверка:
- тесты паритета DLL;
- офлайн-тесты звука;
- сетевые сценарии поддельного сервера;
- крючки вьювера `--capture-*` (`--capture-board` и остальные).

Шаги:
1. **`CarId` везде** (ключ вагона уже есть). Хранилище вагонов в
   `simulation`; поезда ссылаются на id. Вьювер не меняется.
2. **Двери, огни, пантографы** уходят из `TrainView::Car` в компоненты;
   вьювер читает их.
3. **Состояние кабины** переезжает в вагон; у `CabView` остаются только
   отрисовка и выбор мышью; `board_cabs_` уходит.
4. **Модули:** адаптер DLL, клавиатурный машинист и логика по умолчанию —
   за одним интерфейсом модуля.
5. **Шаг** переезжает в `simulation`: `TrainView` перестаёт его вести, и
   сервер может выполнять его без окна.
6. **Интерьер:** граф и находящиеся.
7. **Стандартные классы.**

## Открытые вопросы (решает пользователь)

1. **Без Legacy:** насколько openRTS может отходить от RTS (своя физика,
   свои модули тормозов)?
2. **Сохранённые расстановки:** только положение или полное состояние
   каждого вагона (переключатели, двери)? Собственное состояние DLL
   непрозрачно: сохранить можно только то, что показывает хост.
3. **Купе:** класс вагона или помещения внутри вагона (вагон с купе и
   служебным купе проводника)?
4. **Пассажиры:** в этом шаге или позже?
5. **Модули на Lua:** песочница и бюджет на шаг (из плана Lua в дорожной
   карте).
