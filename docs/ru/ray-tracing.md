# Трассировка лучей: тени от солнца лучами

Состояние: в игре с v0.50.0 (2026-11-27), экспериментальный путь (PBR),
Direct3D 12 и Vulkan.

## Что нужно

- Форк wgpu-native от openRTS начиная с `v27.0.4.0-openrts.6`
  (SmileDoge/wgpu-native, ветка `openrts`): ray query поверх
  `EXPERIMENTAL_RAY_QUERY` из wgpu 27. C API (`ffi/wgpu.h`):
  `wgpuDeviceCreateBlas` / `wgpuDeviceCreateTlas`, `wgpuBlasRelease` /
  `wgpuTlasRelease`, `wgpuCommandEncoderBuildAccelerationStructures`, TLAS
  привязывается через `WGPUBindGroupLayoutEntryAccelerationStructure` /
  `WGPUBindGroupEntryAccelerationStructure` в цепочке записей, флаг буфера
  `WGPUBufferUsage_BlasInput`. Форк разрешает устройству экспериментальные
  возможности, берёт лимиты трассировки у адаптера и содержит wgpu-hal
  27.0.4, где уровень трассировки D3D12 должен быть не ниже 1.1 (драйверы
  NVIDIA сообщают 1.2; исходная проверка на равенство их отвергала).
- CMake находит API в `wgpu.h` форка и задаёт `OPENRTS_HAS_RAY_QUERY`;
  устройство запрашивает `WGPUNativeFeature_RayQuery`, если адаптер его
  поддерживает (`renderer::ray_queries()`).
- Direct3D 12: Shader Model 6.5, то есть DXC (`dxcompiler.dll` рядом с
  программой, как в поставке игры).
- Видеокарта с трассировкой лучей: GeForce RTX, Radeon RX 6000 и новее,
  Intel Arc.

`tools/rt-probe` (`openrts-rt-probe.exe [vulkan]`): один треугольник в
BLAS, TLAS из него, вычислительный шейдер пускает луч в треугольник и луч
мимо; «ray queries work», если первый попал, а второй нет.

## Сцена

`renderer::detail::RayScene` (`include/openrts/renderer/ray_scene.hpp`):
один TLAS (не больше 65536 экземпляров), строится каждый кадр отдельным
буфером команд в конце `ModelRenderer::prepare` (`build_ray_scene`), до
проходов кадра.

- Модели: неподвижный экземпляр (поза покоя, ничего не скрыто) — один
  экземпляр TLAS из BLAS его уровня детализации: непрозрачные примитивы
  уровня как геометрии, их матрицы покоя в буфере преобразований.
  Анимированный или частично скрытый экземпляр: у каждого примитива свой BLAS (вершины в общих страницах или в
  собственных буферах модели, `first_vertex` / `first_index` в них),
  создаётся в первый кадр, когда примитив в очереди, не больше 384 новых за
  кадр. Не входят: смешиваемые примитивы, с альфа-тестом и с шейдерами
  смешивания (деревья, решётки, стекло) — лучам понадобились бы их
  текстуры; их тени остаются на картах. Матрица экземпляра: матрица модели,
  умноженная на локальную матрицу примитива, анимированную, если она есть
  (как `placement()` в `model/interface`), поэтому тени поездов,
  пантографов и дверей движутся вместе с ними. Входят все экземпляры
  очереди, в том числе тенеотбрасывающие вне поля зрения.
- Рельеф: у каждого тайла один BLAS из всей его сетки, строится при
  загрузке тайла; тайлы добавляются при каждом построении такими, какие
  они в этот момент (`RayScene::set_adder`), со сдвигом от начала маршрута.
- TLAS привязан в группе эффектов сцены (binding 14) и строится каждый
  кадр, даже пустой (привязанный TLAS должен быть построен).

## Тень

`effects/ray_shadow` — вычислительный проход после depth pre-pass камеры
(pre-pass идёт всегда, когда включены тени лучами): по глубине пикселя
восстанавливаются точка мира и нормаль поверхности (по ближним соседям по
каждой оси), пускается один луч к точке солнечного диска (0,27 градуса с
учётом мягкости теней), для каждого пикселя и кадра — другая точка (TAA их
усредняет); первое попадание завершает луч. Точка сдвигается от поверхности
на 2 см плюс 1 мм на метр от глаза. Проход пишет маску (R32F, размер
кадра); освещающие шейдеры читают её (`common/ray_shadow`, binding 14
группы эффектов; без ray query — 1 из `common/ray_shadow_off`). Точка перед
поверхностью pre-pass (стекло, смешиваемый кузов) берёт значение того, что
за ней. Тень от солнца — минимум из тени каскадов и маски, умноженный на
тень облаков.

До маски (первый вариант) каждый освещаемый фрагмент сам пускал четыре
луча: платил каждый перекрытый фрагмент, и тяжёлый шейдер работал
медленнее; на кубанском парке с 600 вагонами (у тестеров 80 FPS против 165
с картами) основной проход вырастал на 4,9 мс при 1280 x 720. Маска —
0,58 мс.

С тенями лучами каскады солнца (`DepthPassKind::sun_shadow`) не рисуют
примитивы, которые есть в сцене лучей: на картах остаются вырезанные по
альфе предметы и рельеф. Карты фонарей и кабины не изменились.

## Тени фонарей лучами (2026-11-27)

Тот же проход пускает ещё три луча: к трём фонарям, сильнее всех
освещающим пиксель среди фонарей его кластера (`physical_light`, умноженный
на яркость цвета), у которых нет своей карты теней
(SceneEffects::choose_lamp_shadows); выбор по порядку, не случайный (шума
нет, шумодав не нужен). Маска — RGBA32Uint, упакованная: r — свет (0..255)
солнца (биты 0-7) и трёх фонарей (8-15, 16-23, 24-31), g — номера первых
двух фонарей + 1 (по 16 бит), b — третьего; размытие усредняет свет
каждого фонаря только между пикселями с тем же фонарём. В освещающих
шейдерах `effects_lamp_shadow` берёт карту фонаря, если она есть, иначе
свет из маски, если пиксель трассировал этот фонарь, иначе 1. Так фонари с
картами (у камеры или кабины) остаются на картах, а до трёх остальных
фонарей каждого пикселя, как бы далеко они ни были, дают тень; фонарь с
ORTSNoShadow карты не получает, но луч получает. Проверено на парке с 600
вагонами в 01:10: проход лучей (солнце и фонари) 0,74 мс.

## Вырезанные по альфе: альфа текстуры в лучах (2026-11-27)

Примитив с альфа-тестом или шейдером смешивания, пишущий глубину, если
его текстура не сплошная на всех треугольниках, идёт в сцену лучей как
непрозрачная «не наверняка» геометрия: альфа его текстуры — слой одного
массива R8 (RayScene::mask_layer, 512 x 512, до 256 слоёв; слой на текстуру
и порог), UV его углов —
в одном буфере, таблица (начало UV, слой) по геометриям, первая запись
экземпляра — его custom data в TLAS (запись 0 — непрозрачная, для
рельефа). В `effects/ray_shadow` цикл кандидатов интерполирует UV по
барицентрическим координатам попадания и подтверждает попадание, где альфа
маски выше порога самой отрисовки (биты 16–23 записи таблицы: 0,3 как в RTS
для альфа-теста, 0,9 для смешиваемой, `alpha_cutoff` материала;
`docs/ru/pbr-materials.md`, «Вырезы и тени лучами»): рёбра и промежутки
вагонов, лестницы, решётки и листья дают ту тень, какими нарисованы.
Стекло, плафон или нарисованная тень под вагоном (текстура нигде не
доходит до 0,9) в сцену лучей не попадают вовсе (`shadow_mode` auto), как и
поверхность, которой материал задал `shadow_mode: "none"`. Всегда берётся
ближний уровень детализации. Когда массив или буферы заполнены, примитив
сплошной, если девять десятых его треугольников выше порога.

Дальше 60 м от камеры лучи текстуру не читают: маска — сплошная,
пропускание — весь его цвет (дыры в тени там — пиксель-другой).

Пропускание (`shadow_mode: "transmission"`, стекло): кандидаты не
подтверждаются; луч берёт `mix(1, цвет, alpha)` каждого (z записи таблицы —
цвет, вид 1, слой — альфа текстуры как есть, alpha_layer), каждую геометрию
экземпляра один раз, не больше 4 (пятый слой или меньше 2 % — перекрыт).
В a маски — цвет солнца сквозь стекло (каждый канал от наибольшего, 8 бит;
белый — 0xFFFFFF), в r — наибольший канал; effects_ray_sun_tint из
common/ray_shadow отдаёт его солнечному свету экспериментального рендерера,
земли и воды; фонарь берёт яркость.
Испробовано и отброшено (2026-11-27, доля прохода лучей от основного
прохода): сначала сплошные отдельным лучом, потом вырезы другим (1,70 против
1,30: большинство лучей ничего не встречает и проходило сцену дважды);
дальние вырезы, пропускающие свет (1,82: пропущенный луч летел дальше через
все деревья). Все вырезы сплошные: 1,08.

Слой — сплошной или открытый (255 или 0) по порогу (coverage_mask): для
каждого текселя маски — доля исходных текселей выше порога, затем сплошными
становятся столько текселей, сколько их в исходнике, начиная с больших
долей. Большая текстура сохраняет долю сплошного, прут шириной в полтекселя
маски остаётся линией (чуть шире), дыра шириной в тексель маски остаётся
открытой; мельче этого (прут или дыра в один тексель текстуры 2048 при
512) не различить, сохраняется только доля (пересечения мелкой решётки).
Раньше ближайший тексель выбрасывал или заливал такие детали как попало.
Текстура 512 и меньше — как была (tests/ray_mask_test.cpp).

Замер 2026-11-27 (RTX 4070 Ti SUPER, D3D12, 1280 x 720, без DLSS/TAA,
без ограничения кадров, по 70 с, два прогона; проход лучей, мс): вид
станции `Kuban_RTS_20261127_144827` — 3,07 с чтением текстур, 2,60 со
всеми вырезами сплошными; лесной вид `Kuban_RTS_20261127_forest` (ряды
тополей, ели) — 1,05 против 0,98. Чтение альфы стоит не больше 0,5 мс, в
лесу 0,07: микрокарты непрозрачности (OMM) больше этого не выиграют.

`OPENRTS_RAY_CUTOUT_LOG=1` печатает каждый вырез, получивший маску: его
текстуру, шейдер, альфа-тест, смешивание, порог (0..255), долю треугольников
выше порога и альфу текстуры (выше 0,3, не меньше 0,9, любая, частичная).

## Микрокарты непрозрачности (2026-11-27)

Форк с `v27.0.4.0-openrts.6` строит микрокарты непрозрачности (OMM) на
Vulkan (`VK_EXT_opacity_micromap`) и D3D12 (массивы микрокарт DXR 1.2,
уровень трассировки 1.2; inline-лучи на шейдерной модели 6.9 с
`RAYQUERY_FLAG_ALLOW_OPACITY_MICROMAPS`, naga пропатчена): в `ffi/wgpu.h` —
`wgpuDeviceSupportsOpacityMicromaps`, `wgpuDeviceCreateOpacityMicromap`,
`wgpuOpacityMicromapRelease` и `wgpuDeviceSetNextBlasOpacityMicromaps`
(следующий BLAS, созданный на этом потоке, берёт их, по одной на геометрию).

Вырез с маской (renderer/opacity_micromap.hpp): каждый треугольник делится
на 256 микротреугольников (уровень 4); микротреугольник непрозрачный или
прозрачный, если таковы все тексели маски под ним, иначе — неизвестный
(край текстуры). Непрозрачные железо засчитывает само, прозрачные
пропускает; до цикла кандидатов в шейдере и маски доходят только
неизвестные. Одинаковые микрокарты общие, треугольник целиком в одном
состоянии — специальный индекс. Строятся в отдельном рабочем потоке: BLAS
модели создаётся в кадре, когда её микрокарты готовы. Не для пропускания
(стекло) и не для сплошной геометрии. `OPENRTS_OMM=0` — без них, для
сравнения. Вблизи тени те же, что без них; дальше 60 м прозрачные
микротреугольники пропускают свет там, где лучи считали вырезы сплошными
(tests/opacity_micromap_test.cpp: микротреугольники по кривой покрывают
треугольник ровно по разу; непрозрачный или прозрачный — такой целиком).

Замер 2026-11-27 (без ограничения кадров, `--fps-background`, по 70 с;
проход лучей с микрокартами / без, мс): станция D3D12 3,05 / 3,16, Vulkan
2,95 / 3,10; лес D3D12 1,04 / 0,93, Vulkan 0,97 / 1,04. В пределах разброса:
на этих видах чтение альфы — малая доля прохода (замеры до них частью шли
на 30 кадрах — окно без фокуса).

## Настройки

«Тени лучами» (Графика, настройки графики в лаунчере; `shadow_rays`,
по умолчанию выключено), неактивна, если у видеокарты нет трассировки.
`OPENRTS_RAY_SHADOWS=0`: выключить на один запуск (для сравнения с картами).

Проверено 2026-11-27 (RTX 4070 Ti SUPER, Direct3D 12, 1280 x 720): на
Кубани рядом с ВЛ80с в 15:00 и 19:00 провода контактной сети, опоры и
столбики отбрасывают тени на шпалы и траву, которые на картах терялись или
размывались; на парке с 600 вагонами (отладочный вид и расстановка
`600wags`) проход теней лучами 0,58 мс, весь кадр 10,2 мс против 10,9 только
с картами (каскады легче); ошибок WebGPU нет.
