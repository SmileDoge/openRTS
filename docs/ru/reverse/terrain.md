# Рельеф RTS и выбор окружения

> Перевод [`docs/reverse/terrain.md`](../../reverse/terrain.md). Основной
> текст — английский: при расхождении верен он.

Состояние: проверки на настоящем контенте Kuban_RTS плюс статический
анализ `rts1.exe` (`0x422648`, `0x4224F8`) и `GLOBAL/SHADERS/terrain.*`.
Реализовано в `formats/src/terrain.cpp` и
`renderer/src/terrain_renderer.cpp`.

## Файлы тайлов

### CONFIRMED (контент)

- `TILES/<name>.t` (двоичный `JINX0t6b`) + `<name>_y.raw` (высоты u16).
  `<name>` — путь в 15-уровневом дереве квадрантов над тайлами
  [-16384, 16384), по два уровня на шестнадцатеричную цифру; проверено для
  всех 9 тайлов вокруг старта на Кубани.
- Высота = `floor + scale · y`; 256 отсчётов на сторону, через 8 м.
- Ориентация по непрерывности краёв на холмистых тайлах: столбцы растут на
  восток (+x), строки — на юг (−z); строка 0 совпадает со строкой 255
  северного соседа, столбец 255 — со столбцом 0 восточного.
- Участки 16×16 по 16 отсчётов. Текстурные координаты участка используют
  номера отсчётов внутри участка: `u = X + W·j + B·i`, `v = Y + C·j + H·i`
  (Кубань: `X = Y ≈ 0.002`, `W = H ≈ 0.0623`, т. е. одна текстура на
  участок с отступом в полтекселя).
- Шейдеры рельефа: `DetailTerrain` (текстура + микротекстура),
  `AlphaTerrain` (только текстура). Имена текстур в UTF-16 и могут быть
  кириллическими.

### PROBABLE

- Нормали вычисляются по высотам; `_n.raw` (65536 байт) и `_e.raw` не
  интерпретируются.
- AlphaTerrain рисуется с нейтральной микротекстурой (шейдер RTS умножает
  на микротекстуру и 2; что RTS для неё привязывает, не прослежено).
- Флаги участков пропускаются (скрытых участков не видели).

## Триангуляция (`0x49D228`)

### CONFIRMED

При полной детализации RTS раскладывает каждый блок 2×2 отсчёта веером
вокруг его центрального отсчёта (нечётная строка, нечётный столбец).
Поэтому диагонали четырёхугольников чередуются в шахматном порядке и
всегда проходят через отсчёт нечёт-нечёт: четырёхугольник в (строка,
столбец) делится по (строка, столбец)–(строка+1, столбец+1), когда строка и
столбец одной чётности, иначе по другой диагонали. Нормали вершин берутся
из таблицы на каждый отсчёт (ещё не расшифрована; openRTS вычисляет их по
высотам).

### Проверка контентом (Kuban_RTS)

- Начала объектов пути лежат на рельефе (медианная разница 1 мм примерно
  на 3000 объектах): сетка не сдвинута и не отражена.
- Вдоль осей прямого пути выбор диагонали ничего не меняет (путь идёт по
  линиям отсчётов). Около 6 % точек оси ниже рельефа больше чем на 20 см,
  они собраны в немногих тайлах (до 89 % в одном тайле) и не на краях
  тайлов: рельеф там не опустили до основания пути. У моделей пути нет
  `ESD_Cover_Terrain`; скрывает ли RTS там рельеф — UNKNOWN.

## Шейдер (`terrain.vert/frag`)

`colour = max(diffuse · clamp(−2·N·L), ambient)`;
`texel = texture(uv) · microtexture(uv · 16) · 2`; туман по глубине в
пространстве отсечения; `texel.a == 0` пишет чёрный. Глубина `LEQUAL` с
записью, без смешивания.

## Сезонные текстуры (`0x422648`)

Сезон 0..3 = весна, лето, осень, зима; погода 0 ясно, 1 снег, 2 дождь.

| Сезон | Снег | Порядок поиска в `TERRTEX\` |
|---|---|---|
| лето | любой | (нет) |
| весна | да | `SPRINGSNOW\`, `SNOW\`, `SPRING\` |
| весна | нет | `SPRING\` |
| осень | да | `AUTUMNSNOW\`, `SNOW\`, `AUTUMN\` |
| осень | нет | `AUTUMN\` |
| зима | да | `WINTERSNOW\`, `SNOW\` |
| зима | нет | `SNOW\` |

Запасной вариант: `TERRTEX\<name>` (RTS ещё и пишет ошибку в журнал).

## Выбор окружения

Блок `Environment` в `.trk` сопоставляет `<Season><Weather>` (например,
`WinterSnow`) файлу ENV в `ENVFILES\`. Блок тумана, вычисленный небом (см.
`sky.md`), — тот же блок uniform, что привязывается к шейдерам моделей и
рельефа, поэтому геометрия сцены уходит в цвет неба (PROBABLE: привязка
буфера прочитана из декомпилированного кода).

## Не перенесено

Выбор LOD рельефа / порога ошибки (рисуется полная детализация в пределах
2 тайлов), дальние `LO_TILES`, дополнительные источники света на рельефе,
динамический рельеф (особенность RTS), дыры в рельефе.
