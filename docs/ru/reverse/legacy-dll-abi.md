# ABI старых DLL локомотивов

> Перевод [`docs/reverse/legacy-dll-abi.md`](../../reverse/legacy-dll-abi.md).
> Основной текст — английский: при расхождении верен он.

Состояние: статический анализ только для чтения существующей базы IDA
`rts1.exe.i64`. Проверок во время работы не проводилось. Адреса относятся
к разобранному `rts1.exe`.

Публичный источник ABI — оригинальный `ts.h`, распространяемый с контентом
RTS. Документация PDF описывает `LibraryModule` как основной модуль
локомотива, а `AuxLibraries` / `AuxCall` — как его механизм
вспомогательных модулей. Разделы ниже отличают факты, подтверждённые кодом
и заголовками ABI, от выводов.

## Жизненный цикл основной DLL локомотива

### CONFIRMED

Путь основной DLL:

```text
разобранное имя модуля из ENG
  -> sub_5026FC
  -> закэшированный дескриптор библиотеки (sub_4389E8)
  -> поиск пути и sub_56D9C8(..., 7)
  -> LoadLibraryW в sub_56DBE4
  -> InitRTSLibrary / DLLVersion в sub_5364D0
  -> обратные вызовы через GetProcAddress в sub_5026FC
  -> основной Init, затем Init вспомогательных
  -> основной Run между пред- и пост-рассылкой вспомогательным в sub_5031D8
```

`0x5026FC sub_5026FC` берёт строку имени модуля из уже разобранной записи
со стороны ENG/WAG, получает закэшированный дескриптор и загружает его с
аргументом контекста `7`. Он находит в загруженном модуле основные
обратные вызовы `_CanWorkWith`, `_Init`, `_ChangeLoco`, `_LostMaster`,
`_CanSwitch`, `_Switched`, `_ALSN`, `_SpeedLimit` и `_Run`.

Перед основным `Init` эта функция выделяет и инициализирует объект
локомотива времени выполнения через `0x4FE6C8 sub_4FE6C8` или
`0x4FE734 sub_4FE734`. Она получает объекты, передаваемые плагину, через
`_RTSGetLocoObject` и затем вызывает сохранённый `_Init`. После основного
вызова она вызывает `0x56EE38 sub_56EE38` для `Init` вспомогательных.

`0x5031D8 sub_5031D8` — прямое наблюдаемое место вызова сохранённого
указателя основного `Run`. Она рассылает `Run` вспомогательным до
основного обратного вызова, вызывает основной `Run`, затем рассылает
вспомогательным после него. Её единственный прямой вызывающий, найденный в
этом проходе, — `0x424488 sub_424488`.

### PROBABLE

Разобранная строка, которую потребляет `sub_5026FC`, — представление
`LibraryModule` из ENG во время выполнения. Документация называет это
поле, а этот проход ещё не нашёл разборщик, который пишет сырое поле.

`0x424488 sub_424488` — скорее большая процедура обновления поезда /
симуляции, чем главный цикл приложения. Здесь установлен только её прямой
вызов `sub_5031D8`.

## Дескриптор библиотеки (`LibraryRecord`, предполагаемое имя)

У этой записи сейчас нет пользовательского типа в IDB. `0x4389E8
sub_4389E8` устраняет дубли записей по имени модуля без учёта регистра в
глобальном пуле `dword_61D53C`; `0x56DC14 sub_56DC14` уменьшает её счётчик
ссылок и освобождает её при нуле.

| Смещение | Тип / предполагаемое имя | Уверенность | Доказательства |
|---:|---|---|---|
| `+0x00` | `wchar_t *moduleName` | CONFIRMED | Выделяется и используется для поиска модуля / пути. |
| `+0x04` | `HMODULE module` | CONFIRMED | Пишется `LoadLibraryW` в `sub_56DBE4`; читается всеми последующими вызовами `GetProcAddress`. |
| `+0x08` | флаг `loaded` | CONFIRMED | Проверяется `sub_56D9C8` перед повторной загрузкой. |
| `+0x09` | флаг `loadFailed` | CONFIRMED | Ставится после неудачного `LoadLibraryW`; проверяется при следующих попытках. |
| `+0x0C` | счётчик ссылок | CONFIRMED | Увеличивается путями основной / вспомогательной; уменьшается `sub_56DC14`. |
| `+0x10` | указатель на таблицу адаптеров | CONFIRMED | Присваивается `sub_537DC8` для старых версий DLL и используется функциями поиска объектов. |
| `+0x14` | размер стека переменных DLL | CONFIRMED | Получает `DLLVersion(DLLV_STACKSIZE)`. |
| `+0x18` | флаги ABI / раскладки | PROBABLE | Биты ставятся при двух наблюдаемых несовпадениях размеров раскладки; точные потребители не изучены. |

## Поиск пути модуля и загрузка

### CONFIRMED

`0x56D9C8 sub_56D9C8` вызывает `0x56DBE4 sub_56DBE4`, затем вызывает
`0x5364D0 sub_5364D0` только после успешной загрузки. Для аргумента
контекста `7` наблюдаемый поиск пробует пути в `TRAINS\\TRAINSET` и
`GLOBAL\\LIB`, с запасными вариантами по переданному имени модуля.
`sub_56DBE4` вызывает `LoadLibraryW` и сохраняет возвращённый `HMODULE` в
смещении дескриптора `+0x04`.

### PROBABLE

Контекст `7` обозначает контекст поиска основной библиотеки локомотива.
Основная загрузка явно его использует; смысловая метка выведена из этого
использования.

## `InitRTSLibrary` и экспорты API со стороны RTS

### CONFIRMED

`0x5364D0 sub_5364D0` находит `_InitRTSLibrary` в DLL плагина и вызывает:

```cpp
InitRTSLibrary(GetModuleHandleA(nullptr), libraryRecord);
```

Таким образом, `Module` — HINSTANCE `rts1.exe`, а `DLL` — внутренний
дескриптор библиотеки RTS, а не `HMODULE` плагина. Это совпадает с
`ts.h`, чей `InitRTSLibrary(HINSTANCE Module, void *DLL)` сохраняет второй
аргумент в глобальной переменной DLL `DLLHandle` и находит функции API RTS
в `Module`.

Найдены следующие экспортируемые функции со стороны RTS:

| Экспорт | Адрес | Заметки |
|---|---:|---|
| `_RTSGetInteger` | `0x43929C` | Чтение целого. |
| `_RTSSetIntegerG` | `0x43939C` | Запись целого. |
| `_RTSGetNamedInteger` | `0x4394F4` | Чтение именованного целого. |
| `_RTSIsSMSTriggerOn` | `0x439548` | Запрос триггера. |
| `_RTSGetTrackItems` | `0x4805D8` | Доступ к элементам пути. |
| `_RTSGetLocoObject` | `0x536650` | Поиск объекта локомотива / движка. |
| `_RTSGetLocoObjectByName` | `0x536920` | Поиск объекта локомотива по имени. |
| `_RTSGetCabObject` | `0x536B14` | Поиск объекта кабины. |
| `_RTSGetCabObjectByName` | `0x536F08` | Поиск объекта кабины по имени. |
| `_RTSGetObject` | `0x537590` | Направляет общие запросы объектов. |
| `_RTSGetObjectByName` | `0x5375F8` | Направляет общие запросы по имени. |

`_RTSGetObject` направляет запросы к функциям поиска локомотива / кабины.
Функции поиска локомотива и кабины при определённых условиях используют
таблицу адаптеров, прежде чем выдать объект.

## `DLLVersion` и проверки ABI

### CONFIRMED

После успешного `InitRTSLibrary` `0x5364D0 sub_5364D0` находит
`_DLLVersion` и:

- требует `DLLVersion(DLLV_VERSION) >= 101`;
- сохраняет `DLLVersion(DLLV_STACKSIZE)` в дескриптор `+0x14`;
- проверяет возвращённые размеры `TrackItem` и `TrackItemsItem`, записывая
  биты несовпадения в дескриптор `+0x18`;
- когда `DLLVersion(DLLV_ADAPTER_COMPLIANCE) < 39`, сравнивает набор
  размеров объектов старого ABI (включая переключатель, дисплей, экран,
  локомотив, движок, свет, подобъект класса и объект);
- принимает версию `104` напрямую, когда соответствие адаптерам не меньше
  `39`;
- вызывает `0x537DC8 sub_537DC8` для поддерживаемых нетекущих версий.

Оригинальный `ts.h` определяет `DLLV_ADAPTER_COMPLIANCE` как запрос `18`,
`DLLV_STACKSIZE` — как запрос `19`, и выдаёт значение соответствия `39`,
когда включён соответствующий макрос соответствия адаптерам.

## Основные обратные вызовы

### CONFIRMED

`0x5026FC sub_5026FC` сохраняет адреса основных обратных вызовов, найдя их
через дескриптор `+0x04`. Среди вызывающих, замеченных в этом проходе, —
`0x468C74`, `0x4F995C` и `0x57CD78`.

`0x468C74 sub_468C74` вызывает основной `ChangeLoco` и рассылку этого
события вспомогательным. `0x528540 sub_528540` вызывает основной
`CanSwitch` с пред- и пост-обработкой вспомогательных; `0x5288CC
sub_5288CC` делает соответствующую рассылку `Switched`. Эти назначения
основаны на найденных строках экспортов и наблюдаемых вызовах через
сохранённые указатели функций.

## Загрузка и рассылка вспомогательных DLL

### CONFIRMED

Когда есть разобранные данные вспомогательных, `0x5026FC sub_5026FC`
создаёт стек вспомогательных и вызывает:

- `0x56DC3C sub_56DC3C` — создаёт записи вспомогательных из разобранных
  данных и строит настройку обратных вызовов по умолчанию, если её нет;
- `0x56E970 sub_56E970` — загружает каждый вспомогательный модуль через
  `sub_56D9C8`, находит `_Init`, `_ChangeLoco`, `_LostMaster`, `_ALSN`,
  `_SpeedLimit`, `_Run`, `_CanSwitch` и `_Switched` и выделяет его стек
  переменных;
- `0x56EE38 sub_56EE38` — вызывает `Init` вспомогательных после основного
  `Init`;
- `0x56EADC sub_56EADC` — рассылает Run, ChangeLoco, LostMaster, CanSwitch
  и Switched по настроенному порядку;
- `0x56EF60 sub_56EF60` — рассылает ALSN;
- `0x56F068 sub_56F068` — рассылает SpeedLimit.

Поиска `_CanWorkWith` у вспомогательных не замечено, что совпадает с
документированным набором обратных вызовов вспомогательных. `sub_5031D8`
даёт подтверждённый порядок «до основного / после основного» для `Run`.

### PROBABLE

Каждая запись вспомогательной занимает `0x54` байт в созданном массиве.
Полная раскладка её полей не восстановлена, поэтому этот документ
намеренно не даёт имён полям сверх описанных выше обращений к обратным
вызовам и дескриптору.

## Адаптеры ABI для старых версий

### CONFIRMED

`0x537DC8 sub_537DC8` распознаёт версии ABI DLL `101`, `102` и `103` и
сохраняет указатель на таблицу конкретной версии в дескриптор `+0x10`.
Текущая версия — `104`.

Функции поиска объектов `_RTSGetLocoObject` и `_RTSGetCabObject`
используют эту таблицу, чтобы выбрать путь через адаптер / обёртку.
`0x53782C sub_53782C` и `0x538548 sub_538548` выполняют наблюдаемую
отложенную обработку обновления адаптеров после путей обратных вызовов
плагина. Следовательно, слой адаптеров по версиям существует для версий
ABI 101–103.

## UNKNOWN / открытые вопросы

- Точный разборщик и смещения сырой разобранной записи для
  `LibraryModule`, `VariableStack`, `AuxLibraries` и `AuxCall` не найдены.
- Полный смысл флагов `LibraryRecord+0x18` и их потребители неизвестны.
- Раскладки и точные правила преобразования объектов таблиц адаптеров,
  выбираемых для версий 101–103, неизвестны.
- Точные конкретные типы, которые представляют два выделения движка в
  `sub_4FE6C8` и `sub_4FE734`, одним этим проходом не установлены.
- Полная раскладка записи вспомогательной в `0x54` байта неизвестна.
- `sub_424488` — прямой вызывающий рассылки Run, но главный ли это цикл,
  фаза обновления поезда или вложенная процедура симуляции, требует
  дальнейшего анализа вызывающих и контекста.
- Все результаты — только статические данные; порядок и обработка ошибок
  не проверены на работающем оригинальном RTS.
