# Слой RTS ↔ DLL локомотива

> Перевод [`docs/reverse/train-dll.md`](../../reverse/train-dll.md).
> Основной текст — английский: при расхождении верен он.

Как `rts1.exe` и DLL локомотивов работают вместе: когда происходит каждый
вызов, что передаётся и читается обратно и почему. Шаг 5 плана, пункт 0.
Вытекающее из этого устройство хоста — в `docs/train-dll.md`; основы ABI
(поиск модуля, `InitRTSLibrary`, `DLLVersion`, адаптеры) — в
`legacy-dll-abi.md`.

Источники:
- `rts1.exe` (статический анализ в IDA; адреса ниже);
- `ts.h` (TS_VERSION 104), заголовок, который RTS поставляет авторам DLL
  (`TRAINS/TRAINSET/tsrLoco_VL80k-125/CAB/ts.h`; сюда не копируется);
- исходник DLL ВЛ10к
  (`TRAINS/TRAINSET/tsrLoco_VL10k-1461/cab/vl10k_main.cpp`), сторона DLL
  того же договора.

CONFIRMED означает «прочитано в коде» (и, где отмечено, согласуется с
`ts.h` или исходником ВЛ10к); ничего здесь не запускалось на живом RTS.

## 1. Объекты — собственные вагоны RTS

**CONFIRMED.** Объекты, которые получает DLL, — не копии, сделанные для неё:
это внутренние объекты вагонов RTS, разложенные точно так, как их объявляет
`ts.h`, с упаковкой по 4 байта. Смещения, найденные раньше в физике
(`runtime-overview.md`), совпадают с `ts.h` поле в поле:

| Смещение | Поле `ts.h` | Найденное раньше использование в физике |
|---:|---|---|
| `+0x0C` | `Wagon::IsLocomotive` (класс WCL: 1 электрический, 2 тепловоз) | «вид локомотива» |
| `+0x0D` | `PantoRaised` (бит на токоприёмник) | пишется рассылкой `Run` |
| `+0x1C` | `Flags` (бит 0 развёрнут, бит 2 игрок внутри, байт 2 магистрали / краны, байт 3 кабели) | «флаги; бит 0 развёрнут» |
| `+0x24` | `Mass` | масса |
| `+0x2C` | `BrakeForce` | накопитель диссипативной силы |
| `+0x34` / `+0x38` | `IndependentBrakePressure` / `AuxiliaryPressure` | — |
| `+0x44` / `+0x48` | `Velocity` / `Acceleration` | скорость / ускорение |
| `+0x4C` / `+0x50` / `+0x54` | `Resistance` / `Slope` / `Force` | сопротивление / уклон / активная сила |
| `+0x58` | `double ZOrd` (выровнен на 4) | смещение вагона в поезде |
| `+0x60` / `+0x64` / `+0x68` | `BrakeCylinderPressure` / `TrainPipePressure` / `TrainPipeRate` | цилиндр / магистраль |
| `+0x98`, `+0xD8` | `TrackPDP TrPos[2]` (по 64 байта) | два путешественника |
| `+0x138` | `void *wag` | разобранный тип ENG/WAG |
| `+0x158` | `AnimParts` (узлы по 120 байт) | части токоприёмников |
| `+0x184` | `Locomotive::LocoFlags` | — |
| `+0x194` | `MainResPressure` | — |
| `+0x1A4` | `cab` | «объект кабины» |
| `+0x1B0` / `+0x1BC` | `Slaves` / `locoA` (`Engine*`) | — |
| `+0x1D8` / `+0x1DC` | `LibModule` (дескриптор библиотеки) / `AuxLibs` | — |
| `+0x1EC` | `ElectricLocomotive::Run` | «указатель на Run основной DLL» |
| `+0x1F8` | `LineVoltage` (электрический) / `FuelAmount` (тепловоз) | — |

`Engine` (208 байт) и `ElectricEngine` (216, выделяется как `0xD8` в
`0x5026FC`) — отдельные объекты, доступные через `locoA`.

Поэтому «входы» и «выходы» — вопрос лишь того, кто пишет поле и когда:
физика RTS пишет скорости и давления в ту же память, которую читает DLL, а
DLL пишет поля `Engine`, которые RTS читает после вызова. DLL может
добраться до каждого объекта поезда через указатели (`Slaves`,
`FirstInGroup` / `LastInGroup`, `cab`, `locoA`) и через функции поиска и
может хранить указатели между вызовами.

## 2. Загрузка и привязка

### Когда загружается DLL

**CONFIRMED (`0x468C74`, вход в локомотив).** Когда игрок берёт локомотив
(`a2`):
1. каждый локомотив поезда теряет бит 2 `LocoFlags` («в сплотке игрока»);
2. кабина загружается, если ещё не загружена (`0x51CD88`; в сетевой игре
   отправляется сетевое сообщение);
3. `Flags |= 4` (игрок внутри), `LocoFlags |= 0x10 | 0x40` (есть кабина,
   кабина загружена для игрока);
4. больше ничего, если поезд не игрока (тип 1) и не тип 4 или локомотив
   холодный или под ИИ (`LocoFlags & 0x88`);
5. если ENG называет DLL (`wag + 568`), DLL привязывается и
   инициализируется (`0x5026FC`, ниже); при неудаче показывается сообщение
   0x94 с именем ENG;
6. следуют `ChangeLoco` и группировка системы многих единиц (раздел 3).

Другие поезда (трафик, статические) никогда не загружают DLL.

### Привязка (`0x5026FC`)

**CONFIRMED.**
- Пропускается, если DLL уже привязана (`LocoFlags & 0x20`, «скрипт
  загружен»).
- `LibParam` = параметр `LibraryModule`, `StackSize` = `VariableStack`,
  `NumEngines` / `NumAxles` из ENG.
- Дескриптор библиотеки находится или создаётся по имени и загружается
  один раз на модуль (`0x56D9C8`; счётчик ссылок дескриптора). `StackSize`
  поднимается до `DLLVersion(DLLV_STACKSIZE)`, если тот больше.
- Выделяется объект `Engine` (`0xD8` байт для электрического, `0x4FE6C8`;
  вариант для тепловоза — `0x4FE734`) со своим стеком переменных.
- Обратные вызовы находятся по имени: `_CanWorkWith`, `_Init`,
  `_ChangeLoco`, `_LostMaster` (хранится как `LostSlave`), `_CanSwitch`,
  `_Switched`, `_ALSN`, `_SpeedLimit`, `_Run`. Создаются и загружаются
  вспомогательные библиотеки (`0x56DC3C`, `0x56E970`).
- **`Init(eng, loco, State, time = 0.0, AirTemperature)`**, затем
  отложенные обновления адаптеров (раздел 7).
  - `State`, младший байт: бит 0, когда в поезде есть вагоны (флаг
    вызывающего: какой-то вагон — вагон или холодный локомотив, `v29` в
    `0x468C74`; или байт поезда `+2` = 1), бит 1, когда он начинает в
    движении (скорость поезда `+0x5C` ненулевая или байт `+2` = 2);
    заменяется начальным состоянием задания, когда у поезда оно есть
    (поезд `+0x14` → `+0x48`). `ts.h`/`export.pdf`: 0 холодный без
    вагонов … 3 в движении с вагонами.
  - **CONFIRMED** начальное состояние задания: `Train ( TrainState ( n ) )`
    в `.act` (`0x471B9C`, `"trainstate"` → поезд задания `+0x48`);
    RTSFileReference: 0 стоит без вагонов, 1 стоит с вагонами, 2 едет без
    вагонов, 3 едет с вагонами; 0 — холодный поезд (огни выключены,
    дизели стоят, токоприёмники опущены, звуков нет); по умолчанию 0 для
    статических поездов и 1 для остальных. **UNKNOWN**: без `TrainState`
    поезд, у которого `Type` задания (`+16`, по умолчанию 2) равен 2,
    получает там 2; какой это тип 2, не прослежено.
  - openRTS: `--start cold|on|running` (вьювер) и окно поезда дают `Init`
    TrainState задания (0, 1 или собственные биты поезда). ЭД9М (MaDaDev)
    выполняет `Init` только при ненулевом состоянии: холодным он оставляет
    всё выключенным.
  - **PROBABLE** байт поезда `+2` — состояние от диспетчера: в
    «Редактировании поезда» пульта есть `cbTrainState` = Холодный /
    Включен / Движется (0 / 1 / 2), а `0x5026FC` читает байт `+2` = 1 как
    бит 0 и = 2 как бит 1.
  - **CONFIRMED** исходником ВЛ10к (`vl10k_main.cpp`, `Init`): 0 (случай по
    умолчанию) оставляет его холодным (ручной тормоз затянут, главный
    резервуар 1,2, токоприёмники опущены, выключатель разомкнут); 1
    поднимает токоприёмники, замыкает выключатель, заряжает воздух (главный
    резервуар 7,8, магистраль 5,5) и держит его вспомогательным тормозом
    (3,0); 2 и 3 — то же с главным резервуаром 9,2 и отпущенным
    вспомогательным тормозом. С `0x100` он также ставит переключатели
    кабины игрока (132, 116, 117; 38 для 2 / 3).
  - Холодные локомотивы (`Cold ( )` в `.con`, `Cold` в `WagonGroup`
    задания; бит 3 `LocoFlags`) вообще не получают DLL и считаются
    вагонами.
  - `0x100` — игрок в этом локомотиве, `0x200` — поезд типа 4, `0x400` —
    поезд типа 5.
- **После `Init`:** части анимации токоприёмников прыгают в свой конечный
  кадр для каждого поднятого токоприёмника (`PantoRaised`) или в кадр 0;
  `Init` вспомогательных (`0x56EE38`); DLL, экспортирующая `SpeedLimit`,
  ставит флаг поезда `0x400000` (поезд тогда вычисляет для неё
  ограничения скорости); `PTValue` = магистраль − 0,2.
- Неудача освобождает дескриптор и вспомогательные библиотеки.

## 3. Ведущие и ведомые

### Группировка (`0x468C74`, вход)

**CONFIRMED.**
- Группа — последовательность вагонов, соединённых кабелями: биты `Flags`
  `0x10000` / `0x20000` (байт 3, `WagonData::Cables`, передний / задний)
  прослеживаются в обе стороны от локомотива игрока.
- Для каждого локомотива группы, кроме локомотива игрока, если он не
  холодный и не под ИИ: спрашивается `CanWorkWith(slave, series)`
  **ведущего** (`series` — строка `LocomotiveSeries` ведомого, ENG
  `+386`); отказ оставляет его вне группы. ВЛ10к отвечает «да» только для
  `"vl10k"`.
- Принятый ведомый: его кабина загружается (`LocoFlags |= 0x10`), `|= 4`
  (в сплотке игрока); когда локомотив игрока ведущий (`LocoFlags & 1`),
  бит ведущего у ведомого снимается, а его собственный список ведомых
  освобождается; его DLL привязывается и **инициализируется без игрока**
  (`State` без `0x100`); он сохраняется в массиве `Slaves` ведущего
  (`NumSlaves`).
- **Кто ведущий — решение DLL:** `ChangeLoco` ставит бит 1 `LocoFlags`
  (ВЛ10к: всегда, когда прежнего ведущего не было; иначе только если
  реверсор прежнего в нейтрали и это позволяют несколько переключателей).
- **`ChangeLoco(loco, Prev, State)`**: `Prev` — локомотив, у которого этот
  был среди ведомых (прежний ведущий), `State` — поле `Flags` вагона.
  Обработчики вспомогательных идут до и после (событие 7).
- При первом входе в поезд давления магистрали, цилиндра, запасного
  резервуара и `PTValue` каждого вагона копируются с локомотива (флаг
  поезда 4).

### Перегруппировка (`0x4F995C`)

**CONFIRMED.** Вызывается после сцепки (`0x469ED8`), расцепки
(`0x469858`), действий меню (`0x463F84`) и сетевых событий (`0x57B8E4`):
группы перестраиваются тем же способом. Новые ведомые привязываются и
инициализируются; локомотив, который был ведомым и больше не в группе
своего ведущего, получает **`LostMaster(lost, master, State)`** с
обработчиками вспомогательных до и после (событие 8).

**CONFIRMED (2026-11-04) подробнее:**
- Для поезда из одного вагона или без флага 4 (игрок в нём ещё не был)
  ничего не происходит.
- Группы — это цепочки вагонов, соединённых управляющими кабелями (байт
  `+30` Wagon, биты 1 / 2). Группа считает свои локомотивы, которые не
  холодные и не ИИ.
- Каждый ведущий в группе (`LocoFlags & 0x21` = `0x21`: ведущий, DLL
  привязана) получает новый список ведомых:
  - его `CanWorkWith` (`+452`) спрашивают о каждом другом локомотиве
    группы, ведомом уже или нет;
  - у принятого загружается кабина, если её нет (не удалось — он
    пропускается); его DLL привязывается и инициализируется, только если
    ещё не привязана (`0x5026FC`, пропускается при `LocoFlags & 0x20`);
    создаётся звук его машины (`0x5030B4`);
  - ведомый из старого списка, которого нет в новом, получает
    `LostMaster`.
- Значит, DLL привязывается и инициализируется один раз на вагон. Вагон,
  отцепленный и прицепленный снова, сохраняет состояние своей DLL;
  `Init` и `ChangeLoco` для него больше никто не вызывает.
- **Сцепка** (`0x469ED8`): поезд, который забирает другой, перегруппируется,
  если у него есть флаг 4. Каждый вагон, взятый в поезд игрока из поезда
  без флага 4, получает свои звуки заново (`0x500EDC`, группа 7 для
  локомотивов с битом 7 `LocoFlags`, иначе 5).
- **Расцепка** (`0x469858`): отцепленная часть — новый поезд, который
  копирует флаги поезда (`0x4EEC50`), флаг 4 тоже, и обе части
  перегруппируются.
  - В одиночной игре отцепленная часть — LOOSE (вид 3). Если у части
    игрока нет ведущего, а у отцепленной есть, они меняются местами
    (`0x469744`).
  - Вызов `Run` идёт для каждого поезда с флагом 4, кроме видов 2 и 4
    (ниже), поэтому **DLL отцепленного локомотива продолжает работать**
    без игрока в нём.
- **ВЛ10к (исходник):** `LostMaster` стирает в `var[4]` ведомого команды
  ведущего (БВ, вентиляторы, позиции: `&= ~14016`, `~(2 << 16)`). Секция,
  отцепленная и прицепленная снова, опять ведомая и повторяет позицию
  контроллера, но тянет, только когда машинист снова подаст эти команды.

**openRTS** (`dllhost::Command::reconsist`, `LegacyConsist::reconsist`):
- после сцепки или расцепки хост получает новый список вагонов. Зеркала
  оставшихся вагонов переходят с ними, новые вагоны получают новые
  зеркала, и группы строятся заново, как выше (новые ведомые привязываются
  и инициализируются с состоянием поезда на этот момент, потерянные
  получают `LostMaster`);
- хост ведёт несколько поездов (2026-11-05): сначала поезд игрока, затем
  части, отцепленные от него, у каждого свой объект поезда, свой список
  вагонов и свои группы. Их DLL вызываются каждый шаг, как в RTS (State без
  `0x100`); проход сигналов (`SpeedLimit`, `ALSN`, `Cabin::Signal`) и
  список элементов пути — только у поезда игрока (в RTS типы 1, 2, 4;
  отцепленная часть — LOOSE). Отцепленная часть, пока стоит, движется по
  выходам своих DLL; прицепленная снова, она опять один поезд с поездом
  игрока. Игрок может пересесть в отцепленную часть («вести» в окне
  «Поезд»): хост делает её первым поездом и входит в её локомотив без
  второго `Init`. Вагон, не попавший ни в один поезд (его состав удалён),
  откладывается вместе с зеркалом, пока не вернётся;
- звуки отцепленной части (её наружные `.sms` и звуки её библиотек)
  получают триггеры и переменные её DLL; звуки библиотек следуют правилам
  камер RTS для поезда, который не поезд игрока (`sound.md`, «Звуки
  библиотек»). При пересадке игрок входит в её первый локомотив с DLL и
  кабиной управления (`CabView`; `Cabin` моторного вагона ЭД9М — его
  салон);
- игра следит за вагонами по собственному ключу, потому что UiD из `.con`
  повторяются между составами;
- вьювер сохраняет кабину, машиниста (сидящий остаётся сидеть) и
  нативный плагин;
- тесты: `openrts.dllhost` (поддельная DLL: `Run` отцепленного
  локомотива видит входы своего поезда),
  `openrts.content.dll_vl10k_couple` (секция Б ВЛ10к отцеплена в свой поезд и
  прицеплена снова).

### Ведущие пишут в ведомых

**CONFIRMED (исходник ВЛ10к).** Ведущий меняет своих ведомых напрямую:
стек переменных ведомого (биты флагов `SlaveLoco(i)->Eng()->var[4]`,
`var[5]`, `var[12]`) и `Engine::UR`. В RTS ничто их не копирует: DLL
ведомого читает их при своём следующем `Run`. Поэтому и нужно одно
адресное пространство на состав (`train-dll.md`).

## 4. Каждый кадр

### Время

**CONFIRMED.** Симуляция `0x424488` выполняется раз на нарисованный кадр с
`dt` = разность `timeGetTime()`, прижатая к 8–1000 мс
(`runtime-overview.md`). `Run` получает этот `dt` в секундах
(`*a2 × 0.001`). ВЛ10к интегрирует с ним (`x += rate * time`). Внешнего
фиксированного шага нет: подшаги по 0,05 с делает только решатель сцепок.

### До DLL

**CONFIRMED (`0x424488`).** Для каждого вагона каждого поезда с флагом 4,
кроме видов 2 и 4 (поездов, чьи DLL работают):
- `Force` = 0;
- `TrainPipeRate` := `TrainPipePressure` (поле служит заодно «давлением в
  начале кадра» для Δp магистрали);
- `EPTvalue` = −1 (нет требования ЭПТ);
- электрические локомотивы: `LineVoltage`, `LineFreq`, `LineCurrent` = 0.

### Вызовы

**CONFIRMED.** Каждый вагон с `IsLocomotive` и `Engine` получает рассылку
`Run` (`0x5031D8`), **в порядке вагонов в поезде** — не сначала ведущие.
Поэтому ведомый впереди своего ведущего видит то, что ведущий записал в
прошлом кадре.

`0x5031D8` для одного локомотива:
1. `State` = `0x100`, если игрок в нём (`Flags & 4`), `| 0x200` / `|
   0x400` для поездов типов 4 / 5. Младший байт 0.
2. Электрический: `PantoRaised` из частей анимации токоприёмников, когда
   они есть у модели, иначе из `ElectricEngine::Panto`. Если `LineVoltage`
   равен 0, оно ищется (`0x503CE4`, контактная сеть).
3. Развёрнутый вагон (`Flags & 1`) получает `Velocity` и `Acceleration` с
   обратным знаком: DLL видит их в собственном направлении локомотива.
4. Обработчики `Run` вспомогательных, стоящие до основного вызова.
5. **`Run(eng, loco, State, dt, AirTemperature)`** — напрямую с `locoA` и
   вагоном или через адаптеры для старых версий DLL.
6. Отложенные обновления адаптеров (раздел 7).
7. Обработчики вспомогательных, стоящие после.
8. Знак `Velocity` / `Acceleration` возвращается обратно.
9. Электрический: части токоприёмников ставятся из
   `ElectricEngine::Panto` (номер токоприёмника части — в байте 1 её
   `+4`). Тепловоз: `FuelAmount -= FuelConsuming · dt`.
10. Оба: цилиндр вспомогательного тормоза движется к
    `IndependentBrakeValue` с темпами отпуска / торможения типа вагона
    (`+324` / `+328`); бит 2 `EngineFlags` его отпускает; триггеры SMS
    14 / 54, когда он начинает или заканчивает, если автотормоз не
    приведён в действие. `MainResPressure += MainResRate · dt`,
    `AuxiliaryPressure += AuxilaryRate · dt` (оба держатся ≥ 0).
11. У кабины не на экране переключатели шагаются здесь (`0x526CB0`), что
    может вызвать `Switched` (раздел 6).

### Чтение выходов

**CONFIRMED (`0x424488`, сразу после рассылки):**
- **Песок** (`Engine::Sanding`): `LocoFlags |= 0x100`, сцепление × множитель
  песка из ENG; `SandLeft` отсчитывается вниз; после того как подача песка
  прекращается, действие длится на протяжении пути длиной в локомотив
  (`LastSanding`).
- **Боксование:** сцепление = ENG `+204` × песок × множитель боксования
  (если боксовал в прошлом кадре) × погода. Без данных по секциям
  `|Force| > mass · 10 · adhesion` ставит `Wheelslip` = 15 и **`Force` =
  0**. С `EngineForce[]` по секциям каждая секция проверяется по своим
  осям; сила боксующей секции заменяется на
  `0.1 + (GetTickCount() % 10) / 30` от себя (10–40 %), и её колёсные пары
  проворачиваются.
- **Сила вагона:** `Force` = `Engine::Force` (знак меняется у развёрнутого
  вагона).
- **Тормоза:** бит 1 `BrakeSystemsEngaged` → `TrainPipeRate` ведёт
  магистраль; бит 2 → `EPTvalue` распространяется по линии ЭПТ в обе
  стороны до вагона без ЭПТ или разъединённого кабеля ЭПТ; бит 3 →
  `ChargingRate` ведёт вторую магистраль. `HandbrakeValue` =
  `HandbrakePercent` / 100 (отрицательное прижимается к 0).
- **`GlobalMsg`:** до 16 пар `{action, id}`, применяемых по всему поезду
  (огни, двери, замены текстур, сообщения на экране; `GM_*` в `ts.h`).
  `ShowMessage` кладёт сырой `wchar_t*` в два из short.
- `Engine::BrakeForce`, `Power`, `DynamicBrakePercent` и остальное,
  используемое физикой, читаются там, где они нужны физике (перенесено в
  `simulation/train.cpp`, `train.md`).

## 5. Сигналы: `SpeedLimit` и `ALSN`

**CONFIRMED (`0x508520`, проход сигналов на каждый поезд, каждый кадр для
поездов типов 1, 2 и 4).** Для каждого локомотива с привязанной DLL
(`LocoFlags & 0x20`):
- **`SpeedLimit(loco, Route, Signal, Event)`**: три `SpeedLimitDescr
  {Limit, NextLimit, Distance}`, передаваемые по значению (м/с, м). Часть
  равна −1, когда флаги поезда говорят, что она неизвестна. Затем идут
  обработчики `SpeedLimit` вспомогательных (`0x56F068`).
- **`ALSN(loco, A, nA, B, nB, C, nC, limit, x, y, reversed)`**, только для
  локомотива, у кабины которого есть огни сигнализации со скриптом
  (`Cabin::SignalScripted`): три массива `SignalsInfo` (32 байта:
  расстояние, четыре показания, флаги, ограничение скорости,
  `RTSSignalData*`) со своими числами, построенные из объектов сигналов,
  собранных проходом (с адаптацией кодом 23 для старых DLL); `limit` —
  наименьшее из ограничений поезда; два целых поля поезда; и `reversed` —
  локомотив стоит против направления поезда. Затем идут обработчики `ALSN`
  вспомогательных (`0x56EF60`).
  - UNKNOWN: какие сигналы попадают в каждый из трёх массивов точно
    (проход головы, проход хвоста, оба) и смысл двух целых.
- **CONFIRMED** `Cabin::Signal` (`SignalsInfo` в Cabin `+108`), заполняемый
  тем же проходом для поезда игрока: кабина ведущего вагона (вагон 0 или
  последний вагон, когда поезд идёт в другую сторону) получает следующий
  сигнал — расстояние (`+108`), показание (`+112`, `+160` поезда; 8, когда
  он BLOCK_OBSTRUCTED), ограничение скорости (`+132`), `RTSSignalData*`
  (`+136`); кабина на другом конце получает показание 8 на 0 м. DLL его
  читают (ЭПК и КЛУБ ВЛ10к: `cab->Signal.Aspect[0]`, `Distance`,
  `SpeedLimit`).
- **CONFIRMED** огни локомотивной сигнализации
  (`LocomotiveSignalization`, обновление кабины `0x525DB0`): показываемое
  показание — `Cabin::Signal.Aspect[0]` (за пределами числа показаний — 0);
  `ALSNOn` локомотива (`Engine +106`, int16) 0 гасит все огни, -1 зажигает
  все, другое отрицательное значение показывает показание в своих младших
  12 битах (собственный выбор DLL), положительное показывает показание
  сигнала. Огонь виден (бит 0 флага узла сброшен), когда в маске показания
  есть его бит. Загрузчик (`0x523F94`): `SignalAspects ( n Aspect ( k l1
  .. lk ) .. )`, сначала число, битовая маска на показание из
  ceil(огни / 32) слов (Cabin `+64`); номера за пределами числа огней
  (ВЛ10к перечисляет 10..15 для другого конца) никогда не видны.

## 6. Переключатели: `CanSwitch` и `Switched`

**CONFIRMED.** У каждого `ActSwitch` есть `State` и `SetState`; кабина
шагает `State` к `SetState` за `AnimTime`; ввод игрока и DLL пишут только
`SetState`.
- **`CanSwitch(loco, eng, SwitchID, SetState)`** (`0x528540`), когда игрок
  двигает переключатель (ввод `0x437AA4`, `0x437E64`, `0x43823C`) или это
  делает собеседник по сети (`0x4C9120`). Обработчики вспомогательных,
  стоящие до основного вызова, могут запретить, затем основная DLL, затем
  обработчики после. ВЛ10к использует его, чтобы отказывать в небезопасных
  действиях и посылать звук щелчка.
- **`Switched(loco, eng, SwitchID, PrevState)`** (`0x5288CC`), когда
  переключатель доходит до нового положения: обновление кабины
  (`0x526CB0`, `0x52586C`, `0x525D1C`, `0x525DB0`) копирует `SetState` в
  `State` и вызывает его; также из ввода и сети. Обработчики
  вспомогательных до и после (событие 4). Поэтому `Switched` — конец
  анимации переключателя, а не щелчок.

## 7. Функции хоста и адаптеры

**CONFIRMED.**
- **`_RTSGetInteger(loco, code, index)`** (`0x43929C`): 1 мировое время; 2
  число вагонов (относительно `index`); 3 ночь; 4 число единиц; 6
  направление поезда относительно локомотива (−1 / 1); 7 запись на ленту
  (1 идёт запись, 3 записывается этот локомотив). Код 5 (`RTS_TRIGGERID`)
  идёт через `_RTSGetNamedInteger`; остальные дают 0.
- **`_RTSGetLocoObject(dll, loco, code, index, sub)`** (`0x536650`):
  3 / 21 сам вагон; 4 дверь (`index`); 7 кабина; 12 `Engine`; 13 выхлоп
  (тепловоз); 14 свободная анимация; 16 огонь (`LightObj`, 164 байта); 17
  звук (0 внешний SMS, 1 SMS кабины); 19 параметр ENG (12-байтовый
  `EngineParam`); 20 ведомый `index`. Всё остальное или номер вне
  диапазона: null.
- **Адаптеры (версии DLL 101–103):** функции поиска выдают теневые объекты
  в старых раскладках (`0x537718`), а после каждого вызова в DLL RTS
  выполняет отложенные обновления (`0x53782C` на вагоне, `0x538548` на
  кабине и локомотиве), которые копируют тени обратно. Нынешние DLL (104 с
  соответствием адаптерам 39) получают настоящие объекты. Подробности — в
  разделе 10.
- **Рассыльщик вспомогательных** (`0x56EADC`): стек хранит параллельные
  массивы библиотеки, события и порядка. Записи с отрицательным порядком
  `AuxCall` выполняются до основного вызова, остальные — после; бит 1
  `LibFlags` сообщает библиотеке, когда именно. События: 1
  `Run(lib, loco, State, dt, AirTemperature)`, 2 `ALSN`, 3 `SpeedLimit`, 4
  `Switched(loco, lib, id, prev)`, 5 `CanSwitch(loco, lib, id, set)`, 7
  `ChangeLoco(lib, prev, State)`, 8 `LostMaster(lib, master, State)`.
  Ключевые слова `AuxCall` в `.eng` в порядке таблицы RTS — `run`, `alsn`,
  `speedlimit`, `switched`, `canswitch` (коды 1–5); для 7 / 8 ключевого
  слова нет (PROBABLE: добавляются для библиотек, экспортирующих эти
  функции). `Init(lib, loco, State, 0, AirTemperature)` вызывается для
  каждой библиотеки, которая его экспортирует, без `AuxCall` (`0x56EE38`).
  Пути модулей ищутся как заданы, затем в `GLOBAL\LIB\` (основные DLL:
  `TRAINS\TRAINSET\`, затем `GLOBAL\LIB\`, затем как заданы; `0x56D9C8`).
- **`_RTSGetCabObject(dll, cab, code, index, sub)`** (`0x536B14`): `index`
  — позиция в массиве кабины, то есть `ID` из `.sd`: 1 переключатель
  (104 байта), 2 дисплей (108), 4 дверь (120), 5 область (68), 6 окно (100),
  7 кабина, 8 сцена крупного плана (140), 9 её подобъект (`index` сцена,
  `sub` объект или `sub` = −1 — искать по ID во всех сценах), 10 / 11 экран
  дисплея и его подобъекты (по позиции; docs/reverse/cab-screens.md), 14
  свободная анимация (48), 15 внутренний свет (136), 18 замена текстуры
  (24), 24 кресло (108), 25 сиденье (100). Варианты `ByName` сравнивают
  `lstrcmpiW` с именем объекта (`+8` у активаторов).
- **`_RTSGetNamedInteger(sms, 5, name)`** ищет имя среди именованных
  триггеров SMS; **`_RTSIsSMSTriggerOn`** отвечает −3 без SMS, −2 без его
  таблицы потоков, −4 для неизвестного триггера (`0x439548`).
- **`_RTSSetIntegerG`** (`0x43939C`): код 6 ставит направление поезда,
  только для поезда без вагонов (возвращает 2, если оно изменилось, иначе
  1); код 7 запускает / останавливает магнитофон (повтор RTS) для этого
  локомотива.
- **FPU:** RTS не меняет управляющее слово FPU вокруг вызовов DLL:
  единственные инструкции `fldcw` в исполняемом файле — во вспомогательных
  математических функциях RTL. DLL работают в режиме процесса, PROBABLE —
  умолчание RTL Borland (`0x1332`: точность 64 бита, недействительная
  операция / деление на ноль / переполнение не замаскированы). Во время
  работы не проверялось.

## 8. Почему так устроено

- **Одна объектная модель, правка на месте.** RTS 1.x вырос из данных в
  стиле MSTS: интерфейс DLL открыл собственные структуры движка вместо
  копирования значений, что дёшево и позволяет DLL управлять чем угодно
  (кабина, огни, двери, звуки) без новых вызовов API. Цена —
  фиксированная раскладка, отсюда проверки размеров `DLLVersion` и слой
  адаптеров для старых раскладок.
- **Ведущие и ведомые** моделируют систему многих единиц: DLL ведущего
  решает (`ChangeLoco`, `CanWorkWith`) и ведёт ведомых через их стеки; RTS
  только строит группы по кабелям и хранит списки.
- **Вспомогательные библиотеки** позволяют контенту добавлять системы
  (тормоза, устройства безопасности, радио) к любому локомотиву или вагону,
  не трогая его основную DLL, в порядке вокруг неё.
- **`Switched` в конце анимации** держит видимое состояние кабины и логику
  в ногу: выключатель замыкается, когда рукоятка туда доходит.
- **Скорость, развёрнутая вокруг вызова**: каждая DLL может считать своё
  направление вперёд, как бы вагон ни стоял в поезде.

## 9. Что берёт из этого хост openRTS

- Зеркальные объекты в раскладке `ts.h` для каждого вагона состава, одно
  адресное пространство, постоянные адреса, указатели между ними, как их
  ставит RTS (`Slaves`, `cab`, `locoA`, числа, выводимые из `wag`).
- Та же последовательность вызовов: привязка и `Init` при входе (с битами
  `State` выше), группировка по кабелям с `CanWorkWith`, `ChangeLoco` /
  `LostMaster` при перегруппировке, на каждом шаге сбросы до вызова, `Run`
  в порядке вагонов с разворотом, порядок вспомогательных, затем чтение
  выходов, как выше; `SpeedLimit` / `ALSN` из прохода сигналов;
  `CanSwitch` при вводе, `Switched`, когда переключатель доходит.
- **Шаг (выбор openRTS):** openRTS выполняет всё с фиксированным шагом
  0,05 с (`train.md`), поэтому `Run` получает `dt` = 0,05 с частотой 20 Гц
  вместо раза на кадр. DLL интегрируют по `dt`, поэтому их поведение
  должно совпадать; дисплеи обновляются с частотой 20 Гц.
- **FPU (выбор openRTS):** хост ставит точность 64 бита, как Borland, но
  держит исключения FP замаскированными, поэтому ошибка DLL даёт inf / NaN,
  а не убивает хост.

## 10. Адаптеры для старых DLL (`0x5364D0`, `0x537DC8`, `0x537E10`)

**CONFIRMED.** При загрузке RTS сначала вызывает `InitRTSLibrary`, затем
`DLLVersion`:
- TS_VERSION ниже 101: отклоняется. `DLLVersion(20) != 44` / `(21) != 16`
  ставят два флага модуля (раскладки элементов пути). `DLLVersion(19)` —
  стек.
- Соответствие адаптерам ниже 39: у DLL должны быть ровно сегодняшние
  размеры (переключатель 104, дисплей 108, экран 76, локомотив 480, движок
  208, огонь 164, внутренний свет 136, подобъект крупного плана 204), иначе
  она отклоняется.
- Соответствие 39 и TS_VERSION 104: работает напрямую. 101–103: через
  адаптеры, выбираемые по таблице вариантов для каждой версии по коду
  объекта:

  | Версия | Локомотив (3) / ведомый (20) | Кабина (7) | SignalsInfo (23) |
  |---|---|---|---|
  | 101 | 1 | 1 | 1 |
  | 102 | 2 | 1 | 1 |
  | 103 | — | 1 | 1 |

- **Адаптер** копирует весь объект в тень (`0x214` байт для локомотива,
  `0x160` для кабины), затем удаляет поля, которых нет в старой раскладке,
  сдвигая остаток вниз (`0x537CD0`): вариант локомотива ≤ 1 удаляет `+476`
  (`AuxLibs`), ≤ 2 удаляет `+384` (`Wagon::WagonObjs`); вариант кабины 1
  удаляет `+136` (`Signal.SignalInfo`, `RTSSignalData*`, который
  SignalsInfo получил в 104). Массивы SignalsInfo для `ALSN` становятся
  элементами по 28 байт. После вызова (`0x53782C`) промежутки вставляются
  обратно, удалённые поля восстанавливаются из настоящего объекта, а тень
  копируется обратно.
- Тень обновляется, когда её берут чистой; взятая снова до копирования
  обратно, она выдаётся как есть (запись ведущего в тень ведомого доживает,
  пока собственный вызов ведомого не скопирует её обратно).
- Не адаптируются: движок (код 12), огни, вагоны (21): их старые и новые
  раскладки совпадают во всех полях, которыми пользуются DLL, или DLL
  получает лишь указатели на элементы.

Что это значит для контента (`openrts-dllhost32 --probe` по TRAINSET): 41
из 54 установленных DLL — TS_VERSION 104, 12 — 102 с соответствием 39
(адаптируются), одна (`VL80k000.dll`, запасная копия, которую не называет
ни один `.eng`) — 102 без соответствия, и RTS её тоже отклоняет.

## 11. Ввод переключателей кабины (`0x437AA4`, `0x437E64`)

**CONFIRMED.**
- **Щелчок или клавиша** сдвигает `SetState` на одно положение, отражаясь
  на концах (бит «идёт вниз» `0x10` в `Flags` помнит направление); `LOOP`
  вместо этого заворачивает; `DISABLED` пропускает; `CHECKDISTANCEONPRESS`
  требует, чтобы машинист был в пределах `Radius`. Шаг вниз / вверх (две
  клавиши, `AssignKey ( "up" "down" )`) идёт только в одну сторону.
- **Порядок `CanSwitch`:** RTS сначала пишет новое состояние в `SetState`
  (`+48`), затем вызывает `CanSwitch`, а отказ восстанавливает старое
  состояние. Всё, что DLL записала в `SetState` во время вызова,
  остаётся.
  - ЧС7 (`chs7.dll`, переключатель 0 `C_MAIN`) на это опирается:
    - шаг из 0 (состояние 12) в 11 отправляет контроллер на +1 (1);
    - шаг в 2 отправляет его обратно в 0 (12);
    - в его сектор ослабления поля (5..10) входят через переключатель 200,
      который сдвигает `FixedState` и `SetState` на 10 и ставит бит
      `0x1000` флагов локомотива.
  - Раньше openRTS ставил `SetState` после разрешённого вызова, затирая
    выбор DLL. Контроллер тогда оставался на 11, и следующий шаг уходил в
    сектор ослабления поля.
- **Переключатели `KEY`** имеют состояние «ключ вынут» 0 ниже своих
  положений: первое нажатие вставляет ключ в `InitialState + 1`; Shift при
  вставленном ключе его вынимает (CONFIRMED `0x437AA4`, `+56`; ранняя
  заметка здесь говорила `FixedState`); положения — 1..`States`. Ключ
  `CONTROLLERX` / `CONTROLLERY` берётся нажатием и двигается
  перетаскиванием; с зажатым Shift перетаскивание его вынимает (реверсор
  ЭД9М `C_REV`, `States ( 3 1 )`: вставляется и вынимается в нейтрали,
  состояние 2). Поэтому у переключателя `KEY` со `States ( 2 0 )`
  состояния 0, 1, 2 (ВЛ10к проверяет `Switch(38) >= 2` для «вперёд»).
- **CONFIRMED** загрузчик кабины (`0x51CD88`) создаёт столько
  переключателей, сколько объявляет `Switches ( n` (id, равный n или
  больше, — ошибка, 0x19), так же и дисплеи: id меньше n без блока —
  переключатель в состоянии 0. DLL на это опираются: `Brakes.dll` MaDaDev
  читает переключатель через `RTSGetCabObject(cab, 1, id)` и считает «нет»

    Шторки ЭД9М: 30 кадров в секунду × 1 с × 1 = 30 кадров, ключи 0..5:
    0,1 кадра на пиксель — шторку тянут на 290 пикс. сверху вниз. Это
    пиксели окна RTS (установленные настройки: высота 1080, FOV 65); openRTS
    переводит в них свой сдвиг курсора по углу обзора
    (`rts_pixels_per_pixel`), поэтому орган поспевает за курсором, как в
    RTS, при любом разрешении и поле зрения (у вьювера около 49 градусов).
  - `PRECISE` (`0x437E64`): кадр узла сдвигается на dx * PrecX + dy *
    PrecY (пиксели курсора; y растёт вниз), прижимается к анимации
    (заворачивается с `LOOP`); будущее State = кадр / ((кадры − 1) /
    (состояния − 1)), на одно дальше в направлении движения, спрашивается у
    DLL (`CanSwitch`, отказ: ничего не двигается); затем SetState =
    состояние кадра, +84 = кадр в состояниях (дробный), а переход через
    целое состояние ставит State и вызывает `Switched`. После отпускания

    высоте). Без `SwitchPrecision` перетаскивание `PRECISE` — шаг щелчка.

    (вправо / вверх: +1, влево / вниз: −1), и удержание заканчивается:
    одно положение на нажатие.
  - Контроллер с `SwitchPrecision` (`0x527140`): как `PRECISE`, узел
    ведётся рукой; после отпускания (`0x527190`) SetState = ближайшее целое
    состояние, и узел анимируется туда.
  - Переключатели `KEY` считают с 1, Shift в состоянии ключа вынимает
    ключ.
  - ЭД9М (`cab9.sd`): шторки `STOR_1` / `STOR_2` — `PRECISE CONTROLLERY`,
    `SwitchPrecision ( 0.0 0.1 )`; контроллер машиниста `C_MAIN` и реверсор
    — `CONTROLLERY`, кран 395 и прожектор `K_1` — `CONTROLLERX`. В
    установленных поездах: 1768 `PRECISE`, 2345 `CONTROLLERX`, 1183
    `CONTROLLERY`, 667 `SwitchPrecision`.
  - openRTS: `LegacyCab::grab` / `drag` / `drag_end` (вьювер переводит
    сдвиг курсора в состояния через `SwitchPrecision` и кадры узла) и
    команда хоста `drag_switch` (протокол 3), которая держит кадр
    перетаскиваемого переключателя, пока его SetState не изменится иначе;
    её ответ несёт новое состояние переключателя, показываемое сразу (RTS
    двигает узел в обработчике мыши; ожидание следующего шага 50 мс
    заставляло шторку отставать от курсора). Нажатие на контроллер больше
    не щёлкает его (как в RTS: только движение). Отступление: переключатель
    `PRECISE` без `SwitchPrecision` делает один шаг за нажатие, как
    контроллер (RTS щёлкает его каждый кадр, пока кнопка удерживается).
    Переходы вверх вызывают `Switched` сразу (проверка RTS в `0x437E64`
    видит только переходы вниз; остальные догоняет его обновление кабины).
- **`Switched` вызывается** из обновления кабины (`0x52586C`), когда `State`
  отличается от `SetState` и узел анимации переключателя туда дошёл (сразу,
  если модели нет); `State` := `SetState`, затем `Switched(prev)`. DLL,
  ставящая оба (`SetSwitch(.., SetBoth)`), двигает переключатель без
  `Switched`.
- Ключевые слова `.sd` и биты `Flags` в порядке таблицы RTS: `controllerx`
  1, `key` 2, `nonfixed` 4, `controllery` 0x20, `precise` 0x40,
  `overscale` 0x80, `loop` 0x10000, `disabled` 0x20000,
  `checkdistanceonpress` / `displaysequence` 0x40000, `stretch_uv` 0x80000
  (PROBABLE для битов после `overscale`: сопоставлены с порядком
  комментариев `ts.h`).

## 12. Подробности контента, на которые опираются DLL

- **Файлы `.repaint`** (RTS): `Cabin` или модель вагона могут называть
  `x.repaint` = `Repaint ( Shape ( "a.s" ) ShapeDescription ( "a.sd" )
  TextureReplace ( "old.ace" "new.ace" ) ... )`. Без его разрешения кабины
  и внешних деталей вагона нет, и DLL, которые к ним обращаются, падают
  (`mdd_EP1`, `mdd_2ES4k`, `mdd_EP2D` в пробе).
- **Свободные анимации и двери** `.sd` модели вагона
  (`ESD_Exterior_Details`): DLL находят их по имени (`FindAnim("KONTR")` в
  дрезине) или номеру (`Door(4)` каждого вагона в ЭП2Д) и используют
  результат без проверки.

## 14. Напряжение в линии (`0x503CE4`, `0x5B53A8`)

Вызывается из рассылки `Run` (`0x5031D8`), когда `LineVoltage` равен 0,
один раз на поезд (пропускается, когда выставлен бит 0 байта поезда `+5`).

- **CONFIRMED** Для каждого электрического локомотива поезда (вагон `+12`
  = 1):
  - токоприёмники опущены (байт вагона `+13`, битовая маска поднятых
    токоприёмников, равен 0), или флаг пережога локомотива (бит 9
    `LocoFlags`, `+389` & 2), или флаг вагона `+32` & 0x20: напряжения от
    него нет; его ток всё равно учитывается; пережжённый остывает 60 с,
    затем флаг снимается;
  - иначе напряжение и частота на его токоприёмниках:
    - с загруженным `.electrodb` маршрута (`dword_61D77C`): `0x5B53A8`
      читает секцию пути под вагоном (путешественник `+176`, смещение
      `+192`): куски `SectionElectrification` (`Electricity ( n  section
      start flags … )`, электросекция 0 = обесточена) и куски `Catenary`,
      подстанцию электросекции (`.electrotype`: `ElectricSupplyType`
      `Voltage`, `Frequency`, `VoltageDrop`; подстанция `Power`,
      `PowerDecline`);
    - иначе глобальная замена (`dword_61D774`, напряжение `+12`, частота
      `+16`; PROBABLE — от сервера сетевой игры);
    - иначе, когда маршрут электрифицирован (**PROBABLE**: `.trk`
      `Electrified ( 1 )`): середина **первого** диапазона
      `WorksOnLineVoltages` локомотива, (Min + Max) / 2, и его частота —
      любой локомотив получает напряжение, на котором работает;
    - иначе 0: контактной сети нет.
  - `SetTrainElectricity` задания (поезд задания `+40` напряжение, `+44`
    частота; отрицательное = оставить) заменяет его.
- **CONFIRMED** Поезд берёт наибольшее напряжение своих локомотивов с его
  частотой; каждый электрический локомотив получает это `LineVoltage` /
  `LineFreq` (`+504` / `+508`), а `LineCurrent` (`+512`) = мощность поезда
  (сумма `+212` локомотивов) / напряжение, поделённая на число поднятых
  токоприёмников. Ток нагружает электросекции (`0x5B6030`, падение
  напряжения).
- **CONFIRMED** При превышении предела тока (`MaxLineCurrent`, ENG `+596`)
  или времени пережога (`MaxLineCurrentCatenaryBurnTime`, ENG `+608`)
  токоприёмник пережигается (`LocoFlags |= 0x200`, звук / сообщение).
- **CONFIRMED** `0x5B53A8` подробнее: сначала провод (куски `Catenary`
  узла: тип, начало, **длина**, неизвестное значение, флаги; единственный
  кусок узла с началом <= 0 и длиной < 0 — весь узел, любому другому нужна
  длина > 0 — поэтому «начало 64.9, длина -1», которое есть у трёх
  установленных узлов, — не провод); затем последний кусок `Electricity`,
  начинающийся в месте вагона или раньше (id электросекции, начало, флаги;
  электросекция 0 = обесточена). Источник электросекции: закэшированный у
  куска, если есть; никакого, когда состояние секции (`+10`) равно -2 /
  -3; единственный источник; `CurrentSource`; иначе каждый источник с
  `Active & 3` и включённой подстанцией (бит 0 `+44` сброшен), наибольшее
  напряжение, а при двух питающих — меньшая частота. У одного источника
  должно быть `Active & 2` и (`& 1` или быть закэшированным). Напряжение
  источника: `Voltage` подстанции × `FeederQ` / 100 − `VoltageDrop` типа
  питания (В/км) × расстояние в км до подстанции (`UseSubstationPos`, флаг
  `0x200`) или до `FeederPos` (флаг `0x100`), не меньше 0.
- **CONFIRMED** `0x491DC8` (электросекция): `FeederQ` по умолчанию 100;
  `CurrentSource ( i )` (допустимый номер) ставит бит 0 `Active` только у
  источника i и бит 1 у каждого источника; без него состояние секции -1.
- **CONFIRMED** `0x490A14`: `Section ( n )` в `SectionElectrification` —
  узел пути TDB n (номер n − 1, только векторные узлы; установленные
  маршруты с этим согласны, `openrts.content.electrification`).
- **CONFIRMED** глобальные переменные `0x503CE4`: `dword_61D77C` — число
  электросекций, `dword_61D774` / `dword_61D714` — число и массив типов
  питания (`.electrotype` без электросекций: `Voltage` / `Frequency`
  первого типа везде). **PROBABLE** `dword_61D7CC` — выполняемое задание: с
  ним секция с несколькими источниками и `CurrentSource` питает от первого
  источника, чьи напряжение и частота подстанции попадают в
  `WorksOnLineVoltages` локомотива (в их порядке), с кэшированием на
  куске.
- openRTS (`simulation::Electrification`): всё выше, кроме кэша (выбор
  делается для каждого локомотива каждый раз); нагрузка, пережог и группы
  высоковольтной шины — в §17; расстояние горизонтальное (высоты
  питающих пунктов в файлах 0); без `.electrotype` и `WorksOnLineVoltages`
  локомотив получает 3 кВ постоянного тока (RTS читает там значение,
  которое никогда не ставил); автоматический выбор задания — пункт
  трек-контроля.
- RTS не выбирает для локомотива переменный или постоянный ток: он даёт
  напряжение и частоту провода, а решает DLL (в кабине ВЛ82м два вольтметра
  сети, «Сеть переменный ток» 0–30 кВ и «Сеть постоянный ток» 0–4 кВ). Что
  RTS делает с `WorksOnLineVoltages` для локомотива без DLL, не
  прослежено.
- Контент: Кубань 27,5 кВ 50 Гц; Чернышевск 3 кВ постоянного тока; Павловск
  и Новокузнецк — оба (27,5 кВ переменного, 3,3 / 3,5 кВ постоянного);
  Киевский ход и тестовый маршрут электрифицированы без `.electrodb`;
  Успенск не электрифицирован. Локомотивы двойного питания: ВЛ82м
  (`vl82m.dll`), ЭП20 (только `Brakes.dll`).

## 15. Наружные огни без DLL (`0x4F07D4`, `0x4FFDF8`, `0x4FF9B8`)

- **CONFIRMED** определение огня (72 байта, `+356` типа вагона, число
  `+348`; загрузчик `0x50036C`): `+0` Type, `+1` Headlight, `+2` Control,
  `+3` Service, `+4` Unit, `+5` TimeOfDay, `+6` Weather, `+8` FadeIn, `+12`
  FadeOut, `+16` Cycle, `+40` число States, `+44` States (по 76 байт, `+4`
  Duration).
- **CONFIRMED** `0x4F07D4(train)` ставит бит 8 LightObj («включить») огням
  каждого вагона по их условиям; выполняется по событиям: наступление ночи
  (`0x4F0798` из обновления неба `0x417D74`), сцепка, расцепка, смена типа
  или направления поезда (`0x469858`, `0x469ED8`, `0x4F549C`, `0x4FA374`,
  `0x507634`, `0x50B430`, `0x48A0F8`).
  - Поезд игрока (тип 1): локомотив, у которого `LocoFlags & 0x88` равно 0
    (не холодный, не под ИИ), пропускается: его огни переключает его DLL.
  - Только вагоны с битом 1 `Flags` Wagon («в поле зрения»).
  - Поезд типа 0 (STATIC) или 3 (LOOSE) ничего не зажигает, если этого не
    говорит его служба задания (поезд `+20`: `+96` бит 0x40 сброшен, `+72`
    выставлен).
  - Вагон 0 пробуется с Unit 2 (4, когда поезд идёт развёрнутым, поезд
    `+4` бит 0x80), последний вагон — с 3 (5); один вагон — оба;
    остальные — 1.
- **CONFIRMED** `0x4FFDF8(car, light, unit, train type)`:
  - Control 1: выключен для типов 1 и 4; 2: включён только для них.
  - Service 1: включён для холодного локомотива (`IsLocomotive` и бит 3
    `LocoFlags`) или типов 0 / 3; 2: выключен для холодного локомотива и
    типов 0 / 3.
  - Unit: должен равняться данному месту.
  - TimeOfDay 1: выключен, когда `is_night` и уровень освещённости

    шести каналам, `0x408574`) ниже 0,5; 2: выключен, когда не ночь и
    уровень не меньше 0,5.
  - Weather (`byte_61D62D`: 0 ясно, 1 снег, 2 дождь): 1 ясно, 2 дождь, 3
    снег.
  - Headlight: фаза 1 (день), 2 (уровень ниже 0,5), 3 (ночь), и 1 для
    холодного локомотива; 4 требует 2 или 3, остальные — свою фазу.
- **CONFIRMED** `0x4FF9B8(car, dt)`: включённый огонь разгорается за FadeIn

- openRTS: `simulation/train_lights`, каждый кадр для каждого поезда

## 17. Ток в линии, провод и подстанции (`0x503CE4`, `0x5B6030`)

- **CONFIRMED** `0x503CE4(train, loco, dt)` работает с вагонами между
  `+436` и `+440` локомотива, которые `0x4F9FB4` ставит на
  последовательность вагонов, соединённых высоковольтной шиной (`Flags`
  Wagon 0x40000 спереди, 0x80000 сзади), вокруг каждого не холодного
  локомотива (локомотив без шины — только он сам). Вызывается из рассылки
  `Run`, пока `LineVoltage` равно 0, поэтому один раз на группу и кадр.
- **CONFIRMED** для каждого электрического локомотива группы:
  - со временем пережога (`+608` = `MaxLineCurrent` ×
    `MaxLineCurrentCatenaryBurnTime`, когда оба положительны, иначе 0) и
    не пережжённый: нагрев (`+416`) остывает на (`MLC_A` × |скорость| +
    `MLC_B`) × dt (`MaxLineCurrentVelocityIncrease ( MLC_B MLC_A )`,
    `+600` / `+604`; отрицательные значения обнуляют оба), не ниже 0;
  - токоприёмники опущены, пережжён (`LocoFlags` 0x200) или флаг вагона
    `+32` 0x20: линии от него нет; его мощность (`+484` `+212`,
    `PowerConsuming`) всё равно учитывается; пережжённый отсчитывает 60 с
    в `+416`, затем флаг снимается;
  - иначе его линия (`0x5B53A8`), число поднятых токоприёмников и
    коэффициент пережога провода: из кусков контактной сети типа 1 над ним
    — BurnQ (0, если у какого-то 0, иначе наибольший; −1 без них; 1 без
    куска `.electrodb`).
- **CONFIRMED** затем наибольшее напряжение идёт каждому электрическому
  локомотиву группы с частотой последнего найденного; `LineCurrent` =
  мощность группы / напряжение × поднятые токоприёмники этого локомотива
  / все поднятые. На каждый токоприёмник: без времени пережога выше
  `MaxLineCurrent` он пережигается сразу; со временем нагрев растёт на
  ток / BurnQ × dt (только BurnQ > 0) и пережигает на пределе: нагрев 0,
  `LocoFlags |= 0x200`, сообщение (`off_5F81D0`).
- **CONFIRMED** `0x5B6030(substation, phase, power, dt)`: если подстанция
  не выключена (бит 0 `+44`), её запись фазы (20 байт, `+56`) суммирует
  мощность × dt; через 2000 мс (`dword_5E04E8`) среднее (`+12`) отправляется
  на сервер пакетом `0x4649` (подстанция, фаза, энергия, секунды;
  `0x4CF464`), а в одиночной игре просто сбрасывается. Доля локомотива:
  мощность группы × его токоприёмники / все; два источника (только в
  сетевой игре) делят её по долям электросекции. Сервер (`rts_server.exe`
  `0x4436C8`) пересылает `0x4649` диспетчерам; он читает `PowerDecline`
  (`0x437D44`), но ничто не снижает напряжение по нагрузке.

## 18. Массивы ALSN и переход в другую кабину

- **CONFIRMED** (`0x508520`) проход головы собирает до 16 объектов
  сигналов впереди головы поезда (узлы цепочки по 56 байт), проход хвоста
  — до 16 позади его хвоста; те, что в пределах расстояния проезда
  (скорость × dt × 1,5), считаются проеханными (`v100` в голове, `v101` в
  хвосте). `ALSN(loco, A, nA, B, nB, C, nC, limit, x, y, reversed)`: A —
  непроеханные объекты впереди, B — непроеханные сзади, C — проеханные
  (сначала передние). Каждый `SignalsInfo`: `Distance`; `Aspect[0]` —
  наибольшее состояние его голов NORMAL (флаг 1), `[1]` DISTANCE (2),
  `[2]` SHUNTING (4), `[3]` INFO (8); флаг 0x10 — за препятствием;
  `SpeedLimit` — узла (−1 с битом 3 флага поезда `+6`); `RTSSignalData*` —
  `+124` первой головы. `limit` — наименьшее из ограничений поезда; `x` /
  `y` — ограничение и расстояние следующего знака скорости (поезд `+120` /
  `+116`, float); `reversed` — вагон стоит против направления поезда (`+4`
  бит 0x40). Обработчики вспомогательных получают то же (`0x56EF60`).
- **CONFIRMED** проход через дверь, ведущую в кабину (`-3`, `0x435654`),
  в другой локомотив вызывает `0x436734`, который входит в него как в
  локомотив игрока (`0x468C74`: привязка, `Init`, `ChangeLoco`,
  группировка) и делает его кабину текущей. Цель `-7` — салон.

## 19. Элементы пути, именованные триггеры и данные сигнала (2026-11-04)

### `RTSGetTrackItems` (`0x4805D8`)

- **CONFIRMED** вызов: `(dll, loco, code, distance, items&, count&)`.
  - DLL, у которой размер `TrackItem` не совпадает с RTS, получает об этом
    сообщение один раз; DLL с другим размером `TrackItemsItem` бросает
    «Critical DLL structure mismatch» (флаги модуля из
    `DLLVersion(20 / 21)`, `0x5364D0`).
  - `distance` <= 0 означает 5000 м.
  - У локомотива, обращённого к хвосту поезда (бит 0 `Flags` Wagon), биты
    1 и 2 `code` переставлены, а в том, что он получает, переставлены
    «впереди» и «позади», и `Z` с обратным знаком.
- **CONFIRMED** список — свой у каждого поезда (`+392`, 28 байт):
  - число, записи `TrackItemsItem` по 16 байт и выходная копия;
  - докуда он достаёт впереди и позади, и собраны ли элементы под
    поездом.
- **CONFIRMED** он дособирается, когда запрос заходит дальше (`0x4808DC` →
  `0x480A08`).
  - Обход начинается от путешественника хвоста поезда (`+232`).
  - Вперёд он покрывает длину поезда (`ZOrd` вагона 0 + половина его
    длины, `0x4FB6BC`) плюс `distance`. Назад — `distance`.
  - Каждый найденный элемент (`0x47F214`, любого типа) — запись:
    `Distance` = от головы впереди, отрицательная под поездом; от хвоста
    позади. `Z` = расстояние от хвоста со знаком. `Pos` = 1 впереди, 2
    позади, 4 под поездом.
- **CONFIRMED** проход сигналов на каждый поезд (`0x508520`) очищает
  список каждый кадр, пока поезд движется; на стоянке он сохраняется.
- **CONFIRMED** возвращаются записи с `Pos & code`, в пределах `distance`
  (под поездом — всегда), без сигналов (тип 1: их даёт `ALSN`).
- **CONFIRMED** элементы (`0x482680`): `TrackItem` (44 байта: `Type`,
  `ID`, смещение и флаги `TrItemSData`, `TrItemPData` x z тайл,
  `TrItemRData` x y z тайл, x с обратным знаком) и по типу:
  - 2 знак скорости (64 байта): `Flags`, `Value` (с флагом 2 — ограничение,
    с 1 — ограничение маршрута как есть, иначе км/ч или с 0x100 мили/ч,
    переведённые в м/с), `Off` (поворот знака), `KM` (без флага 2),
    `Number` (флаг 0x10);
  - 3 платформа (76): флаги, другой элемент, имена платформы и станции
    (`wchar_t*`), `PlatformMinWaitingTime`, `PlatformNumPassengersWaiting`;
  - 4 стоянка (76): флаги, другой элемент, её имя;
  - 5 переезд (52): `Time` и `Distance` при загрузке не читаются;
  - 6 съезд (52): другой элемент и секция;
  - 7 пункт погрузки (56): количество и флаги;
  - 8 генератор машин (48);
  - 1 сигнал (128);
  - всё остальное 0 (44).
- **openRTS** каждый шаг даёт список от хвоста поезда игрока, вперёд на
  его длину и дальше, и назад, на столько, сколько просили DLL (не меньше
  5000 м).
  - Обход идёт по выставленным стрелкам и кончается в тупике или на
    пошёрстной стрелке, стоящей против пути.
  - Длина поезда считается от его хвоста до головы.

  Оба пункта PROBABLE: с каким режимом `0x47ECD0` здесь идёт `0x47F214`
  и где стоит путешественник хвоста RTS, не прослежено.
- **Контент:** ЭД9М просит код 1 и код 4 на 4000 м
  (`OPENRTS_DLLHOST_TRACE`).

### Именованные триггеры и пары триггеров (`0x4394F4`, `0x439548`)

- **CONFIRMED** `RTSGetNamedInteger(SMSObject::sms, 5, name)` ищет имя в
  `NamedTriggersTable` скрипта без учёта регистра и возвращает его код.
  Любой другой код или отсутствие совпадения дают 0.
  - Таблица (`0x4DD0EC`) — первый блок `NamedTriggersTable` файла; её
    получает каждая группа.
  - Её токены идут парами: имя и его код (`_wtoi`). Пустое имя её
    обрывает с сообщением.
  - Установлены: `Usavp.sms` (7955 записей: остановки поезда и их
    объявления по маршрутам) и `vl80k_aux.sms`.
- **CONFIRMED** `RTSIsSMSTriggerOn(SMSObject*, code)`:
  - −3 без скрипта или без пар триггеров;
  - −2 до первого кода пары (нет `PairedFlags`);
  - для кода «вкл» пары — состояние этой пары (`0x4A8A58`): 1 вкл, 0
    выкл, −1 ещё неизвестно;
  - −4 для любого другого кода.
  - `IsTriggerOn` из ts.h сам даёт −5 без `PairedFlags`.
- **CONFIRMED** `PairedFlags` (32 байта, `0x4A87C8`, выделяются при первом
  коде пары): четыре слова «пары включены», четыре — «пары известны».
  - Код «вкл» отбрасывается, пока его пара известна как включённая; код
    «выкл» — пока известна как выключенная. До первого кода пары проходят
    оба.
  - Код Halt выключает свою пару и проходит.
  - Пары после 128-й состояния не хранят.
- **openRTS:**
  - хост получает таблицу каждого скрипта и пары его группы при установке
    (один раз на файл);
  - на каждом шаге — состояния, которые держат звуковые объекты игры;
  - звуковые объекты отбрасывают и пропускают коды, как выше. До сих пор
    код «выкл» до первого «вкл» отбрасывался.

### `RTSSignalData` (`0x4903DC`)

- **CONFIRMED** `SignalUnit` базы маршрута (20 байт: тайл x z, `Position`
  x y z с x с обратным знаком, имя или null).
  - Каждая запись вешается (`+124`) на каждый сигнальный элемент TDB, у
    которого её ещё нет, на том же тайле в пределах 0,2 м по x, y и z.
    С именем или без.
  - `ALSN` получает запись первой головы; `Cabin::Signal` — следующего
    сигнала.
- **openRTS:** `formats::rts_signal_units`, хосту — один раз на запись. На
  Кубани у всех сигналов впереди на старте она есть.

## Открытые вопросы

- Типы поездов 4 и 5 (биты `State` `0x200` / `0x400`): PROBABLE — тип 4
  это поезд машиниста на клиенте его помощника (он запрашивает кабину, его
  звук кабины принимает `0x463A`), тип 5 — поезд под управлением
  диспетчера. Поезд удалённого игрока — тип 2 с флагом `0x10000`
  (`reverse/multiplayer.md`).
- Раздел 14: старший байт флагов `Electricity` (`+11`, предел расстояния в
  `0x5B53A8`, 0 на установленных маршрутах); `sub_45F570` (расстояние: 3D
  или на плоскости); глобальная `dword_61D31C` `+36`, PROBABLE — «игра
  через сетевой поток» (`reverse/multiplayer.md`): зачем её читает
  напряжение в сети, не прослежено.
- Раскладка записи вспомогательной (`0x54` байта) и сортируются ли записи
  по порядку или хранятся в порядке объявления.
- Управляющее слово FPU во время работы.
- Флаг поезда `LowerPantoOnStop` (бит 8 `+5`) и `LocoFlags` 0x400 / 0x800
  (§16) не прослежены до места, где они ставятся.
- Затухание дисплея (первое значение `DisplayFade`, `0x4B355C`): как
  затухает узел.
