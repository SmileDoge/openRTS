# Сетевой протокол RTS: каталог пакетов

> Перевод [`docs/reverse/multiplayer-protocol.md`](../../reverse/multiplayer-protocol.md).
> Основной текст — английский: при расхождении верен он.

Каждый id пакета, который используют три программы, с его содержимым и
тем, что делает получатель. Прочитано на копиях, 2026-11-05:
- `rts1.exe` (`build/ida/rts1.i64`);
- `rts_server.exe` (`build/srv/rts_server.i64`);
- `rts_server_DSP.exe` (`build/dsp/dsp.i64`).

Остальное — в `multiplayer.md`:
- транспорт, обрамление и вход;
- роли программ, сцепка и помощники;
- как выглядят и звучат поезда других игроков.

CONFIRMED, если не отмечено иное.

## Как это читалось

- **Инструменты** (`build/ida/s5/`, не в репозитории):
  - `pkgscan.py` находит в базе каждую константу `0x4500`..`0x47FF` и
    декомпилирует функции, где она встречается: клиент — 289 мест в 98
    функциях, сервер — 162 в 67, пульт — 160 в 65;
  - `pkgmap.py` выписывает по каждому id поля, которые пишет каждый
    отправитель и читает каждый получатель.
- **Запись и чтение полей:**
  - клиент: `0x558050` / `0x5581DC`, объект пакета `0x4C2068`;
  - сервер: `0x45DBC0` / `0x45DD24`, объект пакета `0x445990`;
  - пульт: `0x43BEE4` / `0x43C048`, объект пакета `0x423F34`.
- Затем обработчики прочитаны вручную.
- В найденных у клиента `0x45xx` кода пакетов нет: те же числа
  используются для другого.

## Имена пакетов

Короткие имена пакетов — для разговора, заметок и кода `openrts_net`
(имена в его перечислении). В RTS имён нет, это имена openRTS. Имя
говорит, о чём пакет; подробности — в строках ниже.

- **Пары.** `train_pos` и `train_pos_forced` несут одно и то же; второй
  берётся и для собственных поездов получателя.
- **Один id — два имени.** `0x460E` и `0x460F` сами по себе — `uncouple`
  и `couple`, а внутри `train_add` — `train_cars` и `train_car`.
- **В файле восстановления** свои id (из сохранённой игры): те же числа там
  значат другое («Файл восстановления игрока»).

## Программы, связи и обработчики

| Связь | Кто отправляет | Кто принимает |
|---|---|---|
| игрок → сервер | сетевой поток клиента (стоит `dword_61D31C+36`, PROBABLE «игра через сетевой поток») или `0x52CE9C` на собственном узле | сетевой поток сервера `0x4436C8` (ограничения, пересылка), главный поток `0x40FB90` |
| сервер → игрок | сетевой поток сервера | клиент `0x4C3DE0` |
| машинист ↔ помощник | NetworkNode каждой стороны | `0x4C9120`; клиентский `0x4C3DE0` тоже передаёт ему `0x4620`, `0x4622`..`0x4624`, `0x4632` |
| игрок → хост мини-сервера | сетевой поток клиента | `0x4CA588`, затем `0x4C9120` / `0x4C3DE0` |
| пульт ↔ сервер | тот же код, что у сервера | `0x40FB90` в обеих программах |
| файл снимка `multdata` | — | `0x4CAEAC` проигрывает его через `0x4C3DE0` |
| файл ситуации | пишет сервер `0x418474` | читает сервер `0x41A650` |
| файл восстановления `multRecoveryData.dat` | пишет клиент `0x47B09C` | читает клиент `0x47B414` при проигрывании снимка |

- **Пульт.** `rts_server_DSP.exe` собран из кода сервера:
  - те же функции, поле в поле;
  - в `0x40FB90` ветки пульта проверяют `byte_54C83B` («я пульт»);
  - `byte_54C83D` — «пульт загрузился»;
  - `byte_54C838` — «сервер с клиентами»: тогда он пересылает принятое
    дальше.
- **Глобальные переменные клиента:**
  - `dword_61D31C+37`: игра на мини-сервере игрока. Её задаёт только хост,
    пакетом `0x4630` со значением 1. Она включает `0x4622` и запрос
    `0x4623` с режимом 1;
  - `+48`: id поезда игрока из `0x462E` снимка;
  - `+56` (`u16`): PROBABLE сетевая роль, 2 — хост мини-сервера.
- **Виды поездов у клиента:**
  - 0 STATIC;
  - 1 собственный поезд PLAYER этого клиента;
  - 2 TRAFFIC; с флагом поезда `0x10000` — поезд другого игрока;
  - 3 LOOSE;
  - 4 PROBABLE: поезд машиниста на клиенте его помощника.
- **Флаги поезда у клиента (`+4`):**
  - `2` загружен;
  - `4` работают DLL (флаг 4);
  - `0x10` стоит (`0x4606`);
  - `0x20` в нём игрок;
  - `0x1000` есть сошедшие вагоны;
  - `0x10000` поезд другого игрока.

**Кто что считает.**
- В сетевой игре клиент считает и отправляет только свои поезда вида 1
  (`0x424488`):
  - `0x4603` не чаще раза в 1,5 с, пока поезд движется;
  - ещё один при остановке, если стоит флаг поезда `+6 & 0x20`.
- Любой другой поезд экстраполируется по `0x4603`. Через 5 с без пакета
  его скорость и ускорение падают до 0.
- Хост мини-сервера (роль 2) ещё шлёт `0x462F` + `0x4606` для поезда,
  простоявшего дольше 5 с, и то же вместе с `0x4607` для поезда, который
  он создаёт.

## Сеанс

| Id | Направление | Содержимое | Что происходит |
|---|---|---|---|
| `0x4600` | игрок → сервер, сервер → игрок | вход, ответ на вход | `multiplayer.md`, «Вход» |
| `0x4500` | пульт → сервер | вход | та же раскладка, что у `0x4600` |
| `0x4608` | игрок → сервер; сервер → игрок | пусто | запрос стартовых данных; конец снимка. Второй запрос получает `0x4703` |
| `0x4701`..`0x4706`, `0x47FD`..`0x47FF` | сервер → игрок | только код `u16` | `multiplayer.md`, «Вход» |
| `0x4611` | сервер → игрок | `u32 n`, текст UTF-16 | окно сообщения диспетчера; ещё 15 мин держится в списке сообщений; только адресату |
| `0x4612` | локальный | пусто | «Server down»: клиент показывает его и выходит; пульт закрывается. Его никто не шлёт: получатель сам ставит его в очередь, когда закрывается его сокет (клиент `0x4C351C` → `0x4CB390`; сервер и пульт `0x44DCC8`, `0x444B74`) |
| `0x4616` | сервер → игрок, пульт | `u8` приостановлен | пауза; на пульте — кнопка паузы. Пока пауза, не отправляется ничего |
| `0x4643` | сервер → игрок, пульт | сообщение `u32` | `0x4706` показывает предупреждение о потоке пакетов, всё остальное — пронумерованное «Server message» |
| `0x4630` | хост мини-сервера → игрок | `u8` 1 | только в снимке хоста: ставит `dword_61D31C+37` |
| `0x462E` | сервер → игрок | id пользователя, id поезда, `u32`, `u32` + 3 × `f32`, `u32` + 3 × `f32`, имя (32 байта) | запись пользователя, в снимке; id поезда клиент берёт как свой поезд (`+48`) |
| `0x462D` | игрок → сервер → остальные | поля положения клиента (как в `0x462E`, начиная с id поезда): `u32` 0 (`rts1.exe` всегда шлёт 0 в поле поезда записи), поезд, в котором игрок, `u32` (0 — ни в каком), `u32` (UNKNOWN, 0 или 1), тайл x, z (`i16`), x, y, z, четыре `f32` (живая запись 2026-11-05) | сервер сохраняет их в записи пользователя и пересылает всем остальным (аудитория 2) с id отправителя в начале и его именем (32 байта) в конце: значок человека на карте |
| `0x1700` | помощник → машинист | id узла, сеанс | приветствие NetworkNode (`multiplayer.md`, «Помощники») |
| `0x1701` | узел → узел | текст | показывается как сообщение «Multiplayer» (`0x52DE78`) |

**`0x4603` на клиенте** (`0x4C3DE0`):
- Для собственных поездов клиента (виды 1 и 4) он не применяется, если это
  не `0x462F`.
- **Сглаживание.** Пусть поезд на том же узле пути, движется, а новое
  смещение ближе `50 × max(1, |v| / 15)` м. Тогда клиент вместо прыжка
  подправляет скорость на `|v| × d / (100 × max(1, |v| / 15))`.
- Число вагонов должно совпасть, иначе пакет отбрасывается.
- Время отмечается для отсечки в 5 с.

**`0x4603` на сервере** (`0x40FB90`):
- Принимается для поезда PLAYER от любого отправителя, от пульта или от
  пользователя роли 1. Владелец не проверяется.
- Пересылается всем, кроме отправителя.

**Расцепка на сервере** (`0x44FE34`):
- Из части создаётся новый поезд (`0x456958`). Он **сохраняет вид и
  владельца** поезда, от которого отцеплен (`+296`, `+328`), и берёт его

- Отправитель получает `0x4610`: его локальный id → новый id.
- Остальные получают `0x460E` (поезд, вагон, новый id, сторона), затем
  `0x4603` этой части.
- Клиенты режут поезд через `0x469858`.

- Раскладка станционного маршрута — в «Живой записи»; три флаговых байта

6. на каждый поезд:

проигрывает его (`0x4CAEAC`):
- заходит внутрь контейнеров `0x4600`, `0x4608`, `0x4609`, `0x460B`;

  `0x4645`..`0x4648`, `0x464B`..`0x464E`;
- берёт id поезда игрока из `0x462E`;
- на любом другом id загрузка останавливается.

Хост мини-сервера собирает свой снимок (`0x4D14F0`) и добавляет `0x4630`.

## Файл восстановления игрока

`multRecoveryData.dat` в рабочей папке клиента (`rts1.exe`) — то, что
читают «Restore player position» и «Restore train state». На сервере из
этого ничего не хранится.

**Пишется** (`0x47B09C`):
- по F2 в сетевой игре, вместо сохранения игры (`0x4121BC`);
- по `0x4612`, «Server down»;
- аварийным сохранением после падения, если игрок соглашается на «Do you
  want to try saving the simulation state?» (`0x408360` из `0x40521C`).

Два клиента, запущенные из одной папки, пишут один и тот же файл:
остаётся то, что записал последний.

**Содержимое** — в пакетном формате сохранённой игры (`u16` id, `u32`
длина):

| Id | Содержимое |
|---|---|
| `0x4400` | корень: весь файл |
| `0x4504` | версия `u16` (114) |
| `0x4510` | два `u8` (в записи 1 и 0), время симуляции `u32` (с), температура `f32` |
| `0x4502` | место игрока: положение в тайле 3 × `f32`, три 4-байтовых значения, тайл x и z `i16`; внутри него `0x4511`, если игрок в вагоне: id поезда, номер вагона, место `u16` (1 — кабина), положение в поезде 3 × `f32`, ещё два 3 × `f32`; `0x4512` / `0x4513` — номер в списках камер кабины (`0x41ADA8`) |
| `0x4548` | путь `.trk` маршрута (`u16 n` + UTF-16) |
| `0x4506` | собственные поезда игрока (вид 1 с битом 2 у `+4`): по `0x4521` на поезд — запись поезда из сохранённой игры с вагонами (`0x57194C`) |

**Читается** (`0x47B414`) во время проигрывания снимка (`0x4CB2B4`), если
отмечена хотя бы одна галочка (`+70`, биты 0 и 1):
- другой путь маршрута — ничего не восстанавливается;
- время, расходящееся с серверным больше чем на 300 с, вызывает вопрос
  «Time in recovery data … significantly differs … Try to restore train
  state anyway?»;
- «Restore train state»: каждый `0x4521` ложится на поезд с тем же id,
  если этот поезд теперь принадлежит игроку (вид 1) и вагонов в нём
  столько же; вагоны получают сохранённое состояние (`0x57CD78`);
- «Restore player position»: игрок садится в сохранённые поезд и вагон
  (`0x4FC32C`), потом в камеру кабины; иначе — в сохранённую точку.

Значит, повторный вход восстанавливает только то, что сервер сохранил
прежним: id поездов и их владельца.

## Живая запись (2026-11-05)

**Как снималось.**
- Один ПК: `rts_server.exe` (пульт ТЧД, порт 800), `rts_server_DSP.exe`
  (пульт ДСП) и два `rts1.exe` (MashFirst, MashSecond), Кубань.
- Все говорили через `tools/mp-capture/mp_proxy.py --mode helper --dump
  capture.bin`: каждый кадр записан целиком, около 15 000 с
  (4 ч 10 мин) и 99 000 кадров, 30 МБ. Запись читают `mp_dump.py` и `parse4607.py` (из той же папки).
  В записях ники и адреса игроков, в репозиторий они не попадают.
- Собственный «Data trace» сервера (меню `mnDataTrace`) так не может: его
  уровень (`word_53D27C`) в exe равен 0, и ничто его не меняет, поэтому
  он никогда не пишет `0x4603`, огни, звуки и связь с помощником.

CONFIRMED записью, если не отмечено иное; она же поправила несколько
прочтений выше.

**Что показала запись, коротко.**
- **Кто решает.** Каждый клиент считает только свои поезда (вид 1) и раз в
  1,5 с сообщает остальным, где они. Сервер пересылает почти всё и мало
  что проверяет: `0x4603` поезда PLAYER он берёт от любого отправителя.
  Поезда TRAFFIC сервер ведёт сам, раз в 0,5 с, по командам пультов. Все
  остальные поезда клиент только экстраполирует.
- **Чем не обмениваются вовсе:** пассажирские двери (их открывает DLL), как
  ложатся сошедшие вагоны, владельцы (пульт ДСП их не узнаёт), название
  отцепленной части на пульте ДСП.
- **Что ломается:**
  - сцепка поездов двух игроков останавливает DLL второго игрока; поезд у
    него стоит, пока диспетчер его не назначит, и DLL продолжает без
    `Init`;
  - «Удалить из мира» и постановка обратно своего поезда игрока уронили
    его владельца;
  - после повторного входа связь с помощником не вернулась;
  - повторный вход рассылает всем старые тормозные давления диспетчера;
  - сошедшие вагоны лежат у каждого клиента по-своему.
- **Что работает и стоит сохранить:** команды пультов (сигналы, стрелки,
  маршруты, скорость, направление, пауза, сообщения, подстанции и
  секционирование), таймеры сервера у стоящих поездов, снимок при входе,
  вход, который вытесняет старое соединение того же ника.
- **Что из этого берёт openRTS:** `multiplayer.md`, «Что живая запись
  2026-11-05 требует от openRTS».
- **Не снято:** пункт экипировки. Из установленных маршрутов они есть
  только на Успенске (39), поэтому его пропустили; `0x461C` известен только
  по коду.

**Создание поезда.**
- С ДСП:
  1. пульт отправляет `0x4607` со своим локальным id;
  2. сервер отвечает `0x4507`: `u32` 1, локальный id, успех, новый id как
     `f32` (5,0), `u32` 0;
  3. он шлёт `0x4607` с новым id всем остальным;
  4. затем пульт отправляет `0x461A` (название), `0x4508` и `0x4606`.
- С ТЧД (это сам сервер) те же `0x4607`, `0x461A`, `0x4508`, `0x4606`
  уходят всем, пульту тоже.
- Id используются повторно: отцепленные части получили id 1 и 3 ушедших
  поездов.
- **Запись вагона** (`0x460F` внутри `0x4607`), поле за полем:
  - вид, имя файла;
  - uid: номер поезда `<< 18` плюс номер вагона;
  - флаги: 1 развёрнут, 2 холодный, `0x100` тормозной башмак с головы
    состава (на первом вагоне), `0x200` — с хвоста (на последнем);
  - масса, кг (ЧС4з 129 т);
  - ширина, длина, высота, м (ЧС4з 3 / 19,6 / 4,5, ЭД9М длиной 22,1 м);
  - ручной тормоз (`+112`, 0..1);
  - его сила, Н: `MaxHandbrakeForce` вагона (головной ЭД9М 22 кН, моторный
    0, вагоны 15 и 5,4 кН). Клиент читает ручной тормоз и пропускает силу.
- У пульта в «Закрепить состав» четыре галочки (их смысл — в подсказках):
  башмаки с головы, башмаки с хвоста, ручной тормоз с головы, ручной
  тормоз с хвоста. Они ставят ровно эти поля первому и последнему вагону.
- PROBABLE, значения движения поезда. `f32` после подвида в `0x4607` —
  наибольшая скорость в м/с. Хвост `0x4607` — ускорение и замедление.
  `0x4508` повторяет их после текущей скорости 0.

  | Поезд | Наибольшая скорость | Ускорение | Замедление |
  |---|---|---|---|
  | ЧС4з | 41,67 | 1 | 2 |
  | ЭД9М | 36,11 (130 км/ч, его `MaxVelocity`) | 1 | 2 |
  | одни вагоны | 1 | 0,001 | 0,002 |

  У ЧС4з `MaxVelocity` — 100 mph, так что 41,67 взято не оттуда.
- Первая строка `0x461A` — название, которое даёт пульт, свободный текст.

**Назначения.**
- `u32` в `0x4601` — номер поезда (123, 101).
- Он уходит только тому пользователю, которого касается: игроку, который
  получает или теряет поезд, или пульту, когда владельцем становится сам
  пульт.
- Поэтому ДСП никогда не узнаёт, кто что ведёт. Пульт ДСП, вошедший
  заново, тоже не получил в снимке ни `0x462E`, ни `0x4601`. Владельцев
  показывает только ТЧД, который и есть сервер. ДСП получает `0x462D`,
  второй `u32` которого — поезд, где сидит игрок (здесь 0, 2, 3), но
  показывает их только на карте.
- «Назначить диспетчеру»: пульту `0x4601` «твой», прежнему владельцу «не
  твой», затем `0x461A` и `0x4605` (название и номер 101). Вид остаётся 1.
  Вида 5 не появилось.
- Отданный обратно игроку поезд снова становится его видом 1. Его клиент
  не привязывает и не инициализирует DLL заново (`LocoFlags & 0x20`): DLL
  продолжает с того места, где замёрзла. Всё, что за это время делал
  другой владелец, теряется. Пантографы, опущенные MashFirst, клиент
  MashSecond снова сообщил поднятыми.
- Начальное состояние поезда (`+2`) приходит в `0x4605` (2, «Движется») и
  становится `State` для `Init` при привязке DLL. MashFirst зашёл в кабину
  поглощённого ЭД9М, и его DLL стартовала «в движении».

**Положения.**
- `0x4603` приходит раз в 1,5 с, пока поезд едет. Скорость со знаком:
  меньше 0 — поезд едет хвостом вперёд.
- Байт «направления» не следует ни за знаком, ни за реверсом. PROBABLE:
  как поезд лежит на своём участке пути.
- Реверс не передаётся никогда. Стрелка на пульте показывает, куда
  смотрит голова.
- Пульт откладывает маршрут туда, куда поезд ехал последний раз. У
  стоящего поезда скорость 0 и знака нет, поэтому диспетчеру приходилось
  просить чуть сдвинуть поезд назад.
- Движение чужих поездов игроки назвали плохим: торможение видно с
  опозданием до 1,5 с, пока ещё применяется старое ускорение.

**Сцепки.**
- Два игрока: ЧС4з MashFirst наехал на ЭД9М MashSecond. Клиент MashFirst
  отправил `0x460F`, затем `0x463C` по всем восьми вагонам, которые забрал.
  Сервер прислал MashSecond в таком порядке:
  1. `0x4603` поезда А;
  2. **`0x4601` «не твой» по его собственному поезду**;
  3. `0x460F`;
  4. `0x4610` (3 → 2);
  5. `0x4603` общего поезда.

  `0x4601` приходит раньше сцепки. Поэтому клиент MashSecond сделал свой
  поезд чужим (вид 2), и его DLL встала: контроллер, двери, КЛУБ. Дальше
  поезд двигался экстраполяцией.
- Пульт получил только `0x460F` и `0x4603`. ДСП показывал владельца
  пустым, ТЧД — MashFirst.
- Когда MashFirst зашёл в кабину ЭД9М, его клиент привязал DLL ЭД9М и
  вызвал `Init` с нуля: давления накачивались заново. Из состояния DLL
  ничего не переходит.
- **Пассажирские двери ЭД9М не реплицируются.** Это двери, которые
  открывает DLL, а не двери кабины. При их открытии ничего не
  отправляется:
  - у `0x463C` не изменились `Flags`, `+32` и `+14`;
  - изменились только маска пантографов и бит `Flags` `0x4` (игрок в
    кабине).

  Каждый клиент держит те двери, что видел последними. У MashFirst двери
  ЭД9М остались открытыми навсегда, после того как поезд ушёл от него.
- Меню сцепки после сцепки показывало на двух клиентах разное. MashFirst
  разъединил рукава и закрыл краны (`0x461B`, действия 3, 5, 9: явные
  «поставить» или «снять», `0x463F84`); у MashSecond тот же стык остался
  соединённым. `Flags` вагонов никогда не сверяются. Почему пересланные
  действия там промахнулись — UNKNOWN; возможно, разный порядок вагонов.

**Связь с помощником** (MashSecond — помощник MashFirst):
- **Какой поезд.** Поезд называет клиент машиниста в своём ответе
  `0x461F` тип 4, а сервер передаёт его дальше без проверки. Клиент
  MashFirst назвал поезд 3, ЭД9М: тот, в котором он был последним и
  который сервер давно вернул MashSecond. Помощник загрузился в этот поезд,
  ничей для его нового сеанса. `0x461E` (вид 4) пришли только по
  собственным поездам машиниста, 2 и 1. Первый тип 2 ушёл пульту ДСП и был
  отозван через 10 с.
- **Обмен через ретранслятор:**
  - машинист → помощник: `0x4620` дважды в секунду по каждому его поезду,
    `0x4624` (вся кабина) раз в 60 с по каждому;
  - звук кабины `0x463A` (слот 1) идёт через сервер, всем, кто рядом;
  - помощник запрашивал кабины `0x4623` с режимом 1, поезд за поездом.
- **`0x4622` в обе стороны** (26 от помощника, 19 от машиниста):
  - вид 3, владелец 1: переключатель кабины. У ЧС4з 100 (положения
    1 / 12 / 13), 101, 103 (0 / 1 / 2), 106, 109, 110, 119;
  - вид 1, владелец 1: дверь кабины (`ActDoor`, `Cabin+172`), здесь 3 и 5;
  - вид 1, владелец 3: дверь самого вагона, через которую входят (`+328`
    вагона);
  - «положение» — куда переводят орган (`SetState`), «значение» — где он
    стоял;
  - два числа — значение и кадр его анимации.
- Значит, двери кабины и вагона до помощника доходят. Пассажирские у него
  не двигаются:
  - кнопки дверей у машиниста (переключатели кабины ЭД9М 25, 11, 5, 42, 34)
    приходят как `0x4622`, DLL помощника получает `CanSwitch` / `Switched`,
    и кнопки двигаются;
  - сами двери DLL двигает в `Run`, который на клиенте помощника не
    вызывается никогда;
  - когда помощник зашёл в кабину заново, его клиент запросил всю кабину
    (`0x4623` режим 1, `0x4624` на 37 КБ), и двери скачком встали как у
    машиниста: открытыми;
  - следующее закрытие и открытие снова прошли без анимации;
  - PROBABLE: `0x4624` раз в 60 с переписывает состояние DLL, но сам двери
    не двигает.

  Другим игрокам двери не приходят вовсе.
- `0x4632` (перетаскивание мышью) не встретился.

**Расцепки.**
- MashFirst резал свой поезд дважды:
  - `0x460E`: поезд, вагон (1, первый вагон части), локальный id (100244,

  - сервер ответил ему `0x4610` (локальный → 1, потом → 3);

- Два пульта разошлись в названии и номере части:
  - ТЧД показывал «Отцеп от 123-first-1» и пустой номер;
  - ДСП показывал номер 123 и «123-first-1» — свою разрезанную копию;
  - после нового входа ДСП показал номер 0.

- Клиент оставляет отцепленную часть своим поездом: после расцепок клиент
  MashFirst продолжал слать огни частей (`0x4617`) и их положения при
  остановке (`0x4603`).

**Меню вагона.**
- Башмак под поезд другого игрока ставится: `0x4640` (поезд, вагон, `u32`
  2, флаги `0x100`, `f32` 1,0) пересылается без проверки владельца.

**Сигналы и стрелки с пульта.**
- Стрелка — `0x460A` от пульта, его пересылают игрокам.
- **Светофор задаётся `0x4618`**, а не `0x460C`. Поля:
  - номер объекта в таблице светофоров сервера (1 406 записей в снимке
    пульта);
  - состояние `u16`: состояние типа сигнала, например 1 — стоп, 7 —
    CLEAR2 у НМ11;
  - **режим `f32`**:
    - 0 — выключен: сервер держит состояние, которое дал пульт («закрыть»
      даёт 1, «задать показание» — это показание, с `u8` 1);
    - 1 — включён: состояние сигнал выбирает сам по своей логике.
      «Открыть» у НМ11 оставило красный. Меню «Сигналы» на ТЧД с
      «Включить» для типа `t_stop_r` переключило все сигналы этого типа
      разом: 276 `0x4618` пульту ДСП, 192 `0x460C` игрокам, состояния 2
      (43 или 60 км/ч) или 1. Повторно с галочкой «Отображать как
      поездной» ушли только 212 `0x4618` с теми же полями, а игрокам —
      ничего: этой галочки нет в протоколе (PROBABLE: то, как пульт рисует
      сигнал);
    - 2 — автоблокировка;
  - `u8` 1, когда диспетчер выбирает показание.
- Ручное состояние сервер применяет сразу (`0x40FB90` → `0x40C714`):
  - головки, у которых есть это состояние, получают его, его отрисовку и
    скорость;
  - остальные головки получают отрисовку −1;
  - игроки получают `0x460C`, пульты — `0x4618` обратно.

  При автоблокировке состояние выбирает сервер (здесь красный) и шлёт
  режим 2.
- **`0x460C`, уточнено:**
  - номер;
  - `u16` `+78`, во всех пакетах сеанса 0, UNKNOWN;
  - состояние `+84`;
  - отрисовка `+88`;
  - `+92`;
  - режим `+96`;
  - ограничение скорости `+100`, м/с, −1 — нет (11,9 у М96 в состоянии 2).

**Поезд, которого ведёт сервер** (ЧС4з, поезд 5, переведённый на ТЧД в
TRAFFIC):
- **Перевод в TRAFFIC:** `0x461A` и `0x4605` с видом 2.
- **Команды пульта:**

  | Кнопка | Пакет |
  |---|---|
  | «Изменить направление» | `0x4506` (флаги поезда `+79`, бит 2) |
  | «Начать движение» | `0x4505` 1 (`+79`, бит 1) |
  | «Задать скорость» (5 км/ч, наибольшая 150, ускорение 1, замедление 2) | `0x4508` 1,389, 41,667, 1, 2 |
  | «Удалить из мира» | `0x4602` с флагом 0: клиенты снимают поезд с пути и оставляют его |
  | поставить снова | `0x4603` и `0x4606`, без нового `0x4607` |

  Флаг 1 у `0x4602` удаляет поезд («Удаление», ниже).
- **Сборка его маршрута на ТЧД:**
  - сервер переводит стрелки (`0x460A` всем);
  - включает сигналы маршрута: режим 1, состояния от 1 до 3, 25
    `0x4618` пульту ДСП и `0x460C` игрокам;
  - шлёт `0x4619` с длиной: 9 572,81 м.
- **Сервер сам двигает поезд** и шлёт его `0x4603` каждые **0,5 с**, а не
  раз в 1,5 с:
  - разгоняет с заданным 1 м/с²;
  - держал 11 м/с у сигнала на 43 км/ч, потом разгонялся дальше;
  - так что 5 км/ч из «Задать скорость» — не цель. PROBABLE: скорость,
    которую поезд получает сразу.
- **`0x4619` — оставшееся расстояние до конца маршрута:** 9 572,6 →
  9 475,6 м по ходу поезда, раз в 0,5 с. Раньше оно росло, потому что
  поезд отходил от конечной точки.
- Сигналы за поездом переключаются: `0x460C` игрокам, `0x4618` пульту ДСП.
- Поезд с башмаками и ручным тормозом («Закрепить состав») не поехал:
  сервер тормозил его с замедлением (2) уже с первого `0x4603` (0,39 м/с,
  −2 м/с²).

**Маршруты пульта** («Сборка маршрута поезда»):
- **Окно.** Маршрут поезда — цепочка отрезков: станционных маршрутов и
  перегонов из базы маршрута (`.rtsdb`). В сеансе:
  - Краснодар-2: Н → НМ1 [П], 860 м;
  - НМ1 → НМ1С, 412 м;
  - НМ1С → Н1 [П], 199 м.

  Элементы окна:
  - «Задать» добавляет выбранный отрезок;
  - «Отменить» снимает отрезок;
  - «Направление» меняет направление «от последней точки маршрута»;
  - число — приоритет;
  - «Станция» — переключатель, который держит карту пульта на этой
    станции (без пакетов).
- **`0x450B`**, по одному на отрезок:
  - id: `0xFF0000nn` от ДСП, в ответе сервера — его id;
  - id поезда;
  - id станционного маршрута в базе (639, 648, 927, 1083…);
  - название станции (`u16 n` + UTF-16: «Краснодар-1», «Краснодар-2»);
  - два `u16`, около −4545 / 14592: проверка, тайл начальной точки
    станционного маршрута; отрезок с другими значениями отклоняется
    (`0x454194`);
  - направление `u8`: с какого конца станционного маршрута он начинается
    («Направление»); затем два флага, PROBABLE «удержание» (следующий
    отрезок поезда ждёт, пока этот выставлен) и «обратно» (поезд идёт по
    нему назад: флаг уходит в направление поезда на нём); в сеансе все три
    0;
  - длина `f32`, м;
  - приоритет `u32` (0 или 2 из поля окна);
  - состояние `u8`, список стрелок `u16` (номер + 1) и число уже
    переведённых стрелок `u16`, как в `0x450E`.
- **С ДСП** пульт отправляет `0x450B`. Сервер отвечает:
  - `0x450B` со своим id;
  - `0x450C`: id запроса, новый id, успех `u8` 1, без текста;
  - `0x450E`: id, состояние, список стрелок, приоритет, длина, число
    переведённых стрелок.
- **Как сервер выставляет отрезки** (`0x46A348`, `0x41F520`; по коду):
  - все отрезки ждут в одном списке по приоритету, отрезки одного поезда —
    по порядку. Отрезок берётся, когда предыдущий отрезок поезда
    выставлен (состояние 1 или 3) и не держит;
  - сначала он проверяется (`0x469804`): поезд есть; на перегоне нет
    маршрута встречному поезду («На перегон задан маршрут встречному
    поезду»); есть путь от конца предыдущего отрезка («Не найден путь от
    предыдущей точки пути до нового маршрута»); занятый станционный путь
    вызывает вопрос оператору ТЧД («Путь … занят поездом. Все равно задать
    маршрут?»), а запрос пульта этот вопрос пропускает;
  - потом стрелки переводятся по одной (состояние 2, счёт — в последнем
    `u16`), сигналы включаются (состояние 1), поезд отмечается на отрезке,
    когда въезжает (3), а отрезок убирается, когда поезд его покинул (4);
  - PROBABLE: приоритет решает, какой из ждущих отрезков первым получит
    свои стрелки; больше его ничто не читает.

  **С ТЧД** сервер шлёт пультам `0x450B` и `0x450E`.
- **«Задать» исполняет отрезок сразу,** с любого пульта:
  - стрелки (`0x460A`);
  - сигналы на нём включаются (режим 1), `0x4618` пультам и `0x460C`
    игрокам: открылся входной на Краснодар-2;
  - `0x4619`: оставшееся расстояние до конца всего маршрута, оно растёт с
    каждым отрезком (5 943,6 → 7 343,6 м).

  Отрезок для ЧС4з, который не продолжал путь от места поезда, был принят
  (`0x450C`) и ничего не выставил (PROBABLE: ждёт).
- **Отмена:**
  - с ДСП: `0x450D` с id; сервер возвращает его и отвечает `0x450C`
    (id, 0, успех);
  - с ТЧД, весь маршрут поезда: `0x450D` по каждому отрезку пультам,
    `0x4619` −1 всем, сигналы маршрута закрыты (режим 0, состояние 1).
    Стрелки остаются как есть.
- **Ограничения скорости разрешающих состояний** по `0x460C` на Кубани:
  состояние 2 — 11,9 м/с (43 км/ч), 3 — 17,5 (63), 6 — 23,1 (83), 7 — нет
  (−1).
- **«Выключить» для типа сигналов** (`t_stop_r`, «Сигналы» на ТЧД): 212
  `0x4618` с режимом 0 и прежними состояниями, игрокам ничего. Головки
  остаются как были.

**Сообщения и пауза.**
- Сообщение с ТЧД уходит только адресату: `0x4611`, `u32 n`, текст UTF-16
  («Отправил....», `\r\n`, ещё текст), ноль.
- Пауза: `0x4616` 1 всем, пульту тоже; 0 снимает её. За 342 с паузы **не
  ушло ни одного пакета**: ни положений, ни огней, ни звуков, ни времени,
  ни нагрузок подстанций, ни связи с помощником.

**Удаление.** `0x4602` с флагом 1 удаляет поезд (поезда 1, 2, 4, 5
исчезли). Каждый такой `0x4602` пульт ДСП через 0,3 с отправлял серверу
обратно (PROBABLE: общий код повторяет команду, это безвредно).

**Маршрут поезда с пульта** (`0x4619`):
- это длина маршрута в метрах: 128,11 до красного выходного, 26,34 для
  короткого. Маршрут откладывается от головы по текущим положениям стрелок;
  стрелки задаются отдельно;
- пока поезд движется, сервер пересчитывает её и рассылает всем, игрокам
  тоже, раз в 0,5 с, если она изменилась (41,6 → 46,2 м);
- «отменить» шлёт −1; сервер в ответ ничего не шлёт.

**Сход** (ВЛ80 MashFirst, поезд 4, две секции, на 30 м/с):
- Владелец отправил `0x4636` всего четыре раза: при сходе (13015,2 и
  13015,4 с — одна секция, потом обе) и вместе со своими `0x4603`, пока
  поезд ещё двигался (раз в 1,5 с). Поезд остановился в 13017,5 с, и больше
  ничего не пришло, хотя вторая секция ещё опрокидывалась (0,92 из 0,98
  рад).
- Падение каждого сошедшего вагона каждый клиент досчитывает сам, от
  последнего пришедшего положения. У двух игроков секции легли по-разному,
  и ничто это не выравнивает: итогового положения в протоколе нет.
- У пультов нет «поставить на рельсы». Это делают «Удалить из мира» и
  повторная постановка: оба игрока увидели ВЛ80 на рельсах. Ни `0x4637`,
  ни нового `0x4636` при этом не ушло.

**Снятие и постановка своего поезда игрока уронили его владельца**
(сошедший ВЛ80; `rts1.exe` MashFirst записал дамп):
- `0x4602` с флагом 0 снимает у поезда бит `+4` `0x10` и обнуляет узел
  пути его головы (`+192`; клиент `0x4C3DE0`). Цикл кадра (`0x424488`)
  пропускает поезд без `0x10`, так что клиент жил дальше.
- Постановка прислала `0x4603`, `0x4606`, `0x4603` (13217,98 с). Владелец
  пропускает `0x4603` для своего поезда. `0x4606` снова ставит `0x10` и
  пересобирает голову из положения поезда (`+232`, его пишет `0x4603`).
- Через 0,35 с клиента не стало: его ретранслятор замолчал между 13217,79
  и 13218,32 с, а `0x4623`, пришедший позже, застал его уже упавшим.
- Дамп: нарушение доступа при чтении `0x24` в `rts1.exe+0x80124`. Поиск
  сигналов впереди (`0x508520`) шёл по пути от головы (`0x4800C4`) с узлом
  0 и смещением 41,26 м — ровно там, где ВЛ80 остановился.
- Почему у головы и после `0x4606` не было узла, не доказано. Либо его не
  было и у положения (свой поезд владелец никогда не берёт из `0x4603`),
  либо кадр пришёлся между тем, как `0x4606` поставил `0x10`, и его
  копированием. Поезд TRAFFIC те же кнопки переживает (ЧС4з выше): его
  `0x4603` приходит до `0x4606` и принимается.
- Сервер, которому важно не ронять клиентов RTS, ставит поезд с владельцем
  через `0x462F` — он доходит и до своего поезда владельца — или не снимает
  такой поезд из мира.

**Повторный вход игрока** (MashFirst после падения, галочки «Restore
player position» и «Restore train state»):
- **«Подключиться»** шлёт вход (`0x4600`). Сервер отвечает и закрывает
  старое соединение этого ника, которое всё ещё было открыто (упавший
  процесс). Для меню он шлёт `0x4601` с поездом 3.
- **«Зайти»** через несколько минут просит снимок (`0x4608`); он приходит
  за 0,2 с:
  - корень, время, стрелки (8,3 КБ) и сигналы (62 КБ);
  - электроснабжение, игроку тоже: `0x4646` по каждой подстанции,
    `0x4648`, `0x4645`;
