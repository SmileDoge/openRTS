# Путевая сеть в RTS

> Перевод [`docs/reverse/track.md`](../../reverse/track.md). Основной текст
> — английский: при расхождении верен он.

Состояние: статический анализ `rts1.exe` плюс измерения на 7 установленных
маршрутах (`openrts-track-check`). Реализовано в `formats`
(`track_sections`, `track_database`) и `simulation` (`track_geometry`,
`track_network`, `track_traveller`). План и критерии приёмки:
`docs/track.md`.

| Адрес | Роль |
|---|---|
| `0x483694` | загрузчик маршрута: tsection.dat (секции, модели), .tdb |
| `0x481AF8` | узлы пути TDB |
| `0x482680` | таблица элементов TDB |
| `0x481440` | путешественник: продвинуться на расстояние |
| `0x4882A8` | положение внутри одной секции |
| `0x47ECD0` | выход из узла: выводы, стрелки, режимы |
| `0x48C85C` / `0x4F9550` | освобождение стрелки / зазор после хвоста при противошёрстном проходе |
| `0x47E26C` / `0x47E364` | путешественник по положению в мире |
| `0x4F5B34` | движение поезда: вагон, тележка, путешественники головы и хвоста |
| `0x47F214` / `0x48106C` | взгляд вперёд для элементов / `block_state` |

## Геометрия: tsection.dat

### CONFIRMED

- **Секции:**
  - `SectionSize (gauge length)` даёт прямую;
  - `SectionCurve (radius angle)` даёт дугу: `length = |angle| · π/180 ·
    radius`, угол хранится в радианах;
  - `SectionSkew (deg)` оставляет радиус 0 и даёт прямой угол;
  - собственные секции маршрута нумеруются после общих.
- **Модели:** `FileName`, `NumPaths`, `MainRoute`, `ClearanceDist`,
  `SectionIdx (n x y z deg s1..sn)`, флаги.
  - Ветка стрелки по умолчанию и выбранная изначально — `MainRoute` модели.
  - `ClearanceDist` — зазор для хвоста при противошёрстном проходе.
- **Положение в секции (`0x4882A8`).** В осях MSTS, как их использует
  openRTS; RTS работает с отрицательным X:
  - начало секции — (x, y, z) с тангажом `ax` и курсом `ay`; вперёд —
    `(sin ay, 0, cos ay)`;
  - дуга: `turn = angle · f` (доля f длины), вперёд `R·sin|turn|`, вбок
    `R·(1 − cos turn)` вправо при положительном угле;
  - высота: `y − sin(ax) · forward`;
  - курс в конце — `ay + turn`;
  - косая прямая: RTS тоже масштабирует угол косины на f.
- **Измерено** (секции одного узла, конец k к началу k+1): это соглашение
  даёт медиану 0,5–0,7 мм и p95 0,7–2,5 см на всех маршрутах. Остальные 7
  комбинаций знаков расходятся на метры.

## Топология: .tdb

### CONFIRMED

- **Векторные узлы:** на каждую секцию 16 значений — секция, модель, тайл
  мира x/z, uid в мире, два флага, шестнадцатеричная строка, тайл x/z,
  x y z, тангаж, курс, крен. RTS меняет знак x при загрузке.
- **Выводы векторного узла:** `TrPins (1 1)`: вывод 0 — начало узла,
  вывод 1 — его конец.
- **Стрелочный узел:** `TrJunctionNode (a shape b)`, `UiD (тайл мира x/z,
  uid в мире, флаг, тайл x/z, x y z, углы)` и `TrPins (1 2)` — сначала
  корень, затем ветки. У всех 555 стрелок Кубани ровно 2 ветки.
- **Направление вывода** (все выводы Кубани согласуются; совпадает с
  проверкой RTS в `0x47ECD0`):
  - вывод к векторному узлу: 1 = начало этого узла (вход вперёд), 0 = его
    конец (вход назад);
  - вывод к стрелке: 1 = её корень (противошёрстный проход), 0 = сторона
    ветки (пошёрстный проход).
- **Связи:** векторные узлы связаны только через стрелки и тупики
  (Кубань), а связи стрелок сходятся с концами векторов в пределах 0,1 мм
  (медиана).
- **Элементы:** `TrItemSData (смещение вдоль узла, флаги)`, `TrItemRData
  (x y z tile)` и блоки по типу (`TrSignalType (flags dir angle type)`,
  `TrSignalDirs`, `SpeedpostTrItemData`, имена платформ и стоянок).

## Путешественник и стрелки

### CONFIRMED (`0x481440`, `0x47ECD0`)

- **Состояние:** узел, номер секции, смещение в секции, смещение от начала
  узла, флаг направления и закэшированное положение.
- **Выход из узла:** RTS идёт по выводу и продолжает через стрелки, пока не
  дойдёт до векторного узла.
- **Противошёрстный проход** (вход в корень): идёт по выбранной ветке.
  - occupy (голова поезда): пометить стрелку занятой;
  - release (хвост поезда): записать для этого поезда зазор
    `ClearanceDist` (`0x4F9550`).
- **Пошёрстный проход** (вход с ветки k): всегда выход через корень.
  - occupy: **стрелка переводится на k** — взрез, без схода. Если стрелку
    держит другой поезд и задание проваливается при взрезе, задание
    проваливается (`0x41B4F4`);
  - release: снять флаг занятости, убрать этот поезд из списка
    бронирований и поставить стрелку на ветку следующего бронирования или
    по умолчанию (`0x48C85C`);
  - probe (взгляд вперёд): проход проваливается, если k — не выбранная
    ветка; `block_state` сообщает это как `BLOCK_JN_OBSTRUCTED`.
- **Тупик:** продвижение проваливается; вагон тогда сходит (`0x5059A8`),
  если сход не выключен.

### CONFIRMED (`0x47E364`) — путешественник по положению в мире

Для каждого векторного узла рядом с точкой (тайл ±1), секция за секцией:
- секция пробуется, только если её начало в пределах её длины + 0,1 м от
  точки;
- RTS берёт отсчёты по секции каждые **5 м** и берёт **первый** отсчёт в
  пределах допуска + 2,6 м;
- последняя секция перед тупиком пробует ещё и самый свой конец (−1 см).

`TrackNetwork::locate` в openRTS вместо этого возвращает ближайшую точку
(отсчёты через 2 м с уточнением).

### CONFIRMED (`0x47F214`, `0x48106C`)

Взгляд вперёд останавливается только на подходящем элементе или в тупике
и никогда не хранит посещённые узлы; про зависание на замкнутой петле см.
`signals.md`. openRTS ограничивает его расстоянием и посещёнными парами
(узел, направление).

### UNKNOWN

- **Кадр остряков в RTS:** как RTS сопоставляет состояние стрелки кадру
  остряков, не прослежено. Контент и снимки экрана поддерживают MainRoute =
  кадр 0, другая ветка = кадр 1 (см. `shape-animation.md`).
- **Два других числа в `TrJunctionNode`.**
- **Шестнадцатеричная строка в векторных секциях.**

## Измерения на установленных маршрутах (`openrts-track-check`)

| Маршрут | Векторных / стрелок / тупиков | Стыки медиана / p95 / максимум | Компонент |
|---|---|---|---|
| Chernyshevsk_RTS | 1626 / 973 / 333 | 0,5 мм / 1,0 см / 200 м | 11 |
| Kievskij_hod_RTS | 2960 / 1795 / 535 | 0,6 мм / 0,7 см / 65 м | 45 |
| Kuban_RTS | 921 / 555 / 177 | 0,7 мм / 1,7 см / 0,22 м | 5 |
| Novokuznetsk | 2248 / 1343 / 467 | 0,6 мм / 1,1 см / 0,23 м | 6 |
| Pavlovsk_RTS | 1780 / 1061 / 377 | 0,5 мм / 1,3 см / 0,32 м | 6 |
| TestRoute_RTS | 58 / 36 / 8 | 0,7 мм / 2,5 см / 0,16 м | 2 |
| Uspensk_RTS | 1234 / 724 / 297 | 0,6 мм / 1,2 см / 62 м | 62 |

- **Зазоры в десятки метров** — единичные дефекты в данных маршрута. Они
  появляются в списке «худших стыков» инструмента и не останавливают
  путешественника: следующую секцию выбирает топология.
- **На Uspensk_RTS** один висячий вывод (узел 1016 → 0), считается концом
  пути.
- **Концы секций против начала их `TrackObj`:** медиана ≤ 1 мм. p95 в
  2,5 м дают траектории стрелок, начинающиеся не в начале модели.
