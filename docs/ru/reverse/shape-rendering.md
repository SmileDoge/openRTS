# Отрисовка моделей RTS

> Перевод [`docs/reverse/shape-rendering.md`](../../reverse/shape-rendering.md).
> Основной текст — английский: при расхождении верен он.

Состояние: статический анализ `rts1.exe` (сборка 2021-08) в IDA плюс
исходники GLSL, которые RTS загружает из `GLOBAL/SHADERS`. Трассировки GL
во время работы не делалось. Реализовано в
`renderer/src/rts_material.cpp` и пути затенения RTS в
`renderer/src/model_renderer.cpp`.

Примечание: `GLOBAL/SHADERS/shape.*.shader` в этой установке датированы
2025-03-10 и добавляют карты нормалей (атрибуты касательных 5/6). exe
никогда не включает эти атрибуты, так что эта часть — местная правка и не
переносится.

## Имена шейдеров

### CONFIRMED

Значения uniform `NamedShader` (`0x45B1E0`, загрузчик моделей `0x43A944`):

| Имя | Значение |
|---|---:|
| `tex` | 1 |
| `texdiff` | 2 |
| `blendatex` | 3 |
| `blendatexdiff` | 4 |
| `gloss` | 5 |
| `addatex` | 6 |
| `addatexdiff` | 7 |
| всё остальное | 0 |

Загрузчик моделей распознаёт только 1..5; `addatex*` используется крупными
планами кабины и слоями окружения.

Имена фильтров текстур отображаются в фильтры GL:
`linearmiplinear`/`miplinear` → `LINEAR_MIPMAP_LINEAR`, `linear`,
`nearest`, `linearmipnearest`/`mipnearest` → `LINEAR_MIPMAP_NEAREST`,
`nearestmipnearest`, `nearestmiplinear`, иначе никакого. Значение
применяется и к фильтру MIN, и к MAG (MAG отклоняет значения с мип-уровнями).
Сдвиг LOD мип-уровней текстуры идёт в `GL_TEXTURE_LOD_BIAS`.

## Текстуры и мип-уровни — CONFIRMED (2026-11-02)

Загрузчик ACE (`0x44F554`) возвращает список уровней (`u32` число
текселей, ширина, высота, тексели RGBA8) и режим; загрузка в GPU
(`0x44150C`) создаёт текстуру с `GL_LINEAR_MIPMAP_LINEAR` (ставится для MIN
и MAG; MAG его отклоняет и остаётся линейным), `GL_REPEAT`,
`GL_GENERATE_MIPMAP` 0, а затем:

- параметры 17 или 21 (DXT1 с мип-уровнями): уровни из файла, загружаются
  через `glCompressedTexImage2D`;
- параметры ровно 5 (сырые каналы с мип-уровнями): уровни из файла,
  читаются по порядку после всей таблицы строк развёртки
  (`8 * height - 4` байт; смещения таблицы не используются), загружаются
  через `glTexImage2D` уровень за уровнем (постепенно, сначала меньшие,
  `GL_TEXTURE_BASE_LEVEL` следует за ними);
- всё остальное (параметры 0, 1, 13 …): только уровень 0, а остальные
  строит `gluBuild2DMipmaps` (усреднение 2x2).

Поэтому у каждой текстуры есть мип-уровни. Загрузчик выделяет полную
цепочку только для квадратных текстур. В этой установке (2685 файлов ACE
Kuban_RTS, ЭД9М и GLOBAL) у 1737 параметры 5, у 645 — 17 / 21, у остальных
0, 1 или 13; каждый квадратный файл с параметрами 5 содержит полную
цепочку, строки по порядку. Файлы DXT1 содержат уровни DXT1 до 4x4; их
записи 2x2 и 1x1 — не блоки DXT1 (`7carfloat.ace` кончается одним текселем
RGB).

openRTS (`formats::decode_ace_rgba`): уровни из файла по тому же правилу
для квадратных текстур (DXT1 до 4x4, последние два строятся из него), иначе
уровни строятся тем же усреднением; текстуры моделей, рельефа и неба
загружаются со своей цепочкой. Примитивы с фильтром `linear` или
`nearest` читают только базовый уровень, как это делает GL.

## Записи

### CONFIRMED

`prim_state` (44 байта): `+0` флаги, `+4` значение именованного шейдера,
`+8` номера текстур (≤2), `+16` сдвиг z (разбирается, отрисовкой не
используется), `+20` vtx_state, `+24` alpha_test_mode, `+28` light_cfg,
`+32` z_buf_mode, `+40` число текстур.

`vtx_state` (20 байт): `+0` флаги, `+4` матрица, `+8` материал освещения.

**Матрица 0 никогда не применяется** (CONFIRMED, 2026-11-11). `0x4AC5A4`
строит мировые матрицы узлов (модель `+88`, по 64 байта, только когда
матриц больше одной) через `0x4ACDF8`: для каждого узла — его матрица,
умноженная на матрицы родителей вверх по иерархии, пока номер больше 0, так
что матрица 0 и всё выше неё не входят ни в одну цепочку. Отрисовка
(`0x4B1664`, `0x4B042C`, `0x4ADA94`) умножает на матрицу примитива (или её
анимированную) только когда номер матрицы vtx_state не 0. TSRE5 рисует
модели так же. В установленном контенте у 765 моделей матрица 0 не
единичная (484 в маршрутах, 268 в GLOBAL, 13 в TRAINSET: интерьеры,
сдвинутые на 0,5–0,8 м, грузы); у `pineline6.s` «Киевского хода» MAIN —
(0, 13,5, 0) над деревьями от y 0. openRTS: `parse_binary_shape_model`
делает матрицу 0 единичной и без родителя (имя остаётся), и анимация её не
двигает (раньше полоса деревьев висела на 13,5 м над землёй).

Цвета вершин — сырые `u32` 0xAARRGGBB из записи вершины модели.

### PROBABLE

Вершина на GPU (48 байт, атрибуты 0..4: положение, нормаль, uv, colour1 @40,
colour2 @44, `GL_UNSIGNED_BYTE` без нормализации) несёт эти значения `u32`
как хранятся, поэтому шейдер видит байты в порядке B, G, R, A. Сам код
упаковки не найден.

## Состояние на каждый примитив (`0x4B042C`)

### CONFIRMED

- Флаги примитива (`0x4ABB28`): бит 0 = шейдер смешивания (3/4) с
  `alpha_test_mode == 0`; бит 1 = `z_buf_mode == 3`. Флаги модели = OR по
  всем prim_state.
- Шейдеры смешивания (3 / 4): `alpha_test_mode != 0` → `GL_BLEND`
  выключен, альфа-тест включён (`GL_GREATER 0.3`); иначе смешивание включено
  (`GL_SRC_ALPHA`, `GL_ONE_MINUS_SRC_ALPHA`), альфа-тест выключен. Каждый
  другой шейдер рисует с выключенными смешиванием и альфа-тестом
  (`0x4B0EDC`); между примитивами ничего не переносится. Последний аргумент
  функции, бит 0, оставляет альфа-тест таким, как его выставил вызывающий;
  проходы объектов вызывают её с 0 (`0x40BB90`). (Раньше здесь говорилось,
  что другие шейдеры наследуют состояние предыдущего примитива;
  дизассемблер говорит иное.)
- `z_buf_mode == 3` → запись глубины выключена для этого примитива.
- uniform `NamedShader` принудительно ставится в 3 (без освещения), когда
  материал освещения -11 (HalfBright), шейдер 1, 3 или 6, выставлен флаг
  prim_state `0x100`, выставлен флаг экземпляра `0x40` или сейчас ночь и у
  модели есть ночной флаг. Следовательно, собственная ветка HalfBright
  шейдера недостижима.
- `LightMatType` = материал освещения vtx_state.
- Нет текстуры → текстура 0 (чёрная). Не загрузившаяся текстура при
  `HideFailedTextures = 0` рисуется; текстура, которая ещё загружается,
  пропускает примитив.
- Шейдеры смешивания включают `GL_SAMPLE_ALPHA_TO_COVERAGE`, когда в
  `Antialiasing` настроек есть «+Alpha» (`byte_61D5D9`, `0x4B0E6A`, снова
  выключается после отрисовки в `0x4B154D`; то же в `0x4BEDA0`), до проверки
  альфа-теста: его получают и смешиваемые примитивы, и примитивы с
  альфа-тестом. Альфа текселя тогда — ещё и его покрытие, поэтому почти
  прозрачные тексели смешиваемого примитива не пишут ни цвет, ни глубину.
  На это рассчитана кабина ЭД9М: четырёхугольники теней стрелок (`ST_KVT`,
  `ST_TMT` …, `s.ace`, BlendATexDiff, альфа в основном < 10) лежат на
  0,4–0,8 мм перед наложением подсветки панели `PRIBL` (`cabyessv9M.ace`,
  дисплей LAMP); без покрытия их прозрачная часть пишет глубину, и `PRIBL`,
  нарисованный после `ST_KVT`, показывает дыру с неподсвеченной шкалой в
  ней.

Состояние вокруг отрисовки объектов: рельеф выключает смешивание и
альфа-тест и оставляет `glDepthFunc(GL_LEQUAL)`;
`glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)`.

## Проходы (`0x408574`)

### CONFIRMED

Объекты обходятся для `pass = -2..3` в порядке списка объектов; ничего не
сортируется. Байт прохода объекта: статические 1, transfer -2, dyntrack 0;
`0x4E0BFC` поднимает его до 2, когда у модели есть полупрозрачные примитивы
(вагоны всегда 2), `-1` / `0` для флагов экземпляра `0x40000` /
`0x200000`.

Фильтр примитивов по проходу: 1 → модели с любыми флагами рисуют только
примитивы без флагов; 2 → только полупрозрачные примитивы; -1 → пропустить
полупрозрачные; 0 → только примитивы без записи глубины; -2, 3 → все.

Поэтому несмешиваемый примитив `z_buf_mode 3` обычного статического
объекта никогда не рисуется.

**CONFIRMED** (2026-11-02, `0x41B6D0`, `0x4E0BFC`, `0x408574`, `0x4B042C`):
- Флаги экземпляра — это `StaticFlags` объекта мира (шестнадцатеричное,
  объект `+56`). `0x4E0BFC` ставит байт прохода: 2, когда у модели есть
  полупрозрачный примитив, затем -1 для `0x40000` и 0 для `0x200000`, в
  этом порядке (побеждает последнее). По именам OpenRails эти биты —
  Terrain и Global; на установленных маршрутах Global стоит примерно на
  80 000 объектах (`00200180`, модели пути), а Terrain — примерно на 9 000.
- Проход 1 посещает объекты с байтами прохода 0, 1 и 2; проходы -2, -1, 0 и
  3 — только свои; проход 2 — только 2. Поэтому объект Terrain рисуется
  только в проходе -1, а его полупрозрачные примитивы — никогда; объект
  Global рисует свои примитивы без глубины в проходе 0, обычные — в проходе
  1 и ничего в проходе 2.
- Фильтр примитивов (`0x4B042C`, аргумент байта прохода): -1 пропускает
  полупрозрачные примитивы; 0 оставляет только `z_buf_mode 3`; 1 для модели
  с любым помеченным примитивом оставляет только обычные; 2 оставляет
  полупрозрачные, но не те, что ещё и пропускают глубину на объекте Global;
  -2 и 3 оставляют все.
- Transfer (мировой `Transfer`: `FileName` текстуры, `Width` / `Height`, по
  умолчанию 100 м) строятся `0x4B4E60` как отдельная модель с байтом
  прохода -2: сетка на рельефе с ячейками 4 м (если шире 100 м — ячейки по
  4 % ширины, `(int)(4 * 0.01 * Width)`), та же ячейка поперёк; каждая
  вершина на высоте рельефа под ней (`0x49CD24`) минус высота объекта;
  нормали вверх, цвета белые; u вдоль x от западного края, v от северного;
  BlendATexDiff, альфа-тест 0, `z_buf_mode` 1, материал освещения -5;
  текстура из `TEXTURES` маршрута через `0x4224F8` со значением 1 (`SNOW`
  зимой), `LINEAR_MIPMAP_LINEAR` со сдвигом мип-уровней -3; два уровня
  дальности: сетка до 300 м и один четырёхугольник по углам до 2000 м. RTS
  берёт высоты рельефа с одной диагональю на ячейку (не нарисованной
  шахматной) и сдаётся (высота 0) вне тайла объекта.
- Цикл огней (огни поездов, огни сигналов; `0x449818`) идёт внутри цикла
  проходов после прохода 2 (после карт теней RTS) и до прохода 3: огни
  рисуются после стекла и до кабины.

openRTS: `rts::object_pass` / `rts::visits` / `rts::draws_in_pass`,
`StaticFlags` экземпляра задаёт `ModelRenderer::set_world_object`; путь RTS
рисует проходы -2..3 в этом порядке. Transfer загружаются как модели с
именем `<world file>.<UiD>.transfer` (`renderer/src/transfer_shape.cpp`).
Сетка RTS пересекает треугольники рельефа, поэтому между своими вершинами
она уходила под землю или висела над ней, и они мерцали: треугольники земли
проступали пятнами (Новокузнецк, 2026-11-09). openRTS вместо этого режет
прямоугольник по собственным треугольникам рельефа (отсчёты 8 м, шахматные
диагонали, через края тайлов), так что каждый кусок лежит в плоскости своего
треугольника. Куски рисуются на любой дальности до 2000 м и на десятитысячную
долю расстояния ближе (`GpuInstance::decal`, обратный Z), чтобы перекрыть
остаток от округления двух преобразований. Свечения поездов
и сигналов рисуются после прохода полупрозрачных и до кабины, накладываясь
по своей альфе (`GlowBlend::over`).

**CONFIRMED** кабина (2026-11-02): объект кабины (`dword_61D68C + 208`)
получает байт прохода 3 в видах из кабины (`0x438D50`; 2 в виде 4), поэтому
рисуется после всех остальных объектов, все её примитивы в порядке модели
за один проход (проход 3 ничего не отфильтровывает), включая
`z_buf_mode 3`. Её отрисовка — тот же `0x4B042C` (`0x40BB90`, флаги 0).
openRTS: `ObjectPass::last` для кабины, в обоих путях затенения
(экспериментальный путь тоже не сортирует смешиваемые примитивы кабины).

**CONFIRMED** флаг состояния узла 0x01 (не рисуется) исключает только
собственные примитивы узла, его потомки по-прежнему видны (тот же поиск);
RTS ставит его для узла негорящей лампы (`0x514630`) и погасшего огня кабинного сигнала (`0x525DB0`). openRTS:
`NodeAdjustment::hidden` для этих двух; переключатель KEY кабины с
вынутым ключом и дисплей LAMP без ключей анимации по-прежнему скрывают свои
узлы вместе с потомками (как их скрывает RTS, не прослежено).

**PROBABLE** у текстур свечения огней (`LightTex`, огни сигналов) и экранов
кабины есть мип-уровни, как у каждой текстуры RTS (цикл свечения
`0x408574` оставляет `GL_LINEAR_MIPMAP_LINEAR` загрузчика); openRTS строит
им мип-уровни.

**CONFIRMED** флаг состояния узла 0x40 (без освещения) у узла горящей лампы
`SOURCE_VISIBLE` (`0x514630`) действует только на собственные примитивы
этого узла (состояние ищется по матрице примитива, `0x4B042C`). openRTS:
`NodeAdjustment::unlit`, рисуется с неосвещаемым материалом, как ночной
бит.

## Освещение

### CONFIRMED

`Light[0]` (std140, 192 байта на источник): `Diffuse`/`Ambient` из цветов
окружения, `Direction = (sin az·cos el, −sin el, −cos az·cos el)`,
`Type.x` = число дальнейших источников. Рассеянный цвет поднимается
покомпонентно до `world_environment_ambient_light` окружения (по умолчанию:
`DefaultAmbientLight` из настроек). Light[0] управляется временем суток, см.
`sky.md`. Дальнейшие источники (`Light[1..]`) — источники света транспорта и
сцены, в десяти кольцах вокруг камеры (ниже, «Кольца света»).

## Кольца света — CONFIRMED (2026-11-02)

Каждый кадр дальнейшие источники идут в десять UBO (`off_5E0494`,
`dword_5E03D0` = 10), в каждом `Shader.NumLights` источников (в
установке 10: сначала солнце, затем девять), его `Light[0].Type.x` — число
дальнейших:

- Кольцо k с центром в (k + 1) * L / 10 от камеры, простирается на L / 10 в
  каждую сторону, L = `MaxLightDistance` (`ViewDistance`, когда он 0, по
  умолчанию; `0x408574`). Источник, чья досягаемость (сфера) перекрывает
  кольцо, попадает в него: |центр - расстояние| <= досягаемость + L / 10.
- Сначала огни поездов (`0x4AF7D4`, досягаемость — их собственная), затем
  огни окружения (`0x4B009C`). Полное кольцо отдаёт место своего самого
  дальнего источника более близкому; более дальний остаётся снаружи.
- Лампы окружения (`ESD_LightSources`, записи по 140 байт в +108 модели,
  `0x408574`): обновляются (`0x4B0284`), только пока объект в пределах L и,
  если у лампы есть `Distance`, в его пределах. Горящая лампа попадает в
  кольцо, когда её сфера в пирамиде вида; сфера — её `Position` и
  (max(rX, rZ) + `LightFade`) * max(1.1, start + length + 0.1)
  (`LightFade`, прибавленный к радиусу, sic).
- Объект берёт кольцо floor((distance - radius) / (`ViewDistance` / 10)),
  кольцо 0, когда это не положительно или когда в кольце 0 нет ни одного
  источника, последнее кольцо — за пределами (`0x4B042C`, по его
  ограничивающей сфере; участки рельефа так же, `0x4A2AD4`). Два шага
  различаются (40 м и 130 м при установленных настройках), поэтому объект
  видит только источники полосы ближе к камере: лампы дальше примерно
  100 м ничего не освещают.

openRTS: `renderer::LightRings`, то же правило для моделей и участков
рельефа, в обоих путях затенения (экспериментальный путь может позже
получить свой отбор).

## Фонарик — CONFIRMED (2026-11-08)

- Num2 (`WM_KEYDOWN` 0x62, `0x403068`) переключает `[0x61D55D]`; новая
  игра его сбрасывает (`0x4044B9`).
- Пока он включён (и свет GL работает, `[0x5E04C6]`), каждый кадр
  (`0x409A2C`) запись в `0x5E03D4` (огонь на 192 байта, `GLLightObj`
  шейдеров) копируется в огни кадра первой и в кольца, которые накрывает
  её дальность; она ставится в глаз и поворачивается по рысканию и тангажу
  камеры: прожектор по взгляду.
- Запись (умолчания `0x405F15`): цвет 0,643 / 0,4745 / 0,1725 / 1, размер
  0,436 / 0,233 / 50 (x, y, дальность) и 0, тип 1, показатель пятна 90,
  затухание 2 / 0,2 / 0,8. Их переопределяют `flashlight.type`, `.colour`
  (ARGB в hex), `.radx`, `.rady`, `.radz`, `.attenuation` (`0x4070FB`); ни
  в одном установленном файле их нет.
- openRTS: `RouteScene::collect_lights`, Num2 (клавиши RTS) или Shift+`
  (клавиши openRTS).

## Затухание ламп — CONFIRMED (2026-11-02, `0x4B0284`, `0x51C364`, `0x4AEBEC`)

`LightFade ( a b )` разбирается в запись лампы (`+44` a, `+48` b);
используется только `a`, одинаково для разгорания и угасания. Каждое
обновление сдвигает уровень (`+52`) на шаг времени, делённый на `a`, к 1,
пока лампа горит, и к 0, когда нет (биты: 1 разгорается, 2 угасает, 4
горит полностью); `a` = 0 переключает сразу. Лампы окружения шагает функция
кадра `0x408574` с миллисекундами главного цикла (прижатыми к 8..1000 мс),
поэтому их `LightFade` — в миллисекундах; лампы кабины или салона
(`0x514630`) получают секунды. Запись принадлежит модели: каждый её
экземпляр в пределах досягаемости шагает её снова. Лампа попадает в кольцо,
пока горит или затухает; её цвет идёт в шейдер (`0x4AEBEC`) как красный ×
уровень, зелёный × уровень дважды, синий без масштаба, альфа × уровень
(sic). Ни у одной установленной лампы окружения нет `LightFade`; у ламп
кабин в основном `( 0.1 0.0 )`.

openRTS: лампы окружения как выше (путь RTS упаковывает цвет как RTS,
экспериментальный масштабирует его); лампы кабины затухают в обе стороны по
первому значению (раньше они гасли по второму, сразу).

## Ещё не перенесено

Динамический путь (проход 0): ни на одном установленном маршруте его нет.

## Уровни дальности (openRTS, 2026-11-01)

Модели несут несколько уровней дальности (`dlevel_selection` на уровень:
головы сигналов TestRoute 100 / 250 / 500 / 2000 м, ВЛ10к 300 … 2000 м),
каждый — более простая сетка. openRTS загружает все уровни первого
`lod_control` и рисует на каждый экземпляр первый уровень, чьё расстояние
выбора достигает расстояния камеры до центра модели, иначе последний. RTS
рисует уровень, который объект держит в +104 (`0x4B1664`); где RTS его
выбирает (другой поток, расстояние, угол обзора или сдвиг LOD), не
прослежено, поэтому правило — как в MSTS — PROBABLE. Иерархия первого
уровня используется для всех уровней.

Текстовые модели (`JINX0s1t`, переводимые в двоичные токены) до 2026-11-12
теряли `dlevel_selection`: блока не было в таблице перевода, поэтому каждый
уровень читался как 0 м, и на любом расстоянии рисовался самый грубый. В
новой установке это 318 из 2201 текстовой модели с двумя уровнями и более,
среди них опоры контактной сети Кубани `g2wide2.S` / `g2grass2.S` (600 м:
опоры, кронштейны и провода; 1100 м: одни опоры), поэтому линия была с
голыми опорами без проводов, а также тоннели, двойной перекрёстный перевод
и светофоры из `GLOBAL\SHAPES`. `openrts_asset_dump --kind shape` теперь
читает и текстовые модели и печатает дальности уровней.

## Формат выходного цвета

RTS рисует в обычный кадровый буфер GL: выходы шейдеров идут на экран как
есть. Вьювер выбирает формат поверхности без sRGB (BGRA8 / RGBA8 Unorm);
поверхность sRGB, которую Vulkan на NVIDIA предлагает первой, кодирует
значения ещё раз и делала всю картинку ярче, чем в RTS.

## Сглаживание и анизотропия

В установленных настройках RTS `Antialiasing = 4x MSAA +Alpha` и
`Anisotropy = 16`. **CONFIRMED** `Antialiasing` (читается в `0x405D2C`,
разбирается `0x4BD624` в `0x61D5D0`): число в начале — число отсчётов;
режим (`0x61D5D8`) 1 MSAA, 2, когда в значении есть «csaa» (4 отсчёта
покрытия, 8 с «xq»), 3 с «fxaa»; «+alpha» ставит `0x61D5D9`,
alpha-to-coverage для шейдеров смешивания (выше). `GL_MULTISAMPLE`
включён для режимов 1 и 2. openRTS: 4x MSAA по умолчанию (`--msaa 1|2|4|8`; 2 и 8 — если устройство
их поддерживает, иначе 4),
alpha-to-coverage на каждом конвейере шейдеров смешивания (с альфа-тестом
или смешиванием) при мультисэмплинге и 16x анизотропная фильтрация на
сэмплерах, у которых фильтры min, mag и mip все линейные (модели,
рельеф).

## Отсечение граней — CONFIRMED (2026-11-01)

- `create_game_window` (`0x40564D`) один раз включает `GL_CULL_FACE`; RTS
  никогда не вызывает `glFrontFace` или `glCullFace`, поэтому действуют
  умолчания OpenGL: треугольники против часовой стрелки — лицевые,
  обратные грани отсекаются.
- Отсечение выключается только вокруг прохода карт теней (`0x47BEB0`,
  `0x47C5DC`), одного текстурированного наложения (`0x456E8C`) и шейдерных
  эффектов (`0x4BEDA0`, `0x4BF3F8`, `0x4BF878`) и после каждого включается
  обратно; модели (`draw_elements_1`) всегда рисуются с отсечением обратных
  граней.
- openRTS: конвейеры моделей отсекают обратные грани с лицевой стороной
  **по часовой стрелке**. С лицевой стороной против часовой стрелки
  (рассуждение «по одному отражению X в каждом, ccw у wgpu — это ccw у
  OpenGL») видимые грани во вьювере отсекались, поэтому грани, которые
  показывает RTS, здесь выходят на экране по часовой стрелке; причина
  (RTS переставляет индексы при загрузке или соглашение wgpu) не
  прослежена — UNKNOWN. Без отсечения совпадающие лицевые и обратные грани
  двусторонних частей (задняя пластина головы сигнала) боролись по
  глубине. Пункт панели вьювера «Cull back faces (RTS)» выключает его для
  сравнения.

## Ночные и сезонные текстуры, лампы окружения (openRTS, 2026-11-02)

- `ESD_Alternative_Texture ( value )` в .sd модели берёт картинку из
  подпапки той папки, где она нашлась (Kuban_RTS: `TEXTURES\NIGHT`, `SNOW`,
  `WINTER`, `WINTERSNOW`). **CONFIRMED** (`0x4224F8`, ветвление по всему
  значению): 0 — нет; 252 — по сезону: `WINTERSNOW\` / `WINTER\`,
  `AUTUMNSNOW\` / `AUTUMN\`, `SPRINGSNOW\` / `SPRING\` (идёт снег / нет),
  летом нет; 256 — `NIGHT\` ночью; 257 — `NIGHT\` ночью, иначе `SNOW\`;
  любое другое значение — `SNOW\`. `SNOW\`: зимой или когда идёт снег вне
  лета (сезон `byte_61D62C`, погода `byte_61D62D`). Одна папка, после неё
  имя файла картинки. Когда меняется ночь, `0x42288C` перезагружает
  текстуры каждой модели с её флагом (+115 бит 0) из `NIGHT\` + имя или
  обратно. Картинки там нет: openRTS берёт обычную (загрузчик RTS
  `0x439DE8` только записывает путь; промах не прослежен). Ночь — небесная
  (первый спутник вне своего времени восхода / заката, sky.md). RTS
  перезагружает текстуры маршрута при её смене (`is_night`); openRTS
  перезагружает в рабочем потоке модели, чьи папки меняются
  (`ModelLibrary::set_texture_variant`), а модели, подгруженные при другом
  варианте, — по прибытии.
- **CONFIRMED** (`0x4B042C`, отрисовка модели): примитив рисуется без
  освещения (`glDisable(GL_LIGHTING)`, а с шейдерами `NamedShader`
  ставится в 3, чья ветка в `shape.vert` берёт Ambient 1), когда сейчас ночь
  и у его модели есть ночной бит (`ESD_Alternative_Texture` 0x100: 256, 257)
  — каждый примитив модели, какой бы ни была его текстура, — или его
  материал освещения HalfBright (-11), или его шейдер 1 / 3 / 6, или в
  флагах его `prim_state` есть бит 0x100, или у состояния его узла в
  экземпляре есть флаг 0x40. Поэтому `Fon_Rostov.s` на Кубани показывает
  свой ночной город в полную яркость, а HalfBright в RTS — полная яркость.
  Проход теней (`0x4B1664`, флаг 0x10) исключает те же примитивы.
  - **CONFIRMED** флаги `prim_state`: первое поле `prim_state` в .s,
    читается как шестнадцатеричное (`0x43A944`, `wcstoul(.., 16)`);
    больше ничто его не ставит. Бит 0x100 рисует примитив без освещения. Ни
    одна модель этой установки его не ставит (Kuban_RTS, GLOBAL\SHAPES: 9706
    моделей, ЭД9М и его кабины: у каждого `prim_state` флаги 0;
    `train-check --prim-flags <папка>`).
  - **CONFIRMED** флаги состояния узла (на экземпляр, 120 байт на узел,
    ищется по матрице узла): 0x01 / 0x20 не рисуется, 0x80 свой цвет
    (`glColor4fv`), 0x40 рисуется без освещения. 0x40 и 0x01 ставят
    обновления ламп (`0x514630` для 136-байтовых `InternalLight` кабин и
    салонов, `0x526EC0` аналогично) на узле, названном как лампа: лампа с
    `SOURCE_VISIBLE` сохраняет свой узел и рисует его без освещения, пока
    горит (0x40); без него узел виден, только пока лампа горит (0x01, когда
    выключена).
- **CONFIRMED** источники света (`0x4B0284`: `InternalLight` окружения и
  кабин; `0x526EC0`: лампы собственного .sd кабины): `RUNNING` горит
  (`0x4B0284` ставит по нему состояние «горит»; его ставит `SwitchLight`
  DLL); `NIGHT_AUTO` горит ночью или, с `AutoWhenWorldLit` (+88, > 0), пока
  мир освещён не больше этого: `dword_61D60C`, рассеянный и прямой цвета
  солнца, красный, зелёный и синий, усреднённые по шести, до подъёма
  рассеянного (`0x408C19`); `NIGHT_ONLY` никогда не горит днём; лампа без
  всех этих флагов не горит. У `0x526EC0` нет `AutoWhenWorldLit`. openRTS:
  лампы окружения по этому правилу (`SkyState::world_lit`). Старая заметка
  ниже:
- Источники света (`0x4B0284`, `0x526EC0`): `NIGHT_ONLY` выключен днём;
  `NIGHT_AUTO` включён ночью или когда значение темноты (`dword_61D60C`) не
  больше порога источника (+88), если он есть.
- `ESD_LightSources ( n LightSource ( Position PointsTo Radius ( rX rZ )
  Colour Flags Distance Attenuation ( start length kind ) SpotExponent ) )`:
  лампа окружения (Kuban_RTS: 21 модель фонарей и платформ, `NIGHT_AUTO
  LIGHT_CONE`). openRTS освещает ей сцену через дальнейшие источники
  шейдеров (lights.glsl; модели и рельеф): z пространства источника к
  PointsTo, конус, расходящийся на rX / rZ в плоскости PointsTo (`Size` =
  rX / досягаемость), сфера или коробка, берущие их как полуразмеры —
  **PROBABLE**. `LightArray ( n dx dy dz )`: ряд из n ламп, каждая сдвинута
  от предыдущей на (dx, dy, dz) в пространстве модели; lights.glsl RTS
  освещает каждую точку ближайшей лампой ряда (число и шаг массива у
  источника). У платформы Новокузнецка `platf_fonar_9.s` два ряда, 4 и 5
  ламп через 50,118 м: девять ламп. До 2026-11-08 openRTS не читал
  `LightArray`, и ряд светил только первой лампой (там две из девяти);
  теперь путь RTS упаковывает ряд как один источник, как RTS, а
  экспериментальный путь — каждую лампу отдельным источником (кластеры и
  тени у каждой лампы свои). Лампы `NIGHT_AUTO` / `NIGHT_ONLY` горят только ночью
  (справочник файлов RTS), в пределах `Distance` и `MaxLightDistance` (400)
  из настроек RTS от камеры (устарело: см. «Кольца света»). Какие из многих
  источников RTS даёт каждому объекту — **UNKNOWN** (Shader.NumLights 10,
  сначала солнце): openRTS берёт лучи поезда и ближайшие к камере лампы,
  всего девять, на весь кадр.
