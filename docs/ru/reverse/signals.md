# Сигнализация RTS: sigcfg.dat, sigscr.dat и машина сигналов

> Перевод [`docs/reverse/signals.md`](../../reverse/signals.md). Основной
> текст — английский: при расхождении верен он.

Состояние: статический анализ `rts1.exe` (Hex-Rays), обзор файлов
`sigscr.dat`/`sigcfg.dat` 7 установленных маршрутов и вывода компилятора
RTS (`sigscr.dat.asm` TestRoute_RTS). Подробности, которым следует openRTS, —
в разделе «Компилятор, машина и вычисление подробно» в конце.

| Адрес | Роль |

| `0x482680` | `TrItemTable` TDB (`SignalItem`, `TrSignalDirs`, знаки скорости, ...) |
| `0x496DB0` | загружает один файл скриптов, делит его по `SCRIPT`, компилирует каждый скрипт |
| `0x497ED8` | компилятор операторов (исходник → текстовый ассемблер) |
| `0x45911C` / `0x497334` / `0x497E14` | разбивка выражений на токены / генератор кода |
| `0x498964`, `0x499664` | ассемблер (текстовый ассемблер → байткод из dword), декодер операндов |
| `0x499948` | интерпретатор байткода: вычисляет одну голову сигнала |
| `0x49ACB0` | операнд → хранилище (локальная / поле головы / непосредственное / регистр) |
| `0x48106C` | `block_state()` |
| `0x480CCC` | `route_set()` |
| `0x479AFC` | обновление головы на каждом кадре: свободный прогон скрипта, огни, мигание |
| `0x508520` | вычисление сигналов впереди/позади поезда на каждый поезд |
| `0x5C09BC`, `0x5BD8FC` | исходы задания `SetSignalMode`, `SignalOverride` |
| `0x41B4F4` | провал задания «проезд красного / запрещающего сигнала» |

## Модель данных

### CONFIRMED

- `sigcfg.dat` (UTF-16, `SIMISA@@@@@@@@@@JINX0G0t______`), обрабатываемые
  ключевые слова: `LightTextures/LightTex`, `LightsTab/colour`,
  `SignalTypes/SignalType`, `SignalFnType`, `SignalLightTex`, `SignalFlags`
  (`SEMAPHORE`), `SemaphoreInfo`, `SignalLights/SignalLight/Position/Radius`,
  `SignalDrawStates/SignalDrawState/DrawLights/DrawLight`
  (+ `SignalFlags(FLASHING)`), `SemaphorePos`, `SignalAspects/SignalAspect`
  (+ `SpeedMPH`/`SpeedKPH`), `SigFlashDuration(on off)` (секунды),
  `SignalShapes/SignalShape/SignalSubObjs/SignalSubObj` (`SIGNAL_HEAD`,
  `DECOR`, `NUMBER_PLATE`, `USERn`, `SignalFlags`), `ScriptFiles/ScriptFile`
  (путь относительно маршрута). Там же читается `RTS_ShuntingAutoMode`.
- Имена показаний (`0x45B290`): STOP 0, STOP_AND_PROCEED 1, RESTRICTING 2,
  APPROACH_1 3, APPROACH_2 4, APPROACH_3 5, CLEAR_1 6, CLEAR_2 7,
  BLOCK_OBSTRUCTED 8, FAILED 9. Больше номер — менее запрещающее.
- `SignalFnType`: NORMAL 1, SHUNTING 2, DISTANCE 3, REPEATER 4, INFO 5
  (нумерация отличается от документации MSTS/Open Rails; используйте эти
  значения).
- Мировой объект `Signal` содержит несколько *голов*; каждая голова
  связана с `SignalItem` в TDB и имеет поля, которые видит скрипт:

  | Смещение в голове | Имя в скрипте |
  |---|---|
  | +84 | `state` (показание) |
  | +88 | `draw_state` |
  | +96 | `enabled` |
  | +100 | ограничение скорости показания (м/с, −1 = нет) |
  | +104 | `signal_mode` (RTS) |

- Мигание: огонь состояния отрисовки с `FLASHING` горит, пока таймер
  головы ниже `on`; таймер заворачивается на `on + off` (`0x479AFC`).

## Язык `sigscr.dat`

Это язык сигнальных скриптов MSTS: синтаксис, похожий на C, каждое
значение — `float`, по одному разделу `SCRIPT <SignalTypeName>` на тип
сигнала (сопоставляется без учёта регистра; о скрипте для неизвестного типа
сообщается, второй скрипт для того же типа — ошибка). Файл читается как
ANSI (кодовая страница системы).

RTS не интерпретирует исходник. Он компилирует каждый скрипт в текстовый
ассемблер для небольшой регистровой машины, а затем в байткод из dword.
`SignalScriptsGenerateAsm = 1` в `[TSconfig]` настроек RTS пишет текстовый
ассемблер в `<script file>.asm`. Это путь скрипта с дописанным `.asm`,
например `ROUTES/<route>/sigscr.dat.asm`, UTF-16 LE без BOM,
перезаписывается при загрузке маршрута (`0x496DB0`) — CONFIRMED. Это самый
простой способ увидеть, что RTS сделал из скрипта.

### Лексический разбор (CONFIRMED)

- `//` до конца строки и `/* */` затираются. `/*RTS# ... */` — **код только
  для RTS**: метки убираются, а тело компилируется, тогда как MSTS/Open
  Rails видят комментарий. Ни один установленный маршрут им не пользуется.
- Именованные константы заменяются текстуально до компиляции, дополненные
  пробелами, чтобы смещения не менялись:

  | Имя | Значение |
  |---|---|
  | `SIGASP_STOP` … `SIGASP_CLEAR_2` | 0 … 7 (как выше) |
  | `SIGFN_NORMAL/SHUNTING/DISTANCE/REPEATER/INFO` | 1/2/3/4/5 |
  | `BLOCK_CLEAR/OCCUPIED/JN_OBSTRUCTED` | 0/1/2 |
  | `SIGFEAT_USERn` | n |
  | `SIGFEAT_NUMBER_PLATE`, `SIGFEAT_GRADIENT_PLATE` | 32, 33 |
  | `SIGMODE_NORMAL/SHUNT/FAILED/EXCL` (RTS) | 0/1/2/3 |

### Операторы (CONFIRMED)

- `extern float name;` / `extern float name ();` объявляют встроенные;
  `float name;` объявляет локальную. Локальные начинают с 0 на каждом
  прогоне.
- `x = expr;` присваивание; голый оператор-выражение `call (...);`.
- `if (cond) stmt [else stmt]`, с блоками `{ }`; цепочки `else if`
  работают.
- `return;` (`RET`).
- Нет циклов, пользовательских функций, `switch`.

### Выражения

Распознаваемые операции (`0x45911C`). Столбец приоритета — собственное
число силы связывания RTS:

| Операция | Смысл | Приоритет | Опкод |
|---|---|---|---|
| `==# !=# ># >=# <# <=#` | сравнение как целых (обе стороны усекаются к 0) | 2 | `CMPE`… |
| `== != > >= < <=` | сравнение как float | 2 | `CMPEF`… |
| `&&`, `\|\|` | логические и/или (любое ненулевое = истина, результат 0/1) | 1 | `AND`, `OR` |
| `=` | присваивание | 0 | `MOV` |
| `!x` | логическое не | 3 | `NOT` |
| `-x` | смена знака | 3 | `NEG` |
| `#x` | округление до ближайшего целого (половина вверх) | 3 | `ROUND` |

- CONFIRMED: **нет арифметических бинарных операций** (`+ * /` — не
  токены, а `-` всегда унарный).
- CONFIRMED: у `&&` и `||` **одинаковый** приоритет.
- PROBABLE: операции равного приоритета применяются слева направо, поэтому
  `a || b && c` означает `(a || b) && c`, а не `a || (b && c)`, как в C.
  Скрипты в установленных маршрутах всегда ставят скобки.
- CONFIRMED: у `^` (XOR) есть опкод, но разбивка на токены никогда не
  принимает `^`, так что им нельзя пользоваться.
- CONFIRMED: сокращённого вычисления нет. Каждый вызов в условии
  выполняется.

### Виртуальная машина (CONFIRMED)

- 8 регистров float `AX`…`HX`. Операнды — локальные, поля головы (`state`,
  `draw_state`, `enabled`, `signal_mode`), регистры или непосредственные
  значения.
- 30 опкодов. Управление потоком — `JZ` (переход, если `AX` равен нулю),
  `JMP` и `RET`. Вызовы встроенных используют `PUSH` (аргумент) и `CALL`.

### Встроенные

| Имя | Результат |
|---|---|
| `block_state()` | идёт по пути от головы до следующего сигнала своего типа или сигнала NORMAL: 0 свободно, 1 занято поездом, 2 стрелка выставлена против маршрута |
| `route_set()` | 1, если связанные с головой стрелки (`TrSignalDirs` / `JN_LINK`) выставлены для неё |
| `next_sig_lr(fn)` | наименее запрещающее показание голов типа `fn` на следующем объекте сигнала этого типа по маршруту поезда; 0 (STOP), если нет |
| `next_sig_mr(fn)` | то же, наиболее запрещающее |
| `def_draw_state(asp)` | состояние отрисовки из `SignalAspect`; также ставит ограничение скорости головы по этому показанию |
| `sig_feature(f)` | 1, если у модели есть подобъект `USERn` / номерная табличка (32) / табличка уклона (33) |
| `dist_multi_sig_mr(fn, ...)` | наиболее запрещающее показание по перечисленным типам на первом объекте впереди, где оно есть; 0, если нет |
| `this_sig_mr(fn)` | наиболее запрещающая голова типа `fn`, стоящая *до* этой головы на том же объекте; 0, если нет, −1 вне цепочки поезда |
| `this_sig_lr(fn)` | наименее запрещающая другая голова типа `fn` на том же объекте, −1, если нет |
| `state`, `draw_state` | выходы головы |
| `enabled` | ненулевое, когда маршрут поезда забронирован через сигнал |
| `signal_mode` | (RTS) 0 обычный, 1 маневровый, 2 неисправен, 3 исключён |

В установленных маршрутах встречаются только `block_state`, `route_set`,
`next_sig_lr/mr`, `def_draw_state`, `sig_feature`, `enabled`, `state` и
`draw_state`. В установленных маршрутах по 168–308 скриптов, всего около
2100.

## Когда выполняются скрипты

### CONFIRMED

- **На каждый поезд** (`0x508520`): RTS собирает до 16 объектов сигналов
  по маршруту поезда. Он продолжает, пока не увидит
  `SignalNumClearAhead` первого сигнала NORMAL + 2 сигнала NORMAL. Объекты
  вычисляются от самого дальнего к ближайшему, поэтому `next_sig_*` читает
  показания, обновлённые в том же проходе. `enabled` ставится, пока
  работает скрипт, и снимается после. Сигнал, к которому не приближается
  поезд, выполняет свой скрипт без цепочки, поэтому `next_sig_*` там
  возвращает STOP.
- **Наблюдалось в RTS (2026-11-01, Kuban_RTS, ЗИП, M10 = UiD 12924, тип
  INFO `T_Head_WB-new`), сравнено пользователем с openRTS:**
  - его скрипт (первый из двух для типа; RTS: «Multiple signal scripts for
    %s, only first one is used») показывает белый, когда `next_sig_*` даёт
    STOP или блок-участок занят, иначе синий;
  - при приближении поезда игрока: синий; при проезде: белый (позади
    головы, свободный прогон); немного отъехав назад: **снова синий, и
    остаётся синим** при движении вперёд или назад;
  - openRTS показывал белый после отъезда назад: он строил только цепочку
    впереди того конца, к которому поезд двигался последним. Исправлено по
    правилу ниже; пользователь снова проверил M10 в openRTS, и теперь он
    ведёт себя как в RTS.
- **Оба конца для поезда игрока (CONFIRMED, `0x508520`):**
  - проход головы (от путешественника головы `train+0xA8`) выполняется,
    когда `speed (+92) > 0`, или тип поезда 1 или 4, или бит флага `+4`
    0x80 сброшен;
  - проход хвоста (от `train+0xE8`, назад) выполняется, когда
    `speed < 0`, или тип 1 или 4, или этот бит выставлен;
  - поэтому у поезда игрока (тип 1; 4 PROBABLE — удалённый игрок)
    сигналы впереди обоих концов вычисляются каждый кадр, и стоя тоже;
  - UNKNOWN: что такое бит 0x80 в `+4`. openRTS держит другие поезда на
    том конце, к которому они двигались последним.
- **Показание, которому подчиняется поезд**: наименее запрещающее по
  головам NORMAL объекта. Флаги поезда `obey_distance`, `obey_shunting` и
  `obey_info` добавляют головы этого типа. Ограничение скорости —
  наименьшая скорость показания среди них.
- **Режимы** (RTS):
  - головы FAILED/EXCL пропускают скрипт; показание и состояние отрисовки
    берутся из `SignalOverride`.
  - В режиме SHUNT показания 3..7 принудительно становятся RESTRICTING, если
    не выставлен `RTS_ShuntingAutoMode`.
  - Режим, который назначает скрипт, распространяется по цепочке вперёд.
- **Управление из задания**: `SignalOverride(Position, SignalMode,
  SetAspect(head asp), SetDrawState(head ds), SetSpeedLimit, Cancel)`
  заменяет результат скрипта; `SetSignalMode` меняет режим для поезда.

### PROBABLE

- В маневровом режиме `block_state()` при проверке занятости пропускает
  некоторые поезда (флаг внутри записи поезда).
- `route_set()` возвращает ненулевое, как только проход доходит до
  следующего сигнала со всеми связанными стрелками в нужном положении.

## Взгляд вперёд на замкнутых петлях

### CONFIRMED (чтение кода, не запускалось)

- **`0x47F214` (найти следующий элемент пути по маршруту)** обходит узлы
  через `0x47ECD0`. Он останавливается, только когда найдёт подходящий
  элемент или переход не вернёт узел (тупик). Его предел расстояния
  сравнивается только при найденном элементе, а `0x508520` вызывает его без
  предела (0.0).
- **`0x48106C` (`block_state`)** обходит, пока не найдёт сигнал по маске
  или тупик.
- **Ни один не хранит посещённые узлы.**

### PROBABLE

На замкнутой петле без подходящего сигнала в направлении поиска оба
зацикливаются навсегда. Игра зависает, что совпадает с сообщениями о том,
что MSTS/RTS «падают» на закольцованном пути. Во время работы не
воспроизведено.

Документация MSTS согласна, что это старое поведение MSTS.
«Step-by-Step Guide to Building Routes for Microsoft Train Simulator», §1.3
«MSTS limitations» (с. 19):

> you cannot make a closed circuit (like a model railroad that allows running
> round and round forever): if you do, MSTS will freeze up. Loops and wyes can
> create similar problems. What matters is the "organization" (or
> "connectivity") of your route [...]: the order in which switches occur is the
> only important consideration here.

(«Нельзя сделать замкнутый круг (как у моделей железной дороги, где можно
ездить по кругу бесконечно): если сделать, MSTS зависнет. Петли и
треугольники могут создать похожие проблемы. Важна „организация“ (или
„связность“) маршрута [...]: порядок, в котором встречаются стрелки, —
единственное, что здесь важно».)

§3.4.4 (с. 132–133) добавляет:
- автор руководства не знает общего правила размещения петель и
  треугольников;
- главный путь, ответвляющийся в петлю или треугольник, «обычно
  смертелен»;
- каждый способ «выехать с кривого выхода стрелки и как-то вернуться на
  прямой выход той же стрелки» — петля.

Зависание, которое зависит только от связности, а не от геометрии,
подходит к неограниченному обходу графа, как выше. RTS его унаследовал.


## Компилятор, машина и вычисление подробно

Чтение кода (Hex-Rays), CONFIRMED, если не отмечено. Часть про компилятор
также сверена с собственным `sigscr.dat.asm` RTS для TestRoute_RTS.

### Загрузка (`0x496DB0`)

- **Декодирование:** файл в ANSI (`MultiByteToWideChar(CP_ACP)`).
- **Комментарии (`0x459D3C`):**
  - `/* */` затирается;
  - `/*RTS# … */` сохраняет тело (затираются только метки);
  - `//` затирается до CRLF;
  - оба поиска начинаются со второго символа.
- **Скрипты:**
  - каждый `SCRIPT` идёт до следующего `SCRIPT`;
  - имя — следующий токен, в нижнем регистре, сопоставляется с типами
    сигналов;
  - тело **не** переводится в нижний регистр: идентификаторы и имена
    встроенных зависят от регистра (`lstrcmpW`).
- **Константы (`0x4598E8`):** подставляются в каждый скрипт, в таком
  порядке, с учётом регистра, как подстроки без границы слова. Каждая
  замена дополняется пробелами до длины имени:
  - `SIGASP_STOP_AND_PROCEED` до `SIGASP_STOP`, затем остальные показания;
  - `SIGFN_NORMAL`, `_DISTANCE`, `_SHUNTING`, `_INFO`, `_REPEATER`;
  - `BLOCK_CLEAR`, `_OCCUPIED`, `_JN_OBSTRUCTED`;
  - `SIGFEAT_USER` (пробелы, поэтому `SIGFEAT_USER3` становится `3`),
    `SIGFEAT_NUMBER_PLATE` 32, `SIGFEAT_GRADIENT_PLATE` 33;
  - `SIGMODE_NORMAL/SHUNT/FAILED/EXCL` 0–3.

  Констант для показаний 8 и 9 нет.

### Операторы (`0x497ED8`)

- **Слова (`0x458D98`):**
  - слово — последовательность символов в `-`..`9` или ≥ `A` (сюда входят
    `{`, `}`, `|`);
  - `(` начинает группу в скобках;
  - всё остальное пропускается.
- **`extern`** помечает следующее объявление как встроенное.
- **`float name`** объявляет локальную или, после `extern`, встроенную по
  имени:

  | Встроенная | Id |
  |---|---|
  | `block_state` | 1 |
  | `route_set` | 2 |
  | `next_sig_lr` | 3 |
  | `next_sig_mr` | 4 |
  | `def_draw_state` | 5 |
  | `sig_feature` | 6 |
  | `state` | 7 |
  | `draw_state` | 8 |
  | `enabled` | 9 |
  | `dist_multi_sig_mr` | 10 |
  | `this_sig_mr` | 11 |
  | `this_sig_lr` | 12 |
  | `signal_mode` | 13 |

  `float name = expr` компилирует `expr` в AX и выдаёт `MOV name,AX`.
- **`if`:**
  - Условие (группа в скобках) компилируется в AX, затем `JZ if<d>`.
  - Тело идёт до первой `;` на глубине скобок 0 или до закрывающей `}` и
    компилируется на глубине d+1. Затем `JMP else<d>`, `:if<d>`.
  - Тело `else` (расширенное на цепочки `else if`) компилируется на d+1,
    затем `:else<d>`.
  - **d — глубина вложенности, поэтому метки повторяются.** Ассемблер
    (`0x498964`) разрешает переходы по порядку: каждый переход берёт первую
    ещё не занятую метку со своим именем.
- **`return`** выдаёт `RET`.
- **Любое другое слово, чей второй символ ≥ `A`**, начинает оператор,
  который компилируется до `;` как выражение в AX. Однобуквенное первое
  слово пропускается (особенность проверки).
- **Вывод (`0x49722C`):** `SCRIPT <name>` + CRLF CRLF, код, затем CRLF CRLF.

### Выражения (`0x45911C` токены, `0x497334` код)

- **Токены:**
  - число (цифры и `.`);
  - идентификатор (`A`..`z`, цифры, `_`). С `(` после него — это вызов, чьи
    аргументы идут до парной `)`;
  - группа в скобках;
  - операция, сопоставляемая по 3, 2, затем 1 символу:

  | Текст | Оп | Приор. | Мнемоника |
  |---|---|---|---|
  | `==# >=# <=# !=#` | 1 5 3 6 | 2 | `CMPE CMPGE CMPLE CMPNE` |
  | `># <#` | 4 2 | 2 | `CMPG CMPL` |
  | `== >= <= !=` | 13 17 15 18 | 2 | `CMPEF CMPGEF CMPLEF CMPNEF` |
  | `> <` | 16 14 | 2 | `CMPGF CMPLF` |
  | `&&` `\|\|` | 7 8 | 1 | `AND OR` |
  | `=` | 10 | 0 | `MOV name,…` |
  | `! - #` (унарные) | 12 11 19 | 3 | `NOT NEG ROUND` |

  Одинокий `&` — ошибка. `^` никогда не становится токеном.
- **Код в регистре r** (0 = AX … 7 = HX):
  - **Без операции:**
    - число или идентификатор: `MOV r,<text>`;
    - вызов: каждый аргумент компилируется в r и кладётся в стек
      (`PUSH r`), затем `CALL name,r`. Аргументы делятся по каждой запятой,
      без учёта глубины скобок;
    - группа: её содержимое компилируется в r.
  - **Операции:** берётся наименьший присутствующий приоритет, и его
    операции применяются слева направо.
    - Левый операнд компилируется один раз, в r, до первой операции, если
      эта операция не `=` и не унарная.
    - Каждый правый операнд (до следующей операции этого приоритета)
      компилируется в r+1. Затем бинарная операция выдаёт `OP r,r+1`,
      унарная — `OP r+1` и `MOV r,r+1`, а `=` выдаёт
      `MOV <левый идентификатор>,r+1`.
    - Поэтому `a || b && c` — это `(a || b) && c`, и ничего не вычисляется
      сокращённо.

### Машина (`0x499948`, операнды `0x49ACB0`)

- **Операнды:** локальная (номер), поле головы (`state` +84, `draw_state`
  +88, `enabled` +96, `signal_mode` +104), непосредственное значение или
  регистр (16 float; используются AX..HX).
- **Опкоды:**

  | Код | Оп |
  |---|---|
  | 1 | MOV |
  | 3 | CALL |
  | 4 | PUSH |
  | 5 | JMP |
  | 6 | JZ (AX = 0) |
  | 0x0A–0x11 | CMPE, CMPNE, CMPG, CMPGE, CMPL, CMPLE |
  | 0x12 | AND |
  | 0x13 | OR |
  | 0x14 | XOR |
  | 0x15 | NOT |
  | 0x16 | NEG |
  | 0x17–0x1C | сравнения float |
  | 0x1D | RET |
  | 0x1E | ROUND |

  - **Целые сравнения** усекают обе стороны к 0.
  - **ROUND:** ненулевое значение сохраняется, когда его дробная часть
    меньше 0,5, иначе округляется вверх.
- **Локальные не сбрасываются между прогонами (PROBABLE).** Они живут в
  скомпилированном скрипте, поэтому все головы одного типа сигнала делят
  их, а прогон видит значения предыдущего. Скрипт, читающий локальную до
  записи, зависит от порядка вычисления.
- **Перед прогоном (`0x499948`, CONFIRMED чтением кода):**
  - ограничение скорости ставится в −1;
  - в цепочке, если голова не FAILED: первая голова объекта берёт режим
    следующего (дальнего) объекта, когда он ни SHUNT, ни FAILED; остальные
    головы объекта берут собственный режим объекта (узел цепочки +12);
  - замены (список `SignalOverride`, голова +120, каждая запись по очереди)
    ставят режим (+8, если не 0xFFFF), скорость (+12, если больше −2),
    показание (+6, если не отрицательное) и состояние отрисовки (+4, если
    не 0xFFFF; −2 означает состояние отрисовки типа для показания).
- **Режим FAILED / EXCL:** скрипт пропускается.
  - показание: замена, иначе 9 (FAILED);
  - скорость: замена, иначе глобальное умолчание (`dword_61D7D4`, значение
    UNKNOWN);
  - состояние отрисовки: замена (−2: по типу для показания, `0x47A138`),
    иначе −1: без состояния отрисовки, голова тёмная. (Раньше заметки
    говорили — по умолчанию типа; код даёт −1.)
- **После прогона (в цепочке):**
  - режим объекта становится режимом головы;
  - без замены режим, отличный от NORMAL и от режима следующего объекта,
    распространяется на каждый объект дальше (`0x50B6F4`: объект и головы,
    кроме голов FAILED);
  - применяются замены (показание, скорость, состояние отрисовки, как
    выше);
  - режим SHUNT (если нет `RTS_ShuntingAutoMode`) превращает показания 3..7
    в 2 (RESTRICTING), с состоянием отрисовки и скоростью этого показания.
- **`block_state(mask)` и `route_set(mask)`:** аргумент выбирает, какие
  функции сигналов заканчивают обход:

  | Аргумент | Функции, заканчивающие обход |
  |---|---|
  | нет, 0 | только NORMAL |
  | 1 | своя + NORMAL |
  | 2 | только своя |
  | 3 | любая |
  | 4 | своя и с меньшими номерами функций |
  | 5 | как 1 плюс меньшие номера функций |

- **`block_state`** идёт от смещения головы, в её направлении, до первого
  такого сигнала, обращённого в ту же сторону.
  - **1:** найден поезд. На узле головы и на конечном узле поезд должен
    быть между границами; на узлах между ними — где угодно.
  - **2:** пошёрстная стрелка на пути выставлена против. Это побеждает
    найденную раньше занятость.
  - **0:** иначе. Тупик заканчивает обход.
  - С маневровым флагом считаются только поезда, помеченные для этого.
- **`route_set`** идёт так же и считает связанные с головой стрелки
  (`TrSignalDirs`: узел, ветка), пройденные с выбранной этой веткой.
  - Без связей: 1, когда дошёл до сигнала или конца.
  - Со связями: счёт, как только дошёл до сигнала и счёт не 0. Со связями,
    но без совпадения, идёт дальше за сигнал.
  - 0 на пошёрстной стрелке, выставленной против.
- **`next_sig_lr(fn)` / `next_sig_mr(fn)`:** по цепочке начиная со
  следующего объекта.
  - Для NORMAL объект, у которого минимум типов голов — NORMAL, даёт своё
    закэшированное показание, которому подчиняются.
  - Иначе — максимум или минимум по головам типа `fn` этого объекта.
  - Результат даёт первый объект, у которого он есть; 0, если ни у
    одного.
- **`def_draw_state(asp)`:** показание в таблице показаний типа.
  Возвращает его состояние отрисовки (0, когда показания нет в списке) и
  ставит ограничение скорости головы.
- **`sig_feature(f)`:**
  - f = 32 / 33 проверяют флаги головы 0x10 / 0x20;
  - любое другое f ≥ 32 даёт 1;
  - f < 32 проверяет бит f+5 флагов головы (из мирового `SignalSubObj`).
- **`dist_multi_sig_mr(fn…)`:** минимум по перечисленным типам на первом
  объекте, где он есть. Начинает с 7; 0, если нет.
- **`this_sig_mr(fn)`:** минимум по головам типа `fn` до этой на объекте.
  −1 вне цепочки, 0, если их нет.
- **`this_sig_lr(fn)`:** максимум по другим головам типа `fn`. −1, если их
  нет или вне цепочки.

### Свободно работающие головы (`0x479AFC`)

- **Работают каждый кадр**, из цикла отрисовки. Голова, у которой
  `enabled` равен 0 (нет цепочки поезда в этом кадре), сбрасывает свой
  режим на NORMAL (если не FAILED/EXCL) и работает без цепочки. Глобальный
  флаг это пропускает (UNKNOWN какой; тот же останавливает `0x508520`).
- **Огни:**
  - Состояние отрисовки выбирает огни. Огонь с пометкой мигания горит,
    пока таймер головы (+108, плюс время кадра, с заворотом на `on + off`)
    ниже `on`.
  - Каждый огонь — объект света RTS, включаемый и выключаемый (`0x449740`
    / `0x4497A4`). Огни сигналов рисует система света, а не модель.
  - Семафоры (флаг типа 1) ставят положение крыла по состоянию
    отрисовки.
- **`enabled` снимается** в конце кадра.
- PROBABLE: головы вне рисуемой области не обновляются. Это видно только
  на экране.

### Вычисление на каждый поезд (`0x508520`, из обновления поезда `0x424488`)

- **Сбор** объектов сигналов впереди путешественника головы (`0x47F214`):
  - до 16;
  - пропуская объекты, у которых первая голова EXCL;
  - пока число объектов с головой NORMAL не дойдёт до
    `SignalNumClearAhead` первого типа NORMAL + 2.
- **Узел цепочки** содержит:
  - показание, которому подчиняются, и минимальную функцию голов;
  - расстояние;
  - режим из флагов поезда: бит 0 `+7` даёт SHUNT, бит 1 — NORMAL, объекту
    и каждой его голове, которая не FAILED (ни один не выставлен: головы
    сохраняют свой);
  - головы, следующий и предыдущий.
- **Вычисление от самого дальнего к ближайшему.**
  - `enabled` равен 2 на время прогона, кроме 0:
    - для самого дальнего объекта NORMAL, когда счёт был достигнут;
    - за концом маршрута или бронирования поезда;
    - где противошёрстная стрелка выставлена против конца маршрута.
  - Объекты за пределами разрешения на движение или с выставленным
    глобальным флагом не выполняются.
  - После прогона объект дальше `speed · frame time · 1.5` сохраняет
    `enabled = 2` на кадр, поэтому свободный прогон его пропускает. Более
    близкий («проезжаемый сейчас») сбрасывается в 0.
- **Показание, которому подчиняются:** поезд подчиняется максимальному
  показанию по головам NORMAL объекта. С флагами поезда `+6` учитываются и
  другие головы, когда их функция — минимум объекта: бит 0 DISTANCE (нужна
  также одиночная игра или поезд игрока), бит 1 SHUNTING, бит 2 INFO.
  Ограничение скорости — наименьшее положительное.
- **Проезд:** первый объект в пределах расстояния проезда ставит
  ограничение скорости поезда (+108). Для поезда игрока в задании:
  - флаг 1 с показанием 1 (STOP_AND_PROCEED) проваливает с «passed red
    signal» (`0x41B4F4` код 1);
  - флаг 8 с показанием 0 (STOP) проваливает с «passed stop signal»
    (код 4).
- **Назад:** зеркальный проход идёт от хвоста (`train+0xE8`). Какие
  проходы выполняются: см. «Оба конца для поезда игрока» выше.
- **Занятость для `block_state`:** на каждый узел — список записей поездов
  со смещением (`node+52`, записи со смещением в +40). openRTS вместо этого
  использует протяжённость всего поезда на каждом узле (`docs/signals.md`).
  Это охватывает каждый вагон, включая вагоны на стрелке или за ней.

### Огни сигналов (`0x4491E8`)

Когда загружается мировой сигнал, каждая голова получает по одному объекту
света RTS на каждый `SignalLight` своего типа (записи по 164 байта, голова
+112):
- **положение:** `Position` огня. Если у модели выставлен её флаг в +13
  (UNKNOWN, какой), прибавляется сдвиг матрицы модели, названной по
  `SignalSubObj` головы: x − tx, y + ty, z + tz в пространстве RTS.
  Учитывается только сдвиг, не поворот матрицы — CONFIRMED;
- **размер:** `Radius`; **текстура:** `LightTex` типа (имя, прямоугольник
  UV);
- **цвет:** запись `LightsTab` (ARGB).

Обновление головы `0x479AFC` включает и выключает эти огни по состоянию
отрисовки (включая мигание). Огни рисует система света, а не как часть
модели. В пространстве RTS Z перевёрнут относительно пространства модели
MSTS: у мачтовых сигналов TestRoute_RTS линзы смотрят к −Z в модели, а
`Position` ставит огни в +Z (0,65 м). Поэтому openRTS ставит огонь в
(tx − x, y + ty, tz − z) в пространстве модели: Position повёрнут на 180°
вокруг вертикали относительно модели. Знак X проверен на
T_Small_YGW_Rx-new Кубани (столбец красной линзы на x модели +0,28 для
Position x −0,28), знак Z — на мачтовых головах TestRoute — CONFIRMED
геометрией.

### Отрисовка огня (цикл огней `0x408574`, четырёхугольник `0x449818`)

Огни рисуются после объектов: проверка глубины включена, запись глубины
выключена, без освещения и тумана, в преобразовании объекта-владельца.
Каждый огонь — **один плоский четырёхугольник**, а не спрайт, повёрнутый к
камере: углы в (+-s, +-s, 0), повёрнутые кватернионом огня (единичным для
огней сигналов, задаётся в `0x4491E8`) вокруг Position, UV из LightTex,
окрашенные цветом LightsTab. Поэтому четырёхугольник лежит в плоскости XY
сигнала, плоско на линзе: прямо — это горящая линза, сбоку — ребро, сзади
его закрывает корпус — CONFIRMED.

Половина размера s = Radius * fov/45 * max(1, d * light_scale * |u1 - u0| *
k / Radius), где d — расстояние до камеры, light_scale = 0.012 *
LightsScale (rts.ini), а k = ширина текстуры / 512 (целочисленное деление),
когда выставлен флаг текстуры +13. Вблизи это размер линзы, вдали он
сохраняет постоянный угловой размер — CONFIRMED. fov — поле зрения камеры
RTS, `FOV` в config.ini (в этой установке 65).

Зум вида openRTS (Ctrl и колесо вне кабины; не RTS): у огней сигналов
дальний член делится на зум (`SignalView::collect_lights`), и дальний огонь
сохраняет на экране тот размер, что у него без зума; при зуме он был во
столько же раз больше, и красный огонь за километр закрывал вид. Вблизи
Radius линзы (настоящий размер) виден увеличенным, как и сам сигнал. Огни
поездов следуют правилу как есть (2026-11-08).

**Особенность — размер огня следует за полем зрения.** Множитель fov/45
вычисляет `rts1.exe` и передаёт в `lamp.vert.shader` в `Size` (шейдер лишь
рисует четырёхугольник `Size.x * Size.y` вокруг огня). Он сохраняет размер
свечения на экране при смене FOV, что подходит ореолу, но RTS применяет
его к каждому четырёхугольнику огня, и к тем, что являются частью модели:
лицевым частям фонарей и конусу прожектора ЭД9М, собранному из шести
четырёхугольников свечения (train-dll.md, наружные огни). Смена FOV в RTS
растит и сжимает их вокруг их центров: лицевые части фонарей вылезают за
корпуса или сжимаются внутри них, конус отходит от своей лампы или
уходит в неё. Контент делается под FOV, которым пользовался автор (конус
ЭД9М сидит на своей лампе при 65). openRTS задаёт размер каждого огня
(сигналов и поездов) с множителем при 65 градусах, фиксированно, каким бы
ни было поле зрения (`GlowSpriteRenderer`). Сама геометрия линзы — часть
модели; больше ничто её не освещает.

**PROBABLE** смешивание: четырёхугольник огня (`0x449818`) включает
`GL_BLEND` и выключает альфа-тест, но своей функции смешивания не ставит, и
цикл огней `0x408574` перед ним тоже не ставит; действующая в кадре —
`GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA` (ставится обратно там после его
аддитивной части). Поэтому огонь накладывается на сцену по своей альфе
(`lamp.frag`: текстура × LightColor), после каждого объекта, включая
смешиваемое стекло. Цикл стоит между проходами объектов 2 и 3
(shape-rendering.md, «Passes»): после стекла, до кабины. openRTS рисует
там огни поездов и сигналов, накладывая по их альфе в пути RTS
(`GlowBlend::over`) и складывая в экспериментальном пути
(`GlowBlend::added`, излучение в кадре HDR).

### SignalSubObjs и части модели (`0x4491E8`, разборщик `0x483694`)

Номера SigSubType: SIGNAL_HEAD 1, DECOR 2, NUMBER_PLATE 4. Когда
загружается мировой сигнал, каждый подобъект его модели, который
**DECOR** и чей бит сброшен в маске SignalSubObjs мира, ставит флаг 1
(скрыт) на матрицу модели с тем же именем. Больше ничего не скрывается:
головы рисуются, что бы ни говорили маска или OPTIONAL (многие модели
называют каждую голову «SIGNAL» — матрицей, которая держит всю мачту).
SIGNAL_HEAD, у типа которой выставлен бит 1 флага +6, ставит флаг матрицы 2
и получает анимацию (крылья семафора) — CONFIRMED.

### Огни, видимые сзади

RTS один раз включает `GL_CULL_FACE` (`create_game_window`, `0x40564D`) с
отсечением обратных граней по умолчанию и выключает его в других местах
лишь ненадолго; цикл огней — нет. Поэтому односторонний четырёхугольник
огня невидим из-за плоскости линзы — CONFIRMED. openRTS пропускает огонь,
чья линза смотрит от камеры, что также скрывает выросший вдали
четырёхугольник вокруг головы, видимой сзади.
