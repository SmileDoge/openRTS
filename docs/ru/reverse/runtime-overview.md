# Обзор работы rts1.exe

> Перевод [`docs/reverse/runtime-overview.md`](../../reverse/runtime-overview.md).
> Основной текст — английский: при расхождении верен он.

Состояние: статический анализ только для чтения копии `rts1.exe.i64`
(IDA 9.0 без интерфейса + Hex-Rays), сверенный с `ts.h` (TS_VERSION 104),
`export.pdf` v0.43 и `ext.pdf`. Проверок во время работы не проводилось.
Адреса относятся к разобранному `rts1.exe` (PE32, скомпонован 2021-08-06,
база образа `0x400000`).

Все смещения структур ниже — смещения, наблюдаемые в коде. Имена полей —
предполагаемые, если их не называет первичный источник (ts.h, токен
ENG/WAG).

## Двоичный файл

### CONFIRMED

- 32-битная сборка Borland C++ (RTL `CC3260MT.DLL`, символы CRT с
  искажением Borland, точка входа `0x401218`). Без VCL; обычные окна Win32
  и цикл сообщений.
- ~3470 функций, основные очень большие (до 44 КБ каждая), структуры
  классов C++ почти не видно: данные — простые структуры, доступные по
  сырым смещениям.
- Импорты: OpenGL 1.x + расширения через `wglGetProcAddress`
  (`init_open_gl_funcs` `0x4A5D10`), GLU, DirectSound (один
  `DirectSoundCreate`; `bass.dll` отдельно), WinSock 2 (сетевая игра),
  `timeGetTime`.
- Текстовые форматы разбираются одним общим сканером токенов (`0x4578C0`,
  имя в IDB `parser_maybe`), который ищет токен в нижнем регистре в буфере
  UTF-16 и возвращает диапазон `( ... )`. Каждый загрузчик формата — длинная
  прямая последовательность таких поисков, поэтому таблицы строк токенов в
  `.data` — хороший указатель того, что понимает каждый загрузчик.
- Обнаружение установки MSTS читает
  `HKLM\SOFTWARE\Microsoft\Microsoft Games\Train Simulator\1.0\Path`
  (`0x401C3C`); отсутствие ключа — фатальное «MSTS not installed».

## Запуск процесса (`WinMain` `0x401368`)

### CONFIRMED

```text
WinMain
 -> 0x401C3C  регистрация классов окон, проверка ключа реестра MSTS
     -> 0x401E7C  временные указатели «page_consists»/«page_engines» из
                  TRAINS\CONSISTS(_RTS) и TRAINS\TRAINSET (engextended, cabin)
     -> 0x405D2C  чтение config.ini (viewdistance, auxthreads, usevbo, ...)
 -> 0x5B71A8  окно меню (GUI\SCREENS\*.ace, рисуется GDI)           | одно из,
 -> 0x54AEEC  запуск задания/редактора/IPC (/startIPC, .act, сохр.) | по командной
 -> 0x40521C  окно игры: формат пикселей, контекст GL, шейдеры,     | строке
              пулы текстур/моделей/SMS, затем главный цикл 0x44D280
 -> 0x402C2C  очистка
```

## Главный цикл (`0x44D280`)

### CONFIRMED

Порядок загрузки: шейдеры (`0x56F1E0`: GLSL shape/shell/shadows/satellite),
поезда (`0x42F4A4`: задание, сохранение, данные сетевой игры, маршрут,
состав, расстановка), тайлы мира (`StartAddress` `0x42188C`, один раз
синхронно), текстуры.

На каждом кадре:

1. `PeekMessage` / `DispatchMessage`; собственные сообщения потоку несут
   запросы загрузки маршрута/состава и сетевые события.
2. Если камера дальше 1024 м от начала текущего тайла по X или Z,
   (пере)запускается фоновый поток загрузки (`StartAddress`). Он загружает
   файлы мира (`WORLD\w%+07i%+07i`, `0x41B6D0`), рельеф (`TILES\`,
   `0x49B088`) и траву/динамический рельеф (`0x538C14`). Общие пулы
   охраняются семафорами Win32 (`sObjA`, `sTerrain`, `sTrain`, `sSoundObj`,
   `TextureArr`, `ShapeArr`, `SMSFiles`).
3. Ожидающие загрузки текстур в GPU вычерпываются (`0x44150C`).
4. Поезда ИИ / статические (пере)создаются, когда камера сдвинулась больше
   чем на расстояние `updatetrains` (`0x4232A8`).
5. `dt = разность timeGetTime()`, прижатая к **8..1000 мс**; игровые часы
   идут на `dt` (заворачиваются на 86400 с; клавиши `+`/`-` сдвигают время).
6. Сетевой такт (`0x52CD20`), такт задания (`0x530D4C`).
7. Ввод (`0x4121BC`).
8. **Симуляция**: `0x424488(dt)`, затем `0x44AB7C(dt)`.
9. Отрисовка (`0x408574`), необязательный ограничитель 30 кадров/с.

Симуляция работает в потоке отрисовки с переменным `dt` кадра;
фиксированного внешнего шага симуляции нет. Фиксированные подшаги есть
только внутри решателя сцепок (ниже).

## Симуляция поезда (`0x424488`)

### CONFIRMED (порядок выполнения)

Обходит список поездов (`dword_61D794`, связан через `train+0x18C`). Для
каждого поезда и каждого вагона (`train+0x1C` число, `train+0x20` массив
указателей на вагоны):

- обслуживание звука/окружения и проигрывания записи;
- взгляд вперёд по сигналам / элементам пути в обе стороны (`0x508520`),
  который также вызывает провалы задания через `0x41B4F4`: 1 = проезд
  запрещающего сигнала, 3 = разрыв сцепки, 4 = взрез стрелки;
- `Run` DLL локомотива через `0x5031D8` (см. `legacy-dll-abi.md`);
- здесь потребляется очередь до 16 пар `{short action, short id}` в
  `+0x90` объекта вагона (PROBABLE: `Engine::GlobalMsg`, который пишет
  `PostGlobalMessage` DLL, той же формы в `ts.h`): переключение групп огней
  (`0x438430`), смены дверей/анимаций/текстур, сообщения на экране
  (`0x414684`, `0x41463C`, `0x41477C`);
- выравнивание тормозной магистрали между соседними вагонами;
- силы сопротивления, уклона и кривой на каждый вагон;
- решение сцепок и интегрирование (`0x505414`);
- разрыв сцепки, сход и расцепка (`0x469858`);
- движение каждого вагона по пути (`0x4F5B34`);
- столкновение / сцепка поездов (`0x58A07C`, `0x469ED8`, `0x4FB8CC`).

### Состояние вагона (предполагаемая раскладка)

| Смещение | Смысл | Уверенность |
|---:|---|---|
| `+0x0C` | вид локомотива (1 = электрический, 2 = тепловоз, по рассылке DLL) | PROBABLE |
| `+0x1C` | флаги; бит 0 = вагон развёрнут (знак скорости и концы сцепок переставлены) | CONFIRMED |
| `+0x24` | масса, кг | CONFIRMED (используется как `F/m`) |
| `+0x2C` | накопитель диссипативной силы (тормоза + сопротивление), Н | CONFIRMED |
| `+0x44` | скорость вдоль поезда, м/с | CONFIRMED |
| `+0x48` | ускорение, м/с² | CONFIRMED |
| `+0x4C` | сопротивление качению, Н | CONFIRMED |
| `+0x50` | сила уклона, затем используется как сила в сцепке для проверок разрыва | CONFIRMED |
| `+0x54` | активная (движущая) сила, Н | PROBABLE |
| `+0x58` | `double` смещение вагона внутри поезда, м | CONFIRMED |
| `+0x64`, `+0x6C` | давление тормозной / второй магистрали | PROBABLE |
| `+0x98` | 64-байтовый путешественник (тайл X/Z `int16`, положение, узел пути...) | CONFIRMED |
| `+0xD8` | предыдущий путешественник (копия `+0x98`) | CONFIRMED |
| `+0xC4` | текущий радиус кривой (0 = прямая) | CONFIRMED |
| `+0xC8` | угол тангажа (уклон) | CONFIRMED |
| `+0x138` | тип вагона (разобранные данные ENG/WAG, общие) | CONFIRMED |
| `+0x174` | внешнее оборудование / группы огней (записи по 116 байт в `+0x38`) | PROBABLE |
| `+0x1A4` | объект кабины | PROBABLE |
| `+0x1EC` | указатель на `Run` основной DLL | CONFIRMED |

Тип вагона (разборщик `0x44247C`): `Size` → `+0x24/+0x28/+0x2C` (W, H,
**L**), `Mass` (т × 1000) → `+0x30`, блок передней сцепки `+0x54`, задней
`+0x7C` (копируется с передней, если нет), `DerailRailHeight` `+0xD8`,
`DerailRailForce` `+0xDC` (по умолчанию 240000 Н), `DerailBufferForce`
`+0xE4`, байт `NumWheels` `+0x1D`, десять значений `Friction` MSTS
`+0xE8..+0x10C`, `MaxVelocity` (внутри блока тормозов) `+0x1B4`.

Блок сцепки (40 байт): байт типа (`+0`), флаг жёсткости (`+1`), жёсткость
растяжения/сжатия (`+4/+8`, по умолчанию `mass*100`, `mass*120`),
демпфирование (`+0xC/+0x10`, по умолчанию `mass*200`, `mass*250`), сила
разрыва растяжения/сжатия (`+0x14/+0x18`, по умолчанию `mass*100`,
`mass*200`), зазор `r0` (`+0x1C/+0x20`).

### Силы

#### CONFIRMED

- **Сопротивление качению** следует кусочной степенной формуле `Friction`
  MSTS: ниже скорости перехода `c1 * v^e1` (`v <= 1` считается 1), выше —
  второй степенной член по `(v - v_t)`.
- **Штраф за превышение скорости**: выше `MaxVelocity` вагона
  сопротивление растёт до 10× при 1,2 × `MaxVelocity`, затем растёт
  квадратично. Это особенность RTS.
- **Сопротивление в кривой**: `+= 7.0 / R * mass`.
- **Уклон**: `F = -sin(pitch) * mass * 10` (g = 10).
- **Сход** (если не выключен в настройках): когда `mass * v² / R`
  превышает `DerailRailForce`, `0x5059A8` сводит вагон с рельсов.

### Учёт сил перед решателем (`0x424488`)

#### CONFIRMED (декомпиляция)

На каждый вагон, каждый кадр:

| Поле | Смысл |
|---|---|
| `+0x54` | активная сила (тяга, из DLL) |
| `+0x50` | сила уклона |
| `+0x4C` | сопротивление качению и в кривой |
| `+0x2C` | тормозная сила |

Затем:
1. `active −= grade`: уклон добавляется к активной силе.
2. `dissipative = brake + resistance`.
3. **Предварительное погашение.** Если `|active| ≤ dissipative`,
   диссипативная сила съедает активную: `dissipative −= |active|`,
   `active = 0`. Иначе `active −= dissipative · sign(velocity)` (знак
   скорости, а не силы) и `dissipative = 0`.
   - Поэтому стоящий поезд не трогается, пока тяга не превысит тормоза
     плюс сопротивление.
4. **Зазоры.** Для каждой сцепки текущий зазор вычисляется по смещениям,
   половинам длин и `r0` (удвоенному для жёстких концов).
5. **Сон.** Решатель работает, только если у какого-то вагона есть
   активная сила, ненулевой зазор или ненулевая скорость (значения ниже
   1e-6 сначала обнуляются).

### Решатель сцепок (`0x505414`)

#### CONFIRMED (декомпиляция)

Аргументы — массивы по вагонам: диссипативная сила, активная сила,
скорость, зазор и сила в сцепке, плюс `dt` кадра.

`dt` кадра режется на подшаги по 0,05 с, последний укорочен. Каждый
подшаг:

1. **Восстановление сил.** Активная и диссипативная силы
   восстанавливаются из значений кадра.
2. **Пружины сцепок:**
   - `gap = (offset_j + moved_j) − (offset_{j+1} + moved_{j+1}) − (L_j + L_{j+1})/2 − (r0_a + r0_b)/2`,
     минус ещё `r0/2` для жёсткого конца;
   - `F = gap · (k_tension_a + k_tension_b)` при `gap ≥ 0`, иначе с
     жёсткостями сжатия. Линейно, с нулевой силой при нулевом зазоре (без
     мёртвой зоны);
   - каждому вагону идёт **половина** F: `active_j −= F/2`,
     `active_{j+1} += F/2`;
   - расцепленные вагоны (флаг `0x40` в байте `+0x20`) силы не получают;
   - сила первого подшага сохраняется для проверок разрыва.
3. **Интегрирование:** `v += active/m · h` (полуявный Эйлер: сначала
   скорость, затем положение на шаге 5).
4. **Трение покоя:** диссипативная сила уменьшает |v| на `diss/m · h`. Если
   это перешло бы через ноль, `v = 0`, а неиспользованная часть остаётся
   «оставшимся трением» для шага 5 этого подшага.
5. **Выравнивание скоростей** (`0x504648`) для каждой пары соседей с
   разными скоростями (и сцепленных):
   - относительное смещение `(v_j − v_{j+1}) · h` раскладывается по цепочке
     сцепок **к голове** (вагон j, затем j−1, … до 0);
   - в каждой сцепке часть его забирает сама сцепка: зазор `r0/2`
     нежёстких концов, в пропорции `k / (c · Δv/h)` с потолком 1, где k —
     сумма жёсткостей, а c — сумма демпфирований для направления;
   - остаток — **пластичный обмен импульсом** между вагоном j и группой
     позади него (с весами по массе);
   - оставшееся трение покоя заторможенных вагонов поглощает часть его;
   - **демпфирование — не явная сила `c·v`:** оно только задаёт, какая
     часть разности скоростей становится ходом сцепки, а какая —
     немедленным обменом импульсом.
6. **Перемещение:** `moved += v · h`.

После кадра:
- **Скорость и ускорение:**
  - `v = moved / dt` (среднее за кадр);
  - `a = (v − v_old)/dt`;
  - `0x424488` ставит `v = v_old + a·dt` (то же среднее), обнуляет
    `|v| < 0.002·dt` и `|a| < 0.002`.
- **Смещения:** `offset += v·dt`, с пересчётом так, чтобы последний вагон
  оставался опорным. Зазор сцепки меньше `0.001·dt` подгоняется точно к 0
  сдвигом всех вагонов впереди.
- **Расцепка** (`0x469858(train, index, close_cocks, keep_open)`),
  CONFIRMED:
  - вагоны от `index` образуют новый поезд (тип 3, стоящий);
  - флаги вагона `+28`: задний вагон отрезка получает `0x2A00` (рукав,
    вторая магистраль и линия ЭПТ сзади разъединены; байт `+29`
    0x02/0x08/0x20), передний вагон отреза — `0x1500` (то же спереди);
    концевые краны остаются как были;
  - `close_cocks` (или поезд типа 2) выполняет `0x4FECB0`: сзади `0x8200`,
    спереди `0x4100` — концевые краны закрыты (и ЭПТ / вторая магистраль,
    когда они есть у обоих вагонов);
  - `keep_open` ставит вагону `+14` биты 2 / 1 (сцепки оставлены
    открытыми);
  - вызывающие: разрыв сцепки с (0, 0) после «Train damaged»; меню расцепки
    `0x54F288` с (1, 0); сетевая игра и запросы по флагам вагонов.
- **Встреча поездов** (`0x424488`), CONFIRMED: соседние поезда хранят зазор
  между своими концами. Когда шаг его закрывает, удар равен
  `−gap_after / dt · (m1 + m2)` двух концевых вагонов. Выше
  `DerailBufferForce` (`+0xE4`) любого из вагонов или для сошедшего вагона
  `0x58A07C` обрабатывает столкновение (импульс, флаги повреждения 16/32
  выше порога сцепки). Иначе поезда сцепляются (`0x469ED8`), если только
  сцепка не автоматическая (и поезд не типа 2), контактный конец не оставлен
  открытым (`+14` 0x11 / 0x22) или скорость сближения ниже `Velocity` сцепки
  (`+36` блока сцепки); тогда они только толкаются (`0x4FB8CC`: перекрытие
  делится по массам поездов).
- **Разрыв сцепки** (только поезд игрока, если не выключено в настройках):
  - сохранённая сила в сцепке сравнивается со значением `Break` более
    слабого конца — растяжение или сжатие по знаку силы, и растяжение для
    жёстких концов;
  - разрыв расцепляет (`0x469858`) и показывает «Train damaged»;
  - задание считает его провалом 3.

#### Следствия для openRTS

- **Размер шага важен** в пружинах (явных), в отсечке трения покоя и в
  выравнивании, которое работает на каждом подшаге.
- **Зависимость от частоты кадров** в RTS идёт от укороченного последнего
  подшага и от усреднённых по кадру скоростей.

### Движение по пути (`0x4F5B34`)

#### CONFIRMED

Поезд держит путешественников головы/хвоста в `train+0xA8` и
`train+0xE8`. Путешественник каждого вагона — копия путешественника
опорного вагона, продвинутая на разность смещений вагона через
`0x481440(traveller, distance, mode, train)`; неудачное продвижение (конец
пути) сводит/останавливает вагон через `0x5059A8`. Когда путешественник
переходит в другой узел пути, записи занятости (`train+0x128/+0x148`)
обновляются (`0x490324`). Положение в мире восстанавливается как
`(tile - camera tile) * 2048 + local position`; тангаж — `atan` разности
высот между тележками.

Поэтому положения одномерные (расстояние вдоль поезда/пути); трёхмерная
расстановка — их проекция.

## Кабина и интерьер

### CONFIRMED

В строках нет пути 2D-кабины MSTS `.cvf`; кабины RTS — трёхмерные
интерьеры, описанные расширением RTS для описания модели:

- `0x51CD88`: загрузчик описания кабины — `interiorgeometryinfo`,
  `interiorchairs`, `interiorwindows` (`headoutwindow`), `switches`,
  `decorativeswitches`, `displays` (типы arrow / lamp / display / screen),
  `closeups` (2D-экраны крупного плана с `backgrounds`, `camerafov`, ...),
  `locomotivesignalization`, `signalaspects`, `lightsources`, `smstriggers`,
  `animations`. Вызывается из загрузчика кабины `0x435654` («Failed to load
  cabin»), который запускается из обновления поезда, когда игрок входит.
- `0x515434`: интерьер пассажирского вагона (`Interior ( InteriorFile ... )`):
  области, двери, окна, сиденья, `togglelights`, `unlockdoors`.
- `0x4F0BC8`: `esd_interior_parts` внешней модели: наружные двери,
  лестницы, площадки, части токоприёмников, колёса, тележки,
  `wagon_front/back`.

Объекты во время работы — те, что в `ts.h` (`ActSwitch`, `ActDisplay`,
`ActChair`, `ActWindow`, `ActDoor`, `CloseUpSubObject`, `FreeAnimation`,
`TexChange`): у каждого переключателя есть `State` и `SetState`, движок
ведёт `State` к `SetState` за `AnimTime`, а и ввод игрока, и DLL пишут
только `SetState`.

### Договор управления (из `export.pdf` + `ts.h`, совпадает с местами вызова)

```text
щелчок/клавиша игрока на переключателе -> DLL CanSwitch(id)  (запрет + звуковой триггер)
переключатель доходит до нового положения -> DLL Switched(id) (синхронная логика)
каждый кадр                 -> DLL Run(eng, loco, State, dt, AirTemperature)
                               -> Engine::Force, BrakeForce, TrainPipeRate,
                                  AuxilaryRate, MainResRate, UR, песок ...
                               -> SetState переключателей/дисплеев, огни,
                                  триггеры SMS, очередь PostGlobalMessage
вход/выход из локомотива    -> ChangeLoco / LostMaster, группировка СМЕ
                               через SMECable / HVBus (ext.pdf)
```

В движке нет встроенной логики локомотива для кабин RTS: тяга, логика
тормозного крана, устройства безопасности и приборы — всё живёт в DLL.
Движок даёт физику вагонов/поезда, распространение по тормозной магистрали
между вагонами, звук, анимацию и объектную модель, которую правит DLL.

## Открытые вопросы

- Точный смысл `0x504648` (демпфирование против зазора).
- Где `Engine::Force` / `BrakeForce` складываются в `+0x54` / `+0x2C`
  вагона (вероятно, `0x503CE4` или код сразу после рассылки DLL).
- Модель тормозного цилиндра на вагон (`0x50D3B4`, `0x514630`) — ещё не
  прочитана.
- Шаговый механизм анимации переключателей и выбор мышью в кабине
  (`0x4121BC` и отрисовщик) — не прослежены; поведение выше — по
  `ts.h`/`export.pdf`.

## Сход (`0x5059A8` → `0x580B30`; на каждом кадре `0x581BC4`, `0x581694`, `0x586E6C`, `0x58AB30`)

Сошедший вагон получает тело (208 байт, список в поезде +384, следующий в
+204) — CONFIRMED для частей ниже, остальная часть модуля (~40 КБ: решатель
для сошедших поездов `0x586E6C`/`0x588184`, контакт с землёй
`0x58A390`/`0x58A630`, удары `0x589A14`, 19 КБ `0x581ECC`) не перенесена.
- **Опрокидывание** (превышение скорости в кривой `m·v²/R >
  DerailRailForce` или опрокинутый сосед): целевой крен `0.1 + 0.04·|v|`
  рад (сосед: 0,75 от его), не больше 1,8; скорость `|v|/33` рад/с (сосед:
  0,8 от его); сопротивление при полном крене `m·10` (умножить на
  `0.637·target` ниже 1,57); крен растёт на
  `rate·dt·(|target − roll|/|target| + 0.2)` (`0x581BC4`); наружу кривой или
  так, как кренится сосед.
- **Упал** за 0,8 рад: флаги вагона `0x3F00` (рукав, вторая магистраль и
  линии ЭПТ с обоих концов) и обращённые концы соседей.
- **Соседи** (`0x581694`): `0.637·|roll|·m` выше `DerailBufferForce`
  соседа сводит его; за 0,9 рад сцепка повреждена (флаги 16/32); дальше
  друг от друга, чем половины длин + 0,5 м, рукава разъединяются.
- **Скольжение** (неудачное продвижение, например конец пути): тело на
  земле, движущееся по курсу вагона со скоростью вагона, сопротивление
  `m·5`.

- **Контакт с землёй** (`0x58A390`, структура CONFIRMED): углы тела
  (±ширина/2, высота) проверяются против ближних объектов мира
  (`0x58A630`: объекты с ненулевыми `CollideFlags` и сброшенным битом 2,
  предварительный отбор сферой ×1,42, затем их треугольники); контакты
  суммируют силу опоры (глубина контакта × 1 170 000 для вида земли 1,
  × 3000 иначе) и ограничивают опускание тела.
- **Удары** (`0x589A14`): удар у середины сошедшего тела кренит его (цель
  `F/m·t·0.04 + 0.1`, скорость `|F/m·t/width|`), у одного конца —
  поворачивает; на рельсах он добавляется к движению тела.

openRTS: правила опрокидывания и скольжения выше; удары (`Train::hit`: на
рельсах выше DerailBufferForce вагон сходит и скользит, ниже — тело
принимает толчок; сошедший вагон, ударенный сбоку, кренится по формуле
выше, скользящий, ударенный вдоль, складывается); поезд, съехавший с конца
пути или врезавшийся в препятствие, складывается: каждый следующий вагон
сходит, пока тормозящая сила вагонов позади него (m·v за 0,5 с, PROBABLE
замена решателя `0x586E6C`) выше его DerailBufferForce, складываясь в
чередующиеся стороны на `0.1 + 0.02·v` рад (не больше 0,6); столкновения
буферами между поездами бьют оба концевых вагона. Вьювер кладёт
соскользнувшие вагоны на рельеф (билинейные высоты, никогда не выше
рельсов, не больше 6 м вниз), опускает опрокидывающийся вагон на более
низкую землю рядом с путём и останавливает скользящий вагон у объекта
мира с CollideFlags (бит 2 сброшен) впереди в пределах половины его
ограничивающего радиуса.
openRTS: правила опрокидывания и скольжения выше; у упавшего вагона рукава
оторваны (магистраль разряжается); за 0,9 рад сцепка повреждается (флаги
16/32), а поезд остаётся целым, как в RTS (до 2026-11-07 он там резался);
обрыв сцепки по усилию пропускает сошедшие вагоны, чьи усилия даёт
заменяющий решатель (PROBABLE: сошедший ВЛ80 в живой записи остался одним
поездом); скользящий вагон замедляется на 5 м/с² (его сопротивление,
делённое на массу); вьювер кренит опрокидывающееся тело вокруг рельса на
стороне падения и двигает скользящее вдоль линии, по которой оно ушло, на
0,3 м ниже.
