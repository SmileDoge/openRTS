# Пульт диспетчера RTS (`RTS/Пульт ДСП/rts_server_DSP.exe`)

> Перевод [`docs/reverse/dispatcher.md`](../../reverse/dispatcher.md).
> Основной текст — английский: при расхождении верен он.

Разобрано только для чтения на копии (`openRTS/build/dsp`, база IDA
`dsp.i64`, формы извлечены в `build/dsp/forms/*.dfm.txt`). 2026-11-01.

## Программа

- PE32, скомпонован 2021-05-10, **C++Builder** (формы VCL, шаблоны
  `PointerArray<RTS…>`, классы `RTSmult_*`), как `rts1.exe` — CONFIRMED.
- Сокеты напрямую через WS2_32 (`WSASocketA`, `bind`, `listen`,
  `WSAAccept`, `WSAConnect`, `WSARecv`/`WSASend`); схема станции рисуется
  OpenGL из значков `.ace` рядом с exe (`points`, `sig`, `platf`, `person`,
  `cargo`, `brakes`, `arrow`, `circle`, `finish`) — CONFIRMED.
- 26 форм (заголовок окна → назначение):

| Форма | Заголовок | Что делает |
|---|---|---|
| `TfMenu` | RTS server startup | маршрут, порт (800), сезон, погода, время, «подключиться к серверу», адрес, ник |
| `TfMenuDSP` | RTS DSP Connect | `TfMenu`, где скрыто всё, кроме адреса, ника и Start |
| `TfPult` | RTS Dispatcher | схема: пауза, выходы стрелок / перевод, поезда, сигналы, сохранить/загрузить ситуацию, платформы, названия станций, время |
| `TfTrains`, `TfTrainEdit` | Поезда | список поездов (STATIC / PLAYER / TRAFFIC / LOOSE; грузовой / пассажирский / другой; холодный / включён / движется), состав, номер, игрок, заметки, текущий тип; башмаки и ручные тормоза с головы / хвоста |
| `TfrmRoutes` | Маршруты поездов | по станциям: точки маршрутов (пути, выходы; неправильный путь, проверка враждебного маршрута, маневры, пассажирская платформа), маршруты (главный путь, одно направление, приоритет, составной), генерация маршрутов |

| `TfBrakes` | Тормоза | задать тормозную магистраль, запасные резервуары, магистраль главных резервуаров, цилиндры поезда |
| `TfPlayers`, `TfBan`, `TfTrAssign`, `TfPlSelect`, `TfSendMsg` | Участники | игроки в игре и в очереди, диспетчеры и их очередь, список запретов, назначить поезд, помощник, сообщения |

Контекстные меню схемы (`TfPult`): сигнал (открыть, автоблокировка,
задать показание, тип, свойства), поезд (перейти, голова в хвосте,
добавить в мир, поставить, задать / собрать / отменить маршрут, пустить,
остановить, сменить направление, разрешить сцепку, скорость, сообщение,
тормоза, удалить), игрок (назначить поезд, сообщение, запрет, отключить,
допустить, помощник, разрешить управление поездом), конечная точка
маршрута (закончить здесь, открыть сигналы до сюда), сервер (журнал,
сбросить заблокированные адреса, трассировка данных, настройки), пункты
погрузки, замедлители.

## Сервер или клиент — CONFIRMED

- `WinMain` первой создаёт `TfMenuDSP` (главная форма) и никогда не
  создаёт `TfMenu`. `TfMenuDSP` наследует `TfMenu` и сохраняет его
  обработчики.
- `TfMenu::btStartClick` (`0x44B570`) только подключается: с ником он
  вызывает `0x42BEA0(address, nickname)` → `WSAConnect` (`0x42C20C`).
  Серверной ветки в этой сборке нет; скрытая галка «подключиться»
  поставлена.
- Сервер всё ещё в exe: `TfPult::btTurnServOnClick` («Сервер», подсказка
  «Включить сервер») запускает поток сервера `0x420D34` → `0x422BB4`
  (`bind`, `listen`) → цикл приёма `0x4213B4`. Зарегистрированное
  оконное сообщение (`0x44A434`) тоже его переключает.
- После подключения `btStartClick` скрывает пять элементов `TfPult` (поля
  +756, +836, +920, +940, +944); +940 — это `btTurnServOn` (обработчик
  настраивает его перед вызовом своего обработчика нажатия) — PROBABLE для
  остальных. Поэтому поставляемый пульт всегда работает как клиент
  диспетчера; кнопка сервера есть, но никогда не показывается.

## Протокол и файлы ситуаций — CONFIRMED (обрамление), PROBABLE (смысл)

- Куски: `u16 id, u32 length`, где длина считает весь кусок (с id и
  длиной); куски вложены. Те же id (`0x4600…0x464F`) использует
  `rts1.exe`: 37 id встречаются в обоих, ещё больше — в одном из них.
- «Сохранить ситуацию» (`0x45D3EC`) пишет файл в этом формате: корень
  `0x4600` (u16 версия 112), `0x4615` мир (имя маршрута, …), затем:
  - `0x460A` состояния стрелок (номер, выбранная ветка…), только тех, что
    не в положении по умолчанию;
  - `0x460B` сигналы (число) → `0x4616` на каждый объект сигнала →
    `0x460C` на каждую голову;
  - `0x4614` игроки (32-байтовый ник, …);
  - `0x4607` поезда → `0x4604` на каждый вагон (имя, …), `0x461C` заметки
    вагона, `0x4636` маршрут поезда;
  - `0x4634` области погоды; `0x4646` / `0x4647` электрификация (секции,
    источники); `0x4645`, `0x464B`, `0x464C`, `0x464E` пункты погрузки и
    глобальные объекты; `0x464F` история грузов.
- `RTS/multdata` (снят при входе) проходится с тем же обрамлением:
  `460D, 4609 (460A × n), 4646 × 3, 4648, 460B (460C × n), 4607, 4603,
  4606, 4601, 4608` — снимок мира, который сервер отправляет клиенту.

## Пробная заплатка: показать кнопку сервера

`build/dsp/patched/rts_server_DSP_server.exe` (копия; `RTS/` не тронут), со
значками и звуками пульта рядом:
- смещение в файле `0x4ADAA` (VA `0x44B7AA`, конец
  `TfMenu::btStartClick`): `33 D2` (`xor edx, edx`) → `B2 01`
  (`mov dl, 1`), так что `SetVisible` оставляет `btTurnServOn` видимой после
  подключения;
- корень игры берётся из реестра (ключ MSTS, `TfMenu_FormCreate`), поэтому
  копия может лежать где угодно.

Сервер раздаёт тот мир, который пульт уже держит: в этой сборке мир (имя
маршрута → `ROUTES\<name>\<name>.tdb`, поезда, сигналы) приходит только от
сервера, к которому он подключился (`0x454EE4` входящие куски → `0x45AE7C`
→ `0x45B0C0`). Самостоятельный сервер с выбором маршрута (старый `TfMenu`)
вырезан из обработчика запуска; чтобы его сделать, нужно подать мир
другим путём (например, файлом ситуации, «Загрузить ситуацию») — ещё не
прослежено.

## Внутриигровой «RTS track control» (`rts1.exe`) — CONFIRMED

Открывается из внутриигрового меню (`0x462FC8`, пункт «Track control»;
пользователь вызывает его через Ctrl+Shift+F7). Модуль `Rts_trackcontrol`;
им пользуется и просмотрщик заданий («RTS Activity track control»,
`0x54FF80`).

- Окно `RTSTrackControlWnd` «RTS track control» (`0x549A60`), 500×500 в
  50,50, свой контекст GL и значки (`0x549650`); фон
  `glClearColor(0.8, 1.8, 0.8)` = светло-зелёный; начальный масштаб 16 (у
  карты RE — 512). Системное меню: Show sidings, Show electrosections, слои
  грузов.
- Отрисовка `0x53F990`: тот же движок схемы, что у карты RE и пульта
  (узлы пути в мировых координатах, выставленные ветки зелёные, сигналы,
  названия платформ и станций синие / оливковые, поезда, пункты погрузки,
  события задания «Event %i:%i», выбранный маршрут, силы в сцепках в Н /
  кН красным, три кнопки справа вверху).
- Мышь (`0x548C8C`, `0x548E40`): перетаскивание правой кнопкой сдвигает
  (курсор ограничен окном), щелчок правой открывает контекстное меню
  (`0x547F24` → `0x5439E4`), щелчок левой выделяет; колесо меняет масштаб.
- **Названия на схеме (CONFIRMED, `0x53F990`; масштаб = половина вида /
  64 м):**
  - названия станций: список строится при открытии окна (`0x5555D8` →
    `0x555624`): каждый элемент платформы считается под именем своей
    станции (`lstrcmpiW`), подпись — в скользящем среднем положений
    элементов. Рисуется чёрным Arial 16 в среднем плюс (0.03, 0.03)
    половины вида (вправо и вверх), пока масштаб < 3500 и элементы × 300 >
    масштаба — крупные станции подписаны дальше всех;
  - значки платформ и стоянок, пока масштаб < 250 (флаги «показывать
    платформы / стоянки»); их названия (Times New Roman 14; синие 0, 0,
    0.7, стоянки оливковые 0.5, 0.5, 0) — только пока масштаб < 5;
  - шрифты создаются при создании окна (`0x549650`): Arial 16, Times New
    Roman 14, Book Antiqua 16, Arial 12 полужирный.
- Контекстные меню по тому, что под курсором:
  - поезд: Jump to train, Release block point, Show train path, No auto
    remove, Uncouple cars, Trigger board / unboard / tracking event,
    Edit / Cancel / Create route, Save route, Load path…, Save path as…,
    Remove train, Assign to player…, Load for player, Traffic options…, Cast
    to PLAYER / STATIC / TRAFFIC, Start / Cancel shunting;
  - место: Move location, Save location here, Cancel location edit;
  - стрелка на редактируемом маршруте: Switch junction (первый / n-й /
    последний проход);
  - точка маршрута: Change start direction, Remove start / reverse /
    waiting / end / block point, Change waiting time, Turn to normal path /
    static placement;
  - путь: Place start / waiting / reverse / end point;
  - сигнал: Signal info, Force signal update;
  - электрификация: Switch / Reset power source;
  - погрузчик: Switch state (Off / Ready / Load / Unload), Select current
    cargo, Information.
- Обработчик команд (`0x54478C`) правит маршруты поездов модулем маршрутов
  (`0x48B8C8`, `0x48BAF8`, `0x48BBF0`, `0x48D220`, `0x48DD94`, `0x48D0A0`,
  `0x48D470`) — тем же модулем, который нужен шагу 4 для бронирования
  маршрутов.

Итак, у RTS три лица одной схемы: внутриигровой трек-контроль (одиночная
игра / хост: поезда, маршруты, стрелки, сигналы, питание, грузы), карта
редактора маршрутов (слои правки) и пульт диспетчера (работа в сетевой
игре). openRTS: один компонент схемы с этими режимами.

## Модуль маршрутов и бронирование стрелок (`rts1.exe`) — 2026-11-01

CONFIRMED по коду, если не отмечено иное.

**Точки маршрута** (92 байта, `0x4886EC` загружает .pat): +0 флаги
TrPathNode, +4 следующая, +8 следующая по стоянке, +12 номер TrackPDP,
+16 / +20 указатели на следующую / предыдущую, +24 64-байтовая копия
TrackPDP и её путешественника: +40 вид (1 точка на пути, 2 стрелка, 5
блок-точка служебного поезда), +48 узел (стрелка для вида 2), +52 ветка,
+64 смещение, +84 байт направления (для стрелки: 1 = вход с ветки, выход
через корень), +88 расстояние от начала маршрута.
- Для точки-стрелки ветка — та, чей путь доходит до следующей точки; цикл
  по веткам не останавливается на совпадении, поэтому побеждает последняя
  подходящая ветка.
- `0x48BBF0` перестраивает маршрут от правленой точки до следующей точки
  пользователя по главным маршрутам стрелок (или их выставленным веткам),
  вставляя точки-стрелки (правка маршрута в трек-контроле); `0x48BAF8`
  переводит стрелку на маршруте на её следующую ветку и перестраивает.

**Запись стрелки:** +8 по умолчанию (MainRoute), +12 выбранная ветка, +32
число веток, +36 вывод корня, +40 выводы веток (по 8 байт: узел, конец),
+52 очередь бронирований, +56 байт блокировки (через стрелку с ним никогда
не бронируют; UNKNOWN, кто его ставит, PROBABLE пульт диспетчера). Записи
очереди (32 байта): +0 владелец (следователь маршрута поезда), +4 его
точка маршрута (её +52 — нужная ветка), +16 / +20 связи, +24 / +28 время и
расстояние владельца до стрелки, обновляемые `0x48CA28`.
- `0x48C7B8` добавляет владельца в конец (ставит в очередь).
- `0x48C924` ставит владельца первым и переводит стрелку на его ветку;
  бронирования прежнего первого владельца с этой точки и дальше
  освобождаются (`0x48A8AC`).
- `0x48C85C` убирает владельца; стрелка идёт на ветку нового первого
  владельца или в положение по умолчанию.

**Бронирование вперёд** (`0x48A0F8`, из обновления поезда): от текущей
точки поезда, точки-стрелки одна за другой:
- свободна: поставить владельца в очередь, проверить встречные движения
  (`0x48C21C`: другой владелец с другим байтом направления, чьё расстояние в
  пределах досягаемости следующей стрелки), перевести стрелку;
- владелец уже первый: те же проверки, перевести стрелку;
- занята другими: встать в очередь и остановиться там, если только время
  владельца до стрелки (расстояние / скорость плюс горизонт 5000 м /
  скорость или собственный горизонт служебного поезда) не лучше, чем у
  стоящих в очереди: тогда он забирает стрелку (`0x48C924`), проверив
  встречные движения на участке назад до своего бронирования (`0x48C50C`,
  `0x48C654`);
- останавливается на заблокированной стрелке, на точке ожидания, время
  которой ещё не пришло, и на блок-точке, чьи условия (`0x48E36C`) не
  выполнены.

openRTS сохраняет смысл очереди, перехвата и освобождения
(`docs/paths.md`) с более простым приоритетом (на 30 с раньше и держатель
за пределами своего тормозного пути) и блокировкой участка для
однопутных линий вместо `0x48C21C` / `0x48C654`.

## Имена сигналов («литеры») — CONFIRMED (2026-11-01)

Имена живут в базе маршрута (`.rtsdb`, UTF-16
`SIMISA@@@@@@@@@@JINX1R0t`), по одному `SignalUnit` на объект сигнала:
`Position ( tile_x tile_z x y z )` (по нему сервер находит сигнал в TDB:
«Could not find signal in tdb. Location: … Continue?»), `NumSigItems`,
необязательное `Name ( "…" )`, `UnitFlags` (шестнадцатеричное),
`DefaultAspect` (имя показания) — токены записи и чтения в
`rts_server.exe`. В том же файле `SignalTypeShownAsNormal`,
`JunctionDefaultStates ( Junction ( node state ) … )`, `RoutePoints` (Name,
PointType 1/2, Flags, StationName, Point1 / Point2), `RouteTrainRoutes` (ID,
Name, Flags, StationName, Start, End) и `RouteTrainPaths` (RouteID,
Priority, Start, Points). Имя задаётся в «Редактирование сигнала» (поле
«Название», `edtSigName`) и показывается на схеме пульта с «Отображать
литеры сигналов» (`btSigName`, `mnSigName`). В `stepanovka.rtsdb`
пользователя 5 252 сигнальных блока и ни одного имени; установленные
маршруты поставляют `ROUTES/<route>/<RouteID>.rtsdb` с именами (Кубань —
900 из 1 406 сигнальных блоков, Киевский ход — 2 480 из 3 308,
Чернышевск — 1 144 из 1 601, Новокузнецк — 1 584 из 3 506, Павловск —
1 450 из 2 203, Успенск — 797 из 1 125), например «М14», «Ч2». На самих
моделях имя есть только как подобъект NUMBER_PLATE (табличка с текстурой).

**В игре тоже** (`rts1.exe`, одиночная и сетевая игра): `0x4903DC`
(«Loading RTS track database») читает `<путь маршрута><RouteID>.rtsdb`;
каждый `SignalUnit` сопоставляется сигнальному элементу TDB по положению
(тайл и x/y/z в пределах 0,2 м), и его имя сохраняется; затем `0x41B6D0`
создаёт объект-подпись (вид мира 20) на 3 м выше каждого именованного
сигнала.

### Номера вагонов (F7)

- **Формат (CONFIRMED, `0x45C54C`):** вагон +16 печатается как
  `AAAA-BBBB-CCCC`: `n >> 18`, `(n >> 10) & 0xFF`, `n & 0x3FF`, каждая
  часть дополнена нулями до четырёх цифр, между ними `-`.
- **Состав номера (`0x4EF740`, постановка поезда на путь):** биты 10..17 —
  из записи поезда (+20, её поле +52); биты 18 и выше — из записи id поезда
  (+16) или, без неё, следующее значение глобального счётчика
  (`dword_61D6CC`). PROBABLE: младшие биты — UiD записи вагона в составе,
  задаваемый при загрузке состава (составы ЭД4М нумеруют свои вагоны
  3..14). В одиночной игре средняя часть PROBABLE равна 0.
- **openRTS:** каждый вагон сохраняет свой номер при расцепке и сцепке, так
  как поле остаётся с вагоном; часть поезда считает поезда, поставленные на
  путь, средняя часть — 0.
