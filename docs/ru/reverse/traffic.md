# Поезда трафика (ИИ) в RTS

Статический анализ копии `rts1.exe` только на чтение (`build/ida/rts1.i64`,
IDA 9.0 без окна + Hex-Rays, 2026-11-10) вместе с `activity.pdf` RTS (папка
`RTS` сборки 2026-11). Адреса — анализируемого `rts1.exe`.

## Поля поезда, которые задаёт сценарий

**CONFIRMED** (разборщик сценария `0x471B9C` и запись сценария `0x552360`,
которая сохраняет обстановку диспетчера в `.act`). Запись поезда сценария
(`ActivityTrain`, имя-кандидат):

| Смещение | Поле | Примечания |
|---|---|---|
| +4 | `TrainEfficiency` | по умолчанию 1,0, зажимается в [0,03; 2,0] |
| +8, +12 | `TrainAcceleration`: наибольшее ускорение, наибольшее замедление | м/с², отрицательное берётся по модулю |
| +16 | `TrainMaxSpeed` | м/с |
| +20, +24 | `StartupSpeed`, `FinishSpeed` | м/с |
| +28 | `TrainDistanceOfNoReturn` | не меньше 250 м; по умолчанию — общее для сценария |
| +32 | `TrainStartOffset` | м вдоль пути |
| +36 | `TrainTimetableTollerance` | ≥ 0 |
| +60 | `TrainServiceType` | 1 пассажирский, 2 грузовой |
| +72 | `TrainState` | у сервиса трафика по умолчанию 2 |
| +96 | `TrainFlags`; бит 0 — задано время старта, бит 1 — время удаления | оба снимаются, если старт позже удаления |

Объект поезда (один для всех поездов; список `dword_61D794`, следующий в
`+0x18C`): `+0` тип (0 STATIC, 1 PLAYER, 2 TRAFFIC, 3 LOOSE,
4 MASTER_PLAYER, 5 MASTER_TRAFFIC; названия — `0x473CA8`), `+1` грузовой /
пассажирский, `+4` флаги, `+16` его сервис, `+20` его запись сценария,
`+28` / `+32` вагоны, `+36` его путь, `+80` наибольшая скорость, `+84` /
`+88` наибольшие ускорение / замедление, `+92` его скорость (м/с, со
знаком), `+96` его ускорение на этом шаге, `+168` / `+232` точки
расстановки.

## Постановка поезда на путь (`0x4EF740`)

**CONFIRMED**: вагоны откладываются от начала пути (плюс
`TrainStartOffset`) один за другим (`0x481440`); путь сразу отводится
(`0x48A0F8`); поля берутся из записи сценария (+80 ← +16, +84 ← +8,
+88 ← +12; флаги; расписание `0x4FA374`). **Поезду трафика нужны
положительные наибольшая скорость и ускорение** (недостающее замедление
берётся равным ускорению): без них сообщение 0x88, и поезд не ставится —
«TrainMaxSpeed: требуется положительное значение» activity.pdf. Поезд не
ставится, если путь впереди занят (`0x47FE14`).

## Как едет поезд трафика (`0x424488`, обновление поездов)

**CONFIRMED: кинематически.** Для поезда TRAFFIC (и поезда игрока, пока им
управляет игра: `*(dword_61D31C + 68)`, PROBABLE — `AIControlled`
сценария) обновление выбирает ускорение (`+96`), затем
`скорость += ускорение × dt` (с остановкой на 0, без разворота) и отдаёт
скорость первому и последнему вагону. Повагонная физика (сопротивление,
уклон, сцепки, тормозная магистраль, рукоятки DLL) считается только для
поездов LOOSE и для поезда, которым ведёт игрок; STATIC стоят. Поезд
трафика — одно жёсткое тело, идущее по своему пути.

Регулятор (`0x424488`, блок от проверки `== 2`):
- **Скорость, с которой можно ехать** — наименьшая из: общего предела
  (`dword_61D7D0`), `TrainMaxSpeed`; действующих и впереди ограничений
  (поля +104, +108, +116..+128, +144: пути, следующего, сигнала,
  `ModifyVelocity`; что из них что — UNKNOWN), каждое — на
  `TrainEfficiency`; кривых на 3 км вперёд (`0x480204`): таблицы
  `TrafficLimitsTable` сценария, до 10 порогов радиуса (`dword_61D7DC`..)
  со своими скоростями (`dword_61D804`..), 300 м/с (нет ограничения) выше
  них, на эффективность.
- **Где нужно сбросить скорость**: следующая точка остановки на пути
  (`+60`, в `+72` м: конец отведённого пути, точка ожидания, реверсная
  точка, остановка на станции; по виду точки +40: вид 2 — на 40 м раньше,
  вид 5 — на полвагона), конец пути с `FinishSpeed`, скоростные знаки
  впереди (вид 8), поезд впереди в том же направлении (сцепки `0x505C08`,
  на 10 м раньше). Из всех целей (vₜ через d м) берётся та, что требует
  самого сильного торможения, (v − vₜ) / d.
- **Ускорение**: ниже допустимой скорости — `+84` (не больше, чем до неё
  за шаг); выше — −`+88`. Подход к цели самого сильного торможения (vₜ
  через d м), при Δv = v − vₜ и обычном тормозном пути
  d₀ = (Δv / 2 + vₜ) · Δv / замедление = (v² − vₜ²) / 2·замедление: дальше
  4 d₀ — едет (ускорение срезается, чтобы не проскочить отметку 4 d₀);
  между 4 d₀ и d₀ тормозит с (0,25 + 0,75 · (1 − (d − d₀) / (4 d₀ − d₀)))
  · замедление — от 0,25 у 4 d₀ до полного у d₀; ближе d₀ — 2 ·
  замедление. За поездом впереди замедления удваиваются (а d₀ вдвое
  меньше, если уже поздно).
- **Остановки**: на остановке на станции (вид 6) встаёт по платформе (по
  центру или по её краю, +108 остановки: 1 / 2), затем ждёт своё время
  (`+132`: время остановки, пересчитанное на пассажиров, `+116` +60 / +64),
  не уходя раньше времени отправления; прибытие и отправление уходят сети
  / сценарию событиями 22 и 23 (`0x5C8C50`). В остальных местах стоящий
  поезд ждёт `+136` с.
- **Что показывает**: из ускорения — условное положение контроллера
  (0,1..1, меньше на скорости): звук и дизель каждого двигателя (`+512` на
  двигатель, `+32`), токоприёмники электровоза поднимаются ниже его
  скорости `+632`.

## Отвод пути

`0x48A0F8` (`docs/ru/reverse/dispatcher.md`): стрелки впереди по очереди,
очереди, перехват по времени до стрелки, встречные движения; останавливает
у закрытой стрелки, у точки ожидания, срок которой не настал, и у
блок-точки, условия которой (`0x48E36C`: список сервисов / поездов точки,
`+100` / `+104`, по её флагу `+132` бит 3) говорят, что она держит этот
поезд.

## Умолчания и параметры сценария

**CONFIRMED** (`0x407588`, при загрузке маршрута; `0x470A3C`, верхний
уровень сценария):
- Таблица кривых `dword_61D7DC` (радиусы) / `dword_61D804` (скорости), если
  в сценарии нет `TrafficLimitsTable`: 6000 м — 75 м/с, 5000 — 55, 3500 —
  45, 2500 — 38, 2000 — 32, 1500 — 28, 1000 — 25, 600 — 17, 300 — 11,
  200 — 7. Таблица сценария заменяет все десять (сначала обнуляются);
  запись со скоростью не больше 0 отбрасывается.
- Общий предел `dword_61D7D0`: `SpeedLimit` маршрута из `.trk`.
  `dword_61D7D4`: его `TempRestrictedSpeed` (5 м/с, если нет или не
  положительный) — скорость, которую регулятор берёт для ограничения,
  заданного как −1.
- `TrainsDistanceOfNoReturn`: по умолчанию 5000 м, не меньше 250.

## Блок-точки (`0x475B1C`)

**CONFIRMED** поля: `id` (+4), `enabled`, `location` (+32..+44: тайл X,
тайл Z, −x, y, z — RTS хранит x с обратным знаком), `numpassed` (+108),
`releaseontime` (+112), `releaseonreach` (+116 / +120 сервис, поезд),
`releaseonapproach` (+124 / +128), `releasemanual`, `pointaffects` (+104
число, +100 номера), `suppresserrors`. `Location` читается как пять чисел;
то, что редактор RTS пишет после них (`NumPasses: 1`, есть в каждой
блок-точке сценариев MaDaDev), не читается: у `NumPassed` свой ключ.

## Названия

**CONFIRMED** (строки рядом с ними в `rts1.exe`): флаги поезда
`OBEY_DISTANCE`, `OBEY_INFO`, `MUTE`, `NO_LIGHTS`, `PHYSX`,
`IGNORE_SIGNALS`, `OBEY_SHUNTING`, `DOORS_LOCKED`, `OWNS_PATH`,
`IGNORE_SPEED_LIMITS`, `CRITICAL_TRAIN`; флаги сервиса `FORCE_REMOVAL`,
`CHECK_IF_BUSY`, `NO_REMOVE`, `CHECK_PLAYER_APPROACH`; `ServiceStarts`
`SINGLE`, `SERIAL` (и `NONE`). `PHYSX` — PROBABLE: поезд трафика со своей
физикой (не прослежено).
