# Текстуры ACE

Устройство текстур MSTS / RTS `.ace` таким, каким его содержит контент RTS;
читает `formats/src/ace_file.cpp`, пишет `formats/src/ace_writer.cpp`
(`openrts-ace`, 2026-11-10). Обзор: заголовки 6000 файлов `.ace` этой
установки (`GLOBAL`, `ROUTES`, `TRAINS`); устройство проверено побайтно на
`GLOBAL\TEXTURES\7bridge1.ace`, `7bridge2.ace`, `A1t27mTurntable.ace`.
CONFIRMED (файлы), если не сказано иначе.

## Оболочка

- Без сжатия: `SIMISA@@@@@@@@@@` (16 байт), затем тело.
- Сжатая: `SIMISA@F`, u32 с размером тела, `@@@@`, затем поток zlib (с его
  заголовком) с телом. Большинство файлов RTS сжаты.

Смещения внутри тела считаются от его начала (заголовка), в несжатом файле
— через 16 байт от начала файла.

## Тело

- Заголовок, шесть u32: версия (1), опции, ширина, высота, формат, каналы.
- 128 байт: текст программы (`compace` пишет "Unknown" и "ACE file created
  by compace"); не читается.
- Каналы: каждый по два u64 — его биты (8 или 1 у маски) и вид:
  2 маска, 3 красный, 4 зелёный, 5 синий, 6 альфа.

Опции: бит 0 — цепочка мипмапов, бит 4 (0x10) — сырые данные (DXT1), бит 2
(0x04) ставят программы у файлов с цепочкой. RTS берёт уровни из файла у
квадратной текстуры с опциями ровно 5 (построчные) или 17 / 21 (DXT1),
иначе строит свои (`0x44F554`, см. `ace_file.hpp`).

| Вид | Формат | Каналы | Встречаются опции |
|---|---|---|---|
| RGB | 0x0E | R G B | 5, 0, 1 |
| RGB + маска | 0x10 | R G B маска | 5, 0 |
| RGBA | 0x11 | R G B маска альфа | 5, 0, 1 |
| DXT1 | 0x12 | R G B, + маска при прозрачности | 21, 17 |

### Построчные (RGB, RGB + маска, RGBA)

Таблица u32 смещений строк: по одному на строку первого уровня, а с
цепочкой — на строку каждого уровня (высота уровней делится пополам до 1;
ширина тоже, не меньше 1). Затем строки: в каждой плоскости каналов в их
порядке, 8-битная — `width` байт, маска — `(width + 7) / 8` байт, старший
бит первым, 1 — непрозрачно. Некоторые программы пишут таблицу, указывающую
за конец файла (`terrain.ace` Павловска); строки там идут по порядку после
таблицы, и игры так их и читают.

### DXT1 (сырые)

Таблица u32 смещений уровней, по одному на уровень до 1 x 1. Уровень 4 x 4 и
больше: u32 с числом байт, затем 8-байтовые блоки DXT1 по строкам. Уровни
2 x 2 и 1 x 1 — не блоки, а строки, как в построчном файле (плоскости R G B
и маска, если она в файле есть): 12 и 3 байта, с маской 14 и 4. С каналом
маски четвёртый цвет трёхцветных блоков прозрачен (альфа в 1 бит).

**На GPU** (openRTS, 2026-11-10): DXT1 ACE со своими уровнями (квадратный,
options 17 / 21) уходит на GPU как BC1 — блоками файла как есть, уровни до
4 x 4 (в 8 раз меньше RGBA8; RTS отдаёт OpenGL уровни DXT1 так же,
`glCompressedTexImage2D`, `shape-rendering.md`). BC1
видеокарты делает четвёртый цвет трёхцветного блока прозрачным чёрным,
что бы ни говорил файл; в контенте 2026-11 им пользуются только текстуры с
маской (1325 из 4143 файлов DXT1 в TRAINSET, на Кубани и в Новокузнецке;
без маски — ни один), а файл без маски, который бы им пользовался, ушёл бы
на GPU как RGBA8. Остальные ACE (там 83 % текселей, несжатые) и устройства
без BC-текстур остаются в RGBA8. «Скорый поезд 77» Новокузнецка на старте:
текстуры на GPU — с 5,6 ГБ до 3,6 ГБ.

## openrts-ace

Пишет то, что показывает таблица выше: RGB 0x0E, RGB + маска 0x10, RGBA 0x11
(маска — альфа >= 128, и 8-битная альфа), DXT1 0x12 (канал маски, если у
какого-то текселя альфа меньше 128); цепочку изображения со сторонами —
степенями двойки из фильтра 2 x 2, как у RTS, с опциями 5 / 21, иначе без
неё (опции 0 / 16: RTS строит уровни сам); по умолчанию сжато. Его блоки
DXT1: главная ось цветов, затем подгонка концов по методу наименьших
квадратов к выбранным цветам (три круга). `7bridge2.ace` (DXT1 с маской),
записанный заново, читается в среднем в пределах 0,01 из 255 на канал
(`tests/ace_png_test.cpp`). UNKNOWN: читает ли RTS опции 16 (сырые без
цепочки); у всех файлов DXT1 в контенте цепочка есть.
