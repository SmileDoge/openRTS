# Материалы openRTS (PBR)

Новый рендер openRTS освещает поверхности физически корректно (GGX, свет
самого неба; docs/ru/experimental-effects.md). Чем поверхность является для
этого света, берётся только из данных RTS, если материал openRTS не говорит
больше: насколько она шероховатая или гладкая, металл ли она, её затенение,
мелкий рельеф, что светится само. Материалы — файлы JSON5 в VFS, поэтому
мод добавляет их, не трогая контент (этап PBR 4, 2026-11-17).

- Без файлов материалов всё выглядит как раньше (светоматериалы RTS:
  HiShine и LoShine блестят, Normal матовый).
- Рендер RTS («как рисует RTS») их никогда не читает.
- Действуют в новом рендере с HDR и включённым PBR.

## Где они лежат

| Файл | Для чего | Формат |
|---|---|---|
| `body.material.json5` рядом с `body.ace` | для всех моделей с этой текстурой | `openrts-material/1` |
| `MATERIALS/body.material.json5`, `MATERIALS/<поезд>/body.material.json5` | для всех `body.ace`, где бы они ни лежали; в подпапке — только в папках поездов, в имени которых она есть (`#` — любые символы) | `openrts-material/1` |
| `loco.s.material.json5` рядом с `loco.s` | для некоторых частей этой модели | `openrts-shape-material/1` |

Главное место — файл текстуры: одна текстура часто стоит на десятках
моделей через папки-алиасы, и материал пишется один раз. Файл модели — для
исключений: текстуре на одной модели нужен другой вид (стекло на текстуре,
общей с кузовом). Для ночной или сезонной текстуры
(`TEXTURES/NIGHT/body.ace`) читается файл базовой текстуры, а поверх него —
свой файл варианта (`NIGHT/body.material.json5`).

Мод кладёт их по тому же пути: `MODS_OPENRTS/<мод>/TRAINS/TRAINSET/LOCO/body.material.json5`.

**Папка MATERIALS** (2026-11-23, тестеры: маски снега, не трогая поезда).
Папка `MATERIALS` в корне установки (или мода) хранит материалы, которые
находятся по имени текстуры, где бы текстура ни лежала: один файл
одевает все поезда с ней (папок ЧС7 18, и в каждой свой
`zdsLoco_chs7-6A.ace`).

- Файл прямо в `MATERIALS` действует на все текстуры с этим именем.
- Файл в подпапке — только на текстуры, у которых папка поезда (та, что в
  `TRAINS/TRAINSET`, иначе своя папка текстуры) содержит имя подпапки, без
  учёта регистра: `MATERIALS/chs7/` для `mdd_CHS7-016` .. `mdd_CHS7-318`,
  `MATERIALS/mdd_vl10-/` для ВЛ10, но не ВЛ10у (`mdd_vl10u-…`). С `#` имя —
  шаблон всего имени папки, `#` — любые символы (`MATERIALS/mdd_CHS7-2#/`;
  `*` и `?` Windows в имени папки не разрешает). Распространённое имя
  (`kuz1.ace`) кладите в такую подпапку, а не прямо в `MATERIALS`.
- Более глубокие папки — только для порядка; решает верхняя.
- Карты в файле ищутся рядом с ним, как везде.
- Слои как у файла текстуры: сначала общие, затем из подпапок, затем файл
  рядом с текстурой, каждый поверх предыдущего.
- Папка перечитывается, когда меняется VFS (горячая перезагрузка).

## Как собирается материал части

По полям, каждый слой поверх предыдущего:

1. RTS: светоматериал части (HiShine — шероховатость 0,35, LoShine — 0,5,
   Normal и остальные — 1 с десятой долей отражения, Circumference и
   DarkShade — без отражения), её текстура, альфа-тест и смешивание;
2. файл текстуры (потом её ночного или сезонного варианта);
3. записи файла модели для этой части, по порядку;
4. изменения в инспекторе (F12), пока не сохранены.

Поле, которое слой не задал, берётся из нижнего. Число никогда не
отключает карту из нижнего слоя. Новая карта без своей пары сбрасывает пару
на значение по умолчанию (`orm` без `layout` — "orm"; `normal` без
`normal_y` — "up"), так что пара от другой карты не переносится. Новый
`orm` убирает отдельные карты под ним.

Как в glTF, при карте число — её множитель: если шероховатость,
металличность или доля отражения ещё от RTS, слой с картой шероховатости
или металличности делает их 1 (как блестит поверхность, говорит карта).
Карта свечения без множителя где-либо получает 1; без карты ничего не
светится.

## Файл текстуры

```json5
// body.material.json5, рядом с body.ace
{
  format: "openrts-material/1",
  orm: "body_orm.png",        // R затенение, G шероховатость, B металличность
  normal: "body_n.png",
  normal_y: "up",             // "down" — карта из пресетов DirectX / Unreal
  // без карт, только числа:
  // roughness: 0.45, metallic: 0,
  emissive: "body_e.png", emissive_strength: 2,
}
```

В `sdk/materials/template.material.json5` все ключи с комментариями.

| Ключ | Значения | Что |
|---|---|---|
| `format` | `"openrts-material/1"` | обязателен; другая основная версия не читается |
| `roughness` | 0..1 | воспринимаемая шероховатость, 0 — зеркало; при карте — множитель |
| `metallic` | 0..1 | 0 — диэлектрик (краска, стекло, дерево), 1 — голый металл; при карте — множитель |
| `specular` | 0..1 | доля отражения диэлектрика (KHR_materials_specular) |
| `reflectance` | 0..1 | F0 диэлектрика (0,04 — IOR 1,5) |
| `base_color_factor` | [r, g, b] или [r, g, b, a], 0..1 | множитель текстуры, линейный |
| `base_color` | файл | вместо текстуры модели (перекрашенный цвет) |
| `orm` | файл | упакованные затенение, шероховатость, металличность |
| `layout` | `"orm"`, `"mrao"`, `"hdrp_mask"` | каналы упакованной карты (ниже) |
| `ao_map`, `roughness_map`, `metallic_map` | по файлу | отдельные карты (их красный канал) поверх канала `orm` |
| `ao_strength` | 0..1 | насколько затемняет карта затенения |
| `normal` | файл | карта нормалей в касательном пространстве |
| `normal_y` | `"up"`, `"down"` | зелёный канал: OpenGL / glTF / Blender — вверх, DirectX / Unreal — вниз |
| `normal_strength` | 0..2 | |
| `emissive` | файл | что светится само, гамма 2,2 |
| `emissive_factor` | [r, g, b], 0..1 | |
| `emissive_strength` | 0..100 | |
| `height` | файл | рельеф: белое — его верх, чёрное — на `height_scale` ниже (см. ниже) |
| `height_scale` | 0..0,1 | глубина рельефа в метрах (по умолчанию 0,01) |
| `height_reference` | 0..1 | уровень карты, на котором лежит поверхность модели (по умолчанию 1 — белое) |
| `snow` | файл | снег на модели: его цвет (гамма 2,2), в альфе — где он лежит (ниже) |
| `alpha_mode`, `alpha_cutoff`, `double_sided`, `wet` | | читаются, но пока не действуют (об этом предупреждение) |

Файлы — относительно папки файла материала (без абсолютных путей и букв
дисков), PNG или ACE. Незнакомый ключ, значение вне диапазона или не того
типа: предупреждение в журнале, поле пропускается. Файл, который не
разбирается: ошибка в журнале; если в этом запуске он уже читался удачно
(горячая перезагрузка), остаётся то чтение.

### Упакованные карты

Внутри openRTS упакованная карта всегда ORM, остальные перепаковываются при
загрузке:

| `layout` | R | G | B | A |
|---|---|---|---|---|
| `orm` (glTF, Blender, Substance «glTF PBR Metal Roughness») | затенение | шероховатость | металличность | - |
| `mrao` | металличность | шероховатость | затенение | - |
| `hdrp_mask` (маска Unity HDRP) | металличность | затенение | маска деталей (не используется) | гладкость (шероховатость = 1 − гладкость) |

Материалы PBR из Trainz (`m.pbrmetal`, `m.pbrmetalmasked`) хранят карту `_p`:
R — металличность, G — шероховатость, B — затенение. Это `orm: "body_p.png",
layout: "mrao"`. Если вместо этого написать `roughness_map` и `metallic_map`,
обе возьмут её красный канал (металличность, почти везде 0), и поверхность
станет зеркалом; на карту шероховатости, у которой красный канал везде 0, а
другие нет, в журнал (консоль, F2) пишется предупреждение.

Пресет Substance Painter «Unreal Engine 4 (Packed)» пишет те же каналы,
что ORM (R затенение, G шероховатость, B металличность), но карта нормалей
у него в формате DirectX: `normal_y: "down"`. Перед тем как полагаться на
пресет, проверьте его выходные каналы в окне экспорта.

Цветные карты (`base_color`, `emissive`) — sRGB (берутся как гамма 2,2, как
текстуры ACE); ORM и карты нормалей — линейные данные.

### Карты высот (рельеф, parallax)

Серое изображение в тех же текстурных координатах, что и цвет: белое —
верх рельефа, чёрное — его низ, между ними `height_scale` метров (заклёпки
2–5 мм, рёбра и швы панелей 5–15 мм). Собственная поверхность модели
лежит на уровне карты `height_reference`: 1 (белое), когда рельеф врезан в
поверхность (швы, канавки), и уровень основного листа, когда детали из него
выступают (заклёпки, рёбра; у карты, где лист — тёмно-серый 28, это 0,11).
Что светлее этого уровня, выступает, что темнее — уходит вглубь.

- openRTS сдвигает все карты части (цвет, ORM, нормали, свечение) туда, где
  взгляд встречает рельеф (parallax occlusion mapping: 8 шагов при взгляде
  в лоб, до 32 при взгляде вскользь, между двумя последними — интерполяция).
  Контур остаётся плоским, и своей тени рельеф не отбрасывает.
- Касательные не нужны: шаг по поверхности переводится в шаг по картинке
  по экранным производным, поэтому рельеф работает и на зеркальных
  развёртках, и на частях без карты нормалей.
- У вырезанной части (альфа-тест: окна кузова) альфа берётся несдвинутой
  (вырез — край модели); стекло (с прозрачностью) рельефа не получает.
- До «Рельеф до» метров от глаза (по умолчанию 30), на последней четверти
  гаснет; настройка «Рельеф по картам высот материалов (parallax, не как в
  RTS)» в «Графике» его выключает (`parallax`, `parallax_distance`;
  `--parallax on|off`).
- Хранится в BC4 (один канал, восьмая часть RGBA8), когда текстуры
  сжимаются (`.h4` в кэше).
- Карта высот — это сами высоты: ровные места одного серого, ребро —
  светлая полоса шириной с ребро. Изображение контуров деталей (запекание
  граней или кривизны) поднимает только контуры и почти ничего не даёт.

### Карты снега (2026-11-23)

Карта снега на модели, нарисованная по развёртке её собственной текстуры:
цвет снега, а в альфе — где он лежит (255 — гуще всего, 0 — нет). Больше
материалу ничего не нужно, ORM и прочее тащить не надо:

```json5
// kuz1a.ace -> kuz1a.material.json5: все модели с текстурой kuz1a.ace
{ format: "openrts-material/1", snow: "kuz1a_snow.png" }
```

Развёртка у каждой модели своя, поэтому карта идёт к текстуре (или к
записям файла модели, ниже), а не к типу поезда. Сколько её видно
(`ModelLighting::snow_cover`, 0..1), решает сцена: летом нисколько, зимой
сразу 0,8, после примерно 4 минут снегопада вся, после снегопада не зимой
сходит примерно за 10 минут. Растёт от самого толстого снега (наибольшей
альфы) наружу. Выключается вместе с «Дождь и снег».

## Файл модели

```json5
// loco.s.material.json5, рядом с loco.s
{
  format: "openrts-shape-material/1",
  primitives: [
    { match: { name: "Glass_BlendATexDiff" }, roughness: 0.05, metallic: 0 },
    { match: { image: "body.ace", matrix: "BODY" }, orm: "body_orm.png" },
    { match: { index: 12, image: "lamp.ace" }, emissive: "lamp_e.png", emissive_strength: 4 },
    { match: { image: "bogie.ace", all: true }, roughness: 0.8 },
  ],
}
```

`match` выбирает части (primitive state) модели; каждое заданное поле
должно совпасть:

| Поле | Что |
|---|---|
| `name` | имя части в модели (имя блока `prim_state`) |
| `image` | имя файла её текстуры (без папок, регистр не важен) |
| `matrix` | узел, на котором она висит |
| `index` | её номер среди primitive state модели |
| `all` | `true` — все совпавшие части |

Если совпало больше одной части, запись не применяется ни к одной
(предупреждение их перечисляет), пока `all: true` не скажет иначе; не
совпало ни одной — тоже предупреждение. Самый устойчивый выбор: имя, если
его нет у другой части (у 74 % моделей установки все части с именами, но
уникальные — только у 54 %), иначе картинка и узел, иначе номер с
картинкой. `openrts-shape export` пишет самый устойчивый `match` каждой
части в glTF; инспектор выбирает так же.

## Как сделать материал, по шагам

1. **Выгрузить модель.** `openrts-shape export TRAINS/TRAINSET/LOCO/loco.s --out loco_gltf`
   пишет ближний уровень детализации в glTF 2.0: `loco.gltf`, `loco.bin` и
   текстуры в PNG. Узел на каждую матрицу с её именем, материал на каждую
   часть с текстурой как базовым цветом; в `extras.openrts` каждого
   материала — модель, номер части, её имя, картинка, узел, шейдер,
   светоматериал и её `match`. Левосторонние координаты MSTS становятся
   правосторонними glTF (z меняет знак, порядок вершин треугольников
   разворачивается); текстурные координаты остаются как есть (у обоих
   (0, 0) — левый верхний угол картинки).
2. **Рисовать.** Импортировать в Substance Painter или Blender, взять
   исходную текстуру как базовый цвет, запечь затенение, нарисовать
   шероховатость и металличность. Развёртку модели не менять.
3. **Выгрузить карты** пресетом «glTF PBR Metal Roughness» (ORM, нормали с
   зелёным вверх) и назвать по текстуре: `body_orm.png`, `body_n.png`. Карты
   нормалей — в касательном пространстве MikkTSpace (по умолчанию в Blender
   и Substance): openRTS строит такие же касательные.
4. **Написать материал** по `sdk/materials/template.material.json5` рядом с
   текстурой (файл модели — для исключений).
5. **Проверить в openRTS.** Новый рендер с HDR и PBR; в панели графики
   «Показать материал (проверка)» показывает цветом базовый цвет,
   шероховатость, металличность, нормали после карты, затенение (карты и
   GTAO) или свечение (`--material-view base|roughness|metallic|normal|ao|emissive`
   на один запуск). Файлы отслеживаются: сохранили материал или карту —
   модель перерисовалась. Инспектор (F12, «PBR-материал (openRTS)»)
   показывает материал части, откуда взято каждое поле (RTS, текстура,
   вариант текстуры, модель, инспектор) и что не так с файлами.
6. **Собрать мод**: файлы по путям контента в папке, затем
   `openrts-pack pack <папка> -o MODS_OPENRTS/<мод>.zip` (или сама папка в
   `MODS_OPENRTS`), и мод в списке `openrts.ini`.

`sdk/materials/demo-vl80s-606` — такой мод, только с числами: краска кузова
ВЛ80с-606 (шероховатость 0,42), крыша (0,75), стёкла (0,05) и тележки (0,8).

Типичные значения: краска 0,35–0,5, ржавое железо около 0,7, резина около
0,9, стекло около 0,05, катаная поверхность рельса около 0,2 при
металличности 1. Для кузова локомотива хватает карт 2048 x 2048; карта
загружается в RGBA8 со своими мипами (около 5,3 МБ при 1024 x 1024, 21 МБ
при 2048 x 2048).

Контент принадлежит авторам: дорабатывать и раздавать стоковые модели можно
только с их разрешения (у стока MaDaDev своя лицензия). Файл материала не
содержит ничего от модели и её текстур — только имена и числа; карты,
нарисованные поверх текстуры, — производное от неё.

## Инспектор

F12, выбрана часть, «PBR-материал (openRTS)»: часть модели (номер,
текстура, имя и узел), её материал как он рисуется и откуда каждое поле,
сообщения о её файлах и ползунки шероховатости, металличности и доли
отражения. Изменение видно сразу; «Сохранить материал в мод» пишет файл
модели (`<модель>.material.json5`) в мод инспектора (по умолчанию
`openrts_edits`). Он машинный: записи, уже бывшие в файле модели,
сохраняются, комментарии — нет; ваш собственный файл в другом месте никогда
не меняется (копия в моде важнее него).

## Как это рисуется

- Числа и множители части передаются на видеокарту в её параметрах
  отрисовки (224 байта, было 160); карты привязываются рядом с её текстурой
  (привязки 3–6 группы модели), без карт — заглушки 1 x 1 (ORM белая,
  нормаль плоская, свечение чёрное, высота белая), читаются только там, где
  карты есть.
- Затенение из карты затемняет только непрямой свет (небо, отражённый от
  земли свет, свет в кабине), вместе с GTAO — по более тёмному из двух (не
  оба: одни и те же углы дважды); отражение неба берёт его как затенение
  блика. Солнце и лампы им не затемняются.
- Картам нормалей нужны касательные: openRTS строит их MikkTSpace
  (эталонная реализация, как запекают Blender и Substance) только для
  моделей с картой нормалей, отдельным вершинным буфером со вторым
  пайплайном (вершины остальных моделей остаются по 40 байт). Текстурные
  координаты берутся с v вверх, поэтому битангенс смотрит вверх по картинке,
  как зелёный канал карты; вершина на треугольниках обеих ориентаций
  (зеркальный шов развёртки) раздваивается. Треугольники без площади в
  развёртке остаются без карты нормалей (их число в сообщении).
- Горячая перезагрузка: файлы материалов и карты — зависимости модели.

## Пока нет

- `alpha_mode`, `alpha_cutoff`, `double_sided` (пайплайны — от RTS).
- Влажность (`wet`): потемнение и блеск в дождь.
- Карты DDS (ACE в блочных форматах openRTS читается, `docs/ru/reverse/ace.md`).
- Материалы земли, трансферов и лесов.
- glTF обратно в модель (только выгрузка).
