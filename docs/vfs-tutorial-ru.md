# VFS openRTS: папки, паки и моды — практическое руководство

Справочник с подробностями — `docs/vfs.md`. Здесь — как этим пользоваться.

## 1. Главная идея

openRTS видит весь контент как **одно дерево файлов** с путями от корня
установки (папки, где лежат `ROUTES`, `TRAINS`, `GLOBAL`):

```text
ROUTES/Kuban_RTS/Kuban_RTS.trk
TRAINS/TRAINSET/VL10/VL10.eng
GLOBAL/TEXTURES/...
```

Откуда физически берётся файл — из обычной папки, из ZIP-пака или из мода —
игре всё равно. Несколько источников накладываются слоями, верхний слой
перекрывает нижний **по каждому файлу отдельно**.

Правила путей как в RTS:
- регистр не важен (`Routes/kuban_rts` = `ROUTES/Kuban_RTS`);
- `\` и `/` равнозначны;
- `..` работает и между источниками: модель в паке может ссылаться на
  текстуру `../VL80_common/TEXTURES/body.ace`, которая лежит в обычной папке
  или в другом паке;
- абсолютные пути (`C:\...`) запрещены, выйти выше корня нельзя.

RTS ничего не знает о паках — сам `rts1.exe` по-прежнему читает только
папки. Паки нужны openRTS.

## 2. Слои и их порядок

Снизу вверх (каждый следующий перекрывает предыдущие):

| # | Слой | Где лежит | Для чего |
|---|---|---|---|
| 1 | базовые паки | `PACKS/base/*.zip` | маршруты, составы, GLOBAL в архивах |
| 2 | папки установки | `ROUTES`, `TRAINS`, `GLOBAL`, `SOUND`, `GUI` | обычная установка, локальные правки |
| 3 | патчи | `PACKS/patch/*.zip` | исправления к пакам **и** к папкам |
| 4 | моды | `MODS_OPENRTS/<имя>/` или `MODS_OPENRTS/<имя>.zip` | замены и дополнения, по списку в `openrts.ini` |

Что из этого следует:
- **папка бьёт базовый пак** — поправил файл в папке, и он важнее
  архивного оригинала;
- **патч бьёт папку** — исправление можно выпустить даже для маршрута,
  который у человека установлен папкой;
- **мод бьёт всё**.

Внутри одного слоя паки сортируются по `Priority` из манифеста (больше —
важнее), при равенстве — по имени файла.

> Важно: openRTS подключает только `PACKS/base/` и `PACKS/patch/`.
> ZIP, лежащий прямо в `PACKS/`, **не монтируется** — кладите его в
> `PACKS/base/` или `PACKS/patch/`.

`RTS/MODS` — это папка плагинов (DLL) самого RTS, к модам openRTS отношения
не имеет.

## 3. Файл `openrts.ini`

Лежит в корне установки (`D:\Games\MDDRTS\openrts.ini`). Необязателен: без
него действуют значения по умолчанию.

```ini
[VFS]
Folders = ROUTES, TRAINS, GLOBAL, SOUND, GUI   ; какие папки монтировать (это значение по умолчанию)
HotReload = 1                                  ; следить за изменениями файлов (во вьювере включено и так)
ReconcileSeconds = 180                         ; страховочная пересверка папок, секунды

[Mods]
1 = HD_Kuban_Textures        ; папка MODS_OPENRTS\HD_Kuban_Textures
2 = VL80k_Sounds.zip         ; архив MODS_OPENRTS\VL80k_Sounds.zip
```

- Мод, которого нет в `[Mods]`, **не подключается**, даже если лежит в
  `MODS_OPENRTS`.
- Чем больше номер, тем важнее мод (2 перекрывает 1).
- Комментарии — после `;`.

## 4. Утилита `openrts-pack`

Собирается вместе с проектом:
`openRTS\build\tools\pack\Release\openrts-pack.exe`.

```text
openrts-pack pack <папка|файл>... -o <out.zip> [--as <виртуальная папка>]
             [--method deflate|zstd] [--level N] [--threads N]
             [--name N] [--kind K] [--priority N] [--version V] [--requires A,B]
openrts-pack unpack <pack.zip> <корень установки>
openrts-pack convert <in.zip> -o <out.zip> --method deflate|zstd [--level N]
openrts-pack list <pack.zip>
openrts-pack verify <pack.zip>
openrts-pack conflicts <корень установки>
```

### 4.1. Упаковать маршрут

```bat
cd /d D:\Games\MDDRTS
openRTS\build\tools\pack\Release\openrts-pack.exe pack ROUTES\Kuban_RTS ^
    -o PACKS\base\Kuban_RTS.zip --method zstd --kind route --version 2026.11
```

- Пути внутри архива получаются **от корня установки**:
  `ROUTES/Kuban_RTS/...`. Утилита сама понимает, к какой установке
  относится папка (ищет рядом `ROUTES`/`TRAINS`/`GLOBAL`/`PACKS`).
- Если исходная папка лежит вне установки, укажите, куда она должна
  попасть: `--as ROUTES/Kuban_RTS`.
- Уже сжатые файлы (`SIMISA@F`-модели и текстуры, `.wav`, `.ogg`, `.dds`,
  `.png`, `.jpg`…) кладутся без сжатия — читать их из пака так же быстро,
  как из папки. Текст (`.w`, `.eng`, `.wag`, `.sms`, `.dat`, `.trk`, `.tdb`)
  сжимается.
- В архив пишется манифест `openrts-pack.ini` из ключей `--name`,
  `--kind`, `--version`, `--priority`, `--requires`.

После этого папку `ROUTES\Kuban_RTS` можно убрать (для openRTS; RTS она
по-прежнему нужна) — маршрут будет читаться из пака.

### 4.2. Упаковать подвижной состав

```bat
openrts-pack pack TRAINS\TRAINSET\VL80k TRAINS\CONSISTS_RTS\VL80k_train.con ^
    -o PACKS\base\VL80k.zip --kind trains
```

Можно перечислить несколько папок и отдельных файлов — всё ляжет в один
архив со своими путями. Общие папки, на которые ссылаются через `../`
(например `VL80_common`), можно положить в этот же пак или в отдельный —
ссылки разрешатся в любом случае.

### 4.3. Большой маршрут — несколько паков

Пути не пересекаются — VFS сложит их сама:

```bat
openrts-pack pack ROUTES\Kuban_RTS\TILES   -o PACKS\base\Kuban_RTS.terrain.zip --as ROUTES/Kuban_RTS/TILES
openrts-pack pack ROUTES\Kuban_RTS\WORLD ROUTES\Kuban_RTS\SHAPES ROUTES\Kuban_RTS\TEXTURES ... -o PACKS\base\Kuban_RTS.zip
```

### 4.4. deflate или zstd

| | deflate (по умолчанию) | zstd |
|---|---|---|
| Открывается | любым архиватором, Проводником | 7-Zip только с плагином zstd (7-Zip ZS) |
| Распаковка | медленнее | в несколько раз быстрее |
| Для чего | раздача, скачивание | установленные паки |

Переделать один в другой без пересборки из папки:

```bat
openrts-pack convert PACKS\base\Kuban_RTS.zip -o Kuban_RTS.deflate.zip --method deflate
```

Каждый файл после конвертации проверяется по CRC.

### 4.5. Проверить и посмотреть

```bat
openrts-pack list   PACKS\base\Kuban_RTS.zip    :: что внутри
openrts-pack verify PACKS\base\Kuban_RTS.zip    :: целостность (CRC всех файлов)
openrts-pack conflicts D:\Games\MDDRTS          :: какие файлы чем перекрыты
```

`conflicts` показывает, для каждого пути, лежащего в нескольких
источниках, кто победил — так видно, что заменил мод или патч.

### 4.6. Распаковать обратно (для RTS)

```bat
openrts-pack unpack PACKS\base\Kuban_RTS.zip D:\Games\MDDRTS
```

Восстанавливает обычную структуру папок, чтобы маршрут увидел `rts1.exe`.

## 5. Типовые сценарии

### Поставить маршрут
- папкой: распаковать в `ROUTES\<Имя>\` — как всегда;
- паком: положить `<Имя>.zip` в `PACKS\base\`.

В список маршрутов попадает каждая `ROUTES/<папка>/` с файлом `.trk` — из
любого слоя.

### Исправить маршрут, не трогая оригинал
Сделать пак только с изменёнными файлами (пути те же) и положить в
`PACKS\patch\`:

```bat
openrts-pack pack fix\ROUTES\Kuban_RTS\Kuban_RTS.tdb --as ROUTES/Kuban_RTS ^
    -o PACKS\patch\Kuban_RTS_fix1.zip
```

Патч сработает и для пака, и для установки папкой.

### Мод с заменой текстур
1. Создать `MODS_OPENRTS\HD_Kuban_Textures\ROUTES\Kuban_RTS\TEXTURES\brick.ace`
   (те же пути, что у заменяемых файлов).
2. Добавить в `openrts.ini`:
   ```ini
   [Mods]
   1 = HD_Kuban_Textures
   ```
3. Готово. Мод можно оставить папкой (удобно править) или упаковать в
   `MODS_OPENRTS\HD_Kuban_Textures.zip` и прописать с `.zip`.

Мод может и **добавлять** новые файлы (новый вагон, новый состав), не
только заменять.

### Удалить или обновить
- удалить — стереть папку или архив, больше ничего нигде не прописано
  (кроме модов в `[Mods]`);
- обновить — заменить архив или добавить патч с изменёнными файлами.

## 6. Вьювер и паки

```bat
:: маршрут из папки (корень установки находится сам)
openrts_viewer --window --route D:\Games\MDDRTS\ROUTES\Kuban_RTS

:: маршрут, который есть только в паке: имя + корень
openrts_viewer --window --route Kuban_RTS --root D:\Games\MDDRTS

:: временно подмешать папку или архив поверх всего (выше модов)
openrts_viewer --window --route Kuban_RTS --root D:\Games\MDDRTS --mount D:\test\my_textures

:: без слежения за файлами
openrts_viewer ... --no-hot-reload
```

При старте вьювер печатает список подключённых источников:
`content: ... (N sources, M files)` и по строке на каждый слой — удобно
проверить, что пак действительно подключился.

## 7. Горячая перезагрузка и замена файлов на лету

### Что это
Пока вьювер запущен, openRTS следит за всеми источниками: папками
установки, `PACKS\base`, `PACKS\patch`, `MODS_OPENRTS` и тем, что
подключено через `--mount`. Сохранили модель или текстуру — она меняется на
экране без перезапуска.

Включение:
- во вьювере — по умолчанию; выключить ключом `--no-hot-reload` или
  `HotReload = 0` в `[VFS]`;
- в игре — будет выключено по умолчанию, включается `HotReload = 1`.

Что перезагружается сейчас: **модели (`.s`) и текстуры (`.ace`)**, включая
`.sd`, который меняется вместе с моделью. Рельеф, небо (ENV), файлы мира
(`.w`), `.eng`/`.wag` читаются через VFS, но на лету пока не обновляются —
для них перезапустите вьювер или переставьте поезд.

### Как это работает (коротко)
1. Windows сообщает об изменении файла. openRTS ждёт ~0,3 с тишины —
   редакторы и экспортёры пишут файл в несколько приёмов, недописанный файл
   грузить нельзя.
2. VFS строит новую таблицу файлов и вычисляет, **у каких путей реально
   поменялось содержимое** с учётом слоёв.
3. Новые версии моделей и текстур готовятся в фоне целиком (разбор, декодирование,
   загрузка на видеокарту), старые в это время продолжают рисоваться.
4. В начале кадра всё готовое подменяется **одной пачкой**: модель и её
   новые текстуры появляются в одном кадре, без мигания «новая модель со
   старой текстурой».
5. Старые версии освобождаются, только когда видеокарта закончила кадры,
   где они использовались.

В консоли вьювера это выглядит так:

```text
hot reload: 17 model(s), 1 texture(s)
```

Ошибки разбора печатаются там же с префиксом `hot reload:`.

### Способы замены

**1. Правка файла в папке.** Самый простой: открыли
`ROUTES\Kuban_RTS\TEXTURES\brick.ace` в редакторе, сохранили — обновилось.
Удобно для своих маршрутов и составов.

**2. Замена через мод — не трогая оригинал.** Рекомендуемый способ для
экспериментов:
1. Создайте папку мода и пропишите её в `openrts.ini`:
   ```ini
   [Mods]
   1 = Test_Textures
   ```
   (список модов читается при старте — мод, добавленный в `[Mods]` уже во
   время работы, подхватится после перезапуска; это нужно сделать один раз).
2. Кладите файлы в `MODS_OPENRTS\Test_Textures\` по тем же путям, что у
   оригинала, например
   `MODS_OPENRTS\Test_Textures\ROUTES\Kuban_RTS\TEXTURES\brick.ace`.
   Файл появился — на экране сразу новая текстура.
3. **Удалили файл из мода — вернулся оригинал** (из папки или пака под
   ним). Так удобно сравнивать «было/стало».

**3. Временный слой без правки `openrts.ini`.** Запустите вьювер с
`--mount`:
```bat
openrts_viewer --window --route Kuban_RTS --root D:\Games\MDDRTS --mount D:\work\retexture
```
Папка `D:\work\retexture` (с путями от корня: `ROUTES\Kuban_RTS\TEXTURES\...`)
встаёт поверх всего, включая моды, и тоже отслеживается.

**4. Замена архива.** Перезаписали `PACKS\base\Kuban_RTS.zip` или
`MODS_OPENRTS\X.zip` целиком — архив перечитается, обновятся только
файлы, которые в нём действительно поменялись. Архив открывается, когда его
размер и время изменения перестали меняться; если он недописан или битый,
остаётся старая версия, ошибка — в логе.

**5. Патч поверх.** Положили новый ZIP в `PACKS\patch\` во время работы —
папка отслеживается, файлы патча сразу перекроют базовые.

### Чего ожидать
- **Перекрытый файл не перезагружается.** Если `brick.ace` есть в моде,
  правка такого же файла в паке или папке под ним ничего не изменит на
  экране — побеждает мод. Проверить, кто победил: `openrts-pack conflicts
  <корень>`.
- **Битый файл не ломает картинку.** Если новая версия не разбирается
  (сохранили на середине, не тот формат), на экране остаётся предыдущая.
- **Пропущенные события не страшны.** Если Windows потеряла уведомления
  (массовое копирование, сон, сетевой диск), источник пересканируется целиком,
  плюс раз в `ReconcileSeconds` (по умолчанию 180 с) идёт страховочная
  сверка папок.
- **Много файлов разом** (распаковали пачку текстур) — придут одной или
  несколькими пачками, по мере того как запись затихнет.

## 8. Частые вопросы

**Пак лежит, а маршрута нет.** Проверьте, что архив в `PACKS\base\` (не в
`PACKS\`), и что пути внутри начинаются с `ROUTES/<Имя>/` (`openrts-pack
list`). Архив, где сразу лежит `Kuban_RTS.trk` без `ROUTES/Kuban_RTS/`,
не подойдёт — пересоберите через `openrts-pack pack` или с `--as`.

**Можно ли собирать паки 7-Zip/WinRAR вручную?** Да, это обычный ZIP.
Главное — пути от корня установки. Но `openrts-pack` сам выбирает, что
сжимать, а что хранить без сжатия, и пишет манифест.

**Какой файл реально используется?** `openrts-pack conflicts
<корень>` или строки источников при запуске вьювера.

**DLL локомотивов в паке?** Будут поддерживаться: openRTS скопирует их в
`CACHE\extracted\...` при первом использовании (вместе с DLL-хостом,
пока не готово).
